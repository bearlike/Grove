# grove.core — engine: lifecycle, config, side effects, status, registry, activity

> ↑ [root](../../../CLAUDE.md)

The engine: the manager sequences worktree/tmux lifecycle, the config cascade resolves user policy, status reconciliation promotes intents to displayed states, and the registry + activity service aggregate across repos. All side effects funnel through two files; everything else is pure.

Children: [contracts](contracts/CLAUDE.md) (wire shapes) · [agents](agents/CLAUDE.md) (agent adapters) · [tickets](tickets/CLAUDE.md) (branch-aware ticket providers) · [notifications](notifications/CLAUDE.md) (push on activity edges).

## Lifecycle & manager

- **Init outcome is captured in one helper (`_init_outcome` in `manager.py`).** `create()` and `resume()` both apply it via `_replace(state, **_init_outcome(...))`; never reimplement the OK/FAILED/SKIPPED branching at a call site, so the paths can't drift.
- **`kill()` is the only op that deletes a branch, and it never touches a remote.** `pause` removes the worktree, keeps the branch (worktree is Grove's, branch is the user's); `resume` recreates the worktree from the branch; `respawn` touches only tmux. `kill(id, *, delete_branch=None)` resolves an unspecified flag from `state.branch_provenance` (GROVE_CREATED → True, USER_ATTACHED → False); the TUI modal can override. Remote branches are never touched — `git push --delete` stays in the user's shell. Kill event emits `branch_deleted: "true"|"false"`.
- **Recovery from a vanished tmux session is `respawn`, not `resume`.** `respawn(id)` requires persisted OFFLINE (`ensure_can_respawn`) and the worktree dir on disk (else ORPHANED, kill-only), then recreates session + layout; intent stays RUNNING. Init re-runs only with `cfg.init_script.run_on_resume`. Never overload `resume` — the verb means different things per path.
- **The init log survives `_rollback_create`; only `kill()` drops it (issue #9, 2026-06-11).** Rollback fires exactly when the log is needed for diagnosis, so deleting it there made fail_fast failures undiagnosable. Every fail_fast init raise (create/resume/respawn) goes through `_init_failure_detail`, which appends the kept log's path + tail (stderr is the log's last section, so the file tail doubles as the stderr tail) — route any new init-failure raise through it. Companion fix: the daemon's systemd unit bakes an install-time PATH (see [packaging](../../../packaging/CLAUDE.md)) because a bare `systemd --user` PATH was what made init scripts fail in the first place.
- **Agent session ids are minted in one helper (`_mint_agent_session_id`), AFTER the worktree exists, with opposite directions per kind (#36).** claude_code: client-minted UUID (`--session-id`); mewbo: SERVER-minted — `MewboClient.create_session(cwd=worktree, title=...)` anchors the remote session to the worktree (the API validates the dir exists, hence the post-worktree ordering) and the returned id is persisted. Remote-create failure is loud and transactional (`_rollback_create`, like fail_fast init). create/respawn mint fresh; resume keeps the persisted id (mewbo re-engagement via `/message` is #37). The Mewbo HTTP surface is the dedicated side-effect module `core/mewbo.py` (sibling of git/tmux); the manager takes an injectable `mewbo_client` for tests.
- **Manual session remap + resume-into-workspace are two halves of "which session does this workspace track" (#120).** `remap_session(ws_id, session_ref)` is the trusted-operator counterpart to the automatic discovery/adoption path — it mirrors `attach_ticket` exactly (`ensure_can_update` gate, idempotent by resolved id, emits `updated`) and sets `state.agent_session_id` to a session resolved through `SessionExplorer(self).resolve` (a call-time local import — `sessions.py` imports `manager.py`, so a module-level one cycles). **Manual = trusted: NO `adopts_session` birth-gate** (the operator outranks the heuristic, exactly as `grove_launched` is never gated) **but it DOES enforce adapter-kind equality ():** the resolved session's `adapter_kind` must equal the workspace's effective kind (`_effective_kind` = persisted `agent_kind`, else config, else generic), else it is a permanent dead pointer the workspace's adapter can never read — rejected as `AgentSessionNotFound` naming both kinds (404). `resolve`'s bare `GroveError` is re-raised as `AgentSessionNotFound` so the daemon maps it to 404; the daemon route runs `remap_session` in the **executor** (it full-parses every transcript — never block the loop). The resume half rides `create()`: `CreateWorkspaceRequest.resume_session_id` is **resolved through the same `SessionExplorer.resolve` (id OR unique prefix) BEFORE any side effect ()** — an unknown/ambiguous ref or a kind mismatch fails clean rather than provisioning a dead workspace pinned to a bogus id; the RESOLVED full id short-circuits `_mint_agent_session_id` and flips `_compose_launch(resume=True)` to the tool's resume flag, gated to `_RESUMABLE_KINDS` (derived from each adapter's `resumable` flag — not hand-listed) at create()'s top (mint runs post-worktree, too late → `ResumeNotSupported`, 422). **Unpause continues what EXISTS, mints what doesn't ():** `resume()` composes `resume=True` iff the pinned session already MATERIALIZED (`adapter.locate_transcripts` non-empty across `scan_cwds`) and the kind is resumable — else it keeps the mint form, so a resume-created codex workspace doesn't relaunch a bare `codex` (new thread, stale pin) and a never-materialized minted claude id keeps `--session-id`. Respawn stays on its mint-fresh path (#36). Per-provider resume flag shapes live in [agents](agents/CLAUDE.md).
- **Title is identity-seed-only at create; rename is metadata-only.** `create()` derives the worktree path and tmux session name from `slug(title) + ts` once, then persists them. `update(id, *, title, description)` changes only `title`/`description`/`updated_at` — dir and session keep their names forever (renaming breaks attached clients). Uses an `_UNSET` sentinel: `None` = clear (description only), `_UNSET` = leave alone; title can never be cleared.

## Placement (worktree vs root)

- **Placement gates every worktree side effect and is safety-critical.** A workspace is WORKTREE (dedicated dir under `${repo}/.worktrees`) or ROOT (runs in `repo_root`, adopts live HEAD, Grove creates nothing). Modeled as the `RootBranch` discriminated-union variant in [contracts](contracts/CLAUDE.md) — not a boolean — so illegal combos are unrepresentable. `RootBranch.resolve()` returns `placement=ROOT`, `provenance=USER_ATTACHED`, `name=""`; the empty name is the sentinel the manager fills from `git.current_branch()` (detached HEAD → `"HEAD"`).
- **The `Placement` enum lives in `workspace.py`, NOT `contracts/branch_plan.py`** — `branch_plan` imports from `workspace`, so the enum sits on the depended-upon side or the import cycles. `WorkspaceState.placement` defaults to WORKTREE so legacy JSON loads with no migration.
- **Agent cwd is orthogonal to worktree placement — the worktree/branch always anchor at the repo root, the agent session only *starts* in a nested subdir (#101).** `WorkspaceState.project_subpath` (a POSIX relative path under the worktree root, `""` = the root itself, legacy default) is the durable fact; `WorkspaceState.agent_cwd` (= `worktree_path / project_subpath`) is the single derived "where the agent runs", reused by create/resume/respawn so they can't drift. `create()` derives the subpath from `CreateWorkspaceRequest.project_cwd` via `_project_subpath` (resolve + `relative_to(repo_root)`; out-of-repo → loud `GroveError` *before* any side effect) and threads `agent_cwd` into exactly the agent-session sites — `tmux.create_session` cwd, `build_workspace_layout`, the mewbo mint — while `git worktree add`, branch ops, and the init script stay on `repo_root`/`worktree`. This is why several subdirs of one repo are distinct projects sharing one worktree family: cwd is per-workspace state, not a second worktree. The store round-trips `project_subpath` with the same `.get(...,"")` legacy-default discipline as `placement`.
- **The gate is one check (`placement is ROOT`) at each worktree side-effect site:** `create` skips `worktree_add` + branch creation; `kill` skips `worktree_remove` and **forces `delete_branch=False` even when the caller passes `True`**; `_rollback_create` reuses the gate so a failed root create can't destroy the repo; `respawn` never re-runs init for root. Root lifecycle is **create/kill/respawn only** — `ensure_can_pause`/`ensure_can_resume` refuse it, and reconciliation never yields ORPHANED. Tests must spy that `worktree_remove`/`branch_delete` are never *called* for root — git refuses to remove the main worktree, so a survival-only assertion passes even with the gate missing.

## Config cascade

Six-layer cascade philosophy (mechanism, not policy) lives in [root](../../../CLAUDE.md).

- **Pydantic config = validated, frozen submodels; runtime state = plain dataclass.** Config loads once and is immutable; `WorkspaceState` is mutable, persisted to JSON. Mixing them tempts per-write validation and erodes the boundary.
- **`${repo}` / `${repo_name}` placeholders expand at consume time, not validate time.** One global config serves every repo without re-validation; expansion deferred to `create()` is what makes that work.
- **`agents` lists merge by `name` field-by-field; other lists replace wholesale.** Codified in `_merge_agents` (`config.py`): an overlay entry refines the base (`{**base, **overlay}`), so overriding just the `claude` agent's `command` keeps its `kind="claude_code"`. Any new list-of-named-things: decide merge vs replace explicitly, document it at the field. **The built-in roster is literally layer 0 of `load_config` (#105, 2026-07-01):** Pydantic's `default_factory` fires only when NO layer declares `agents`, so before the seed layer, any config with an `agents` key replaced the built-ins wholesale — the `config init` scaffold hid codex/shell (`unknown agent: shell` on the documented first-run flow) and dropped the redeclared claude to `kind="generic"`, silently killing dashboard tracking. Removing a built-in agent from the picker is deliberately not supported by omission anymore; that wants an explicit disable knob if anyone asks.
- **`AgentSpec.models` is the per-agent model-catalog OVERRIDE; the catalog itself resolves in [agents](agents/CLAUDE.md) (`resolve_models`).** Empty (default) falls through to the adapter's live discovery (codex `debug models`, claude's stable aliases); set it to pin/curate/reorder the ≤10 ids a create picker offers. Merges by field like every AgentSpec knob. Never a create-time allowlist — `CreateWorkspaceRequest.model` is still forwarded verbatim (provider boundary). The daemon `GET /agents` route resolves it into `AgentSummaryView.models` for remote clients; the TUI resolves it in-process.
- **`skip_init` is a per-create override of `init_script.enabled` — create-scoped, never persisted.** `create()` runs init only when `init_script.enabled and not request.skip_init`, else `InitStatus.SKIPPED`. Gating at the call site lets one create opt out without touching config. Not stored, never re-applied on resume/respawn (those keep their own `run_on_resume` gate). Placement and skip-init are independent in the engine.

## Side effects & status

- **Side effects only in the dedicated modules: `grove/core/git.py`, `grove/core/tmux.py`, and `grove/core/mewbo.py` (HTTP, #36).** Manager sequences them; everything else is pure. A new I/O concern routes through one of those (or a new dedicated side-effect module) — never scatter `subprocess.run` or ad-hoc HTTP.
- **Grove never runs `git commit` or `git push`.** Pause refuses dirty worktrees with a typed error; we never auto-commit. The user owns commits/pushes via the tmux shell window or lazygit.
- **`peek()` is best-effort by contract — it never raises.** Helpers can fail (git/tmux gone, branch deleted); peek returns zeros/empty rather than break the render loop. Lifecycle methods keep the loud, transactional failure surface.
- **The pane snapshot captures scrollback, not just the live viewport (`-S -peek_history_lines`, #39).** `tmux capture-pane` with no `-S` starts at the *top of the visible viewport*, so a long session previewed as only its current screen — earlier output was never read (the "only ever shows the bottom of the session" bug). `capture_pane_snapshot` now passes `-S -<cfg.tmux.peek_history_lines>` (default 500) and returns the whole captured grid with only the viewport's trailing blank rows trimmed — **core never pre-crops to a fixed line count for everyone**; the client owns the viewport (rail/dashboard tile tail it, the webapp `<pre>` scrolls it). `-J` was *dropped*: rejoining wraps yields logical lines far wider than the pane that renderers then clip, so the raw grid (one line per display row, already pane-width-bounded) is the faithful snapshot. The knob is the captured/over-the-wire bound, so it's the one place to tune preview depth vs payload size.
- **Steering (`send_message`/`interrupt`, #37) is manager policy over reused seams:** the pane resolves via the same `pane_target` policy peek uses (None → typed `PaneNotFound`); injection is `tmux.send_text` (literal `-l --` payload + a separate Enter, loud `TmuxError`). Remote-steered kinds (`_REMOTE_STEERED_KINDS`) funnel through `_steer_remote` — THE single remote dispatch point, wired to `MewboClient.send_message`/`interrupt` (no liveness gate on purpose: `/message` re-engages idle/finished sessions by design). The `message_sent` event carries text *length*, never content.
- **Pane-target resolution is manager-side policy, never tmux-side.** `tmux.list_windows(session)` is mechanism — list whatever exists, never raise. `pane_target(id)` is policy — prefer configured `agent_window_name`, fall back to first non-`shell` window, then `shell`, return `None` only with no windows. Hard-coding `f"{session}:{agent}"` was the original peek-empty bug.
- **`WorkspaceStatus` is one enum, two domains.** Persisted: `RUNNING`/`PAUSED`/`ERROR` (written by `pause`/`resume`/`respawn`/`_record_error`). Computed at read time, never persisted: `ACTIVE`/`IDLE`/`OFFLINE`/`ORPHANED`. `_reconcile_status` is the **single** policy site promoting persisted → displayed; `JsonWorkspaceStore.save` rejects non-`PERSISTED_STATUSES` (defense in depth). Adding a computed status: extend the enum + `STATUS_HEX`/`STATUS_GLYPH`/`STATUS_LABEL` + `_reconcile_status` + the TUI footer gate. Never branch on raw `RUNNING` outside `_reconcile_status` and the lifecycle writers.
- **Active vs Idle = `tmux #{window_activity}`, NOT `#{pane_activity}`.** `pane_activity` (tmux ≥3.4) returns empty on tmux ≤3.3 (Ubuntu 22.04 ships 3.2a) → every workspace reads IDLE. `#{window_activity}` is broadly supported and, since Grove runs one pane per window, equivalent. Public helper stays `pane_activity_seconds_ago`; implementation reads `window_activity`. Threshold `cfg.tmux.activity_threshold_seconds` (5s). No snapshot-diff cache — tmux is source of truth, one subprocess per running workspace per slow tick. Unknown/future/non-numeric age → `None` → IDLE.
- **`branch_provenance` defaults to `GROVE_CREATED` so legacy state files load without migration.** Default matches historical behavior; new stores write it explicitly, old reads coerce missing → GROVE_CREATED. No version bump — same precedent as `placement` and `agent_session_id`.

## Registry & activity

- **`RepoRegistry` (`grove/core/registry.py`) caches one `WorkspaceManager` per `Path.resolve()`d repo_root.** Pure engine (cfg + store + manager cache), consumed by daemon, `ActivityService`, and TUI dashboard; `grove.daemon.repos` re-exports for back-compat. Symlinks collapse to one Manager via `.resolve()`. `known_roots()` is fresh-from-store every call so new repos appear without restart. Unbounded by design (loopback-only, small N).
- **`known_roots()` is THE single "which repos exist" seam — a union of store-derived roots and config-declared `cfg.projects` (#95).** Projects were once derived *only* from persisted workspace state, so a repo with zero workspaces (fresh, or all-killed) vanished from every cross-project surface (`/workspaces`, `/activity`, the webapp create dialog, the TUI switcher). The fix is one union point: `known_roots()` returns `{store roots} ∪ {declared roots}`, deduped on `Path.resolve()` (symlink-collapse, same rule as the Manager cache key). Declared roots are best-effort: `Path(raw).expanduser().resolve()` then dropped silently unless `(root/".git").exists()` — a bad path never fails config load or a request. `cfg.projects` is a plain `list[str]` on `GroveConfig` (mechanism, not policy: a user-level path list, no per-project objects, no parent-dir auto-scan). Because every downstream consumer already iterates `known_roots()`, empty-project visibility flows for free — `ActivityService.snapshot()` emits a `ProjectGroup` per known root even with empty `workspaces`, which is exactly what the webapp dialog reads. The `.git`-stat check is deliberately not a `git rev-parse` subprocess: `known_roots()` is on the hot per-request path, and a stat is the boring cheap test.
- **`known_projects()` is the *listing* seam; `known_roots()` stays the *repo* seam (#101).** A `cfg.projects` entry may be a subdirectory of a repo, not a repo root. `known_roots()` (Manager dispatch + `repo`-query validation + sessions scan) must still answer "which repos exist", so a declared subdir resolves to its **enclosing** repo root (collapsing siblings to one) — `_declared_projects()` keeps the cheap `.git`-stat for the common repo-root entry (`cwd == repo_root`) and pays one `git rev-parse` (`detect_root`) only for an entry that isn't itself a root. `known_projects()` returns `Project(repo_root, cwd)` — store roots as repo-level projects (the #95 empty-visibility arm) ∪ declared projects — so a nested subdir lists *distinctly* while anchoring its worktrees at the true root. `ActivityService.snapshot()` consumes it: one `mgr.list()` per repo, split into a `ProjectGroup` per `cwd` by each workspace's `project_subpath` (an unmatched subpath still gets its own implied group — no row is ever dropped; every declared project appears even when empty). `ProjectGroup`/`ProjectGroupView` gained `cwd` (repo_name stays the repo's basename); the webapp/TUI *surfacing* of nested projects in the picker is a follow-up — the engine + wire carry it now.
- **Each Manager gets its OWN repo cascade via the registry's injectable `config_loader` (the #46/#47 fix).** The daemon loads its global config with `load_config(repo_root=None)` (the auth/daemon source) and previously SHARED it across every Manager — so `create()` validated agents and read `init_script` against config that never saw `<repo>/.grove/config.json`: a project-scoped agent read as "unknown agent" (#46) and a project-enabled `init_script` read as disabled → `SKIPPED`, so new worktrees never inherited the project's `.mcp.json`/`CLAUDE.md` (#47). Now `RepoRegistry(config_loader=load_config)` resolves each repo's full cascade once at first access (the CLI `manager.build()` always did this; only the daemon was blind). `config_loader=None` keeps the shared `cfg` for every repo — the seam tests use to inject an in-memory config with no files on disk. **Why it's safe to vary config per repo here:** `cfg.auth`/`cfg.daemon` are consumed ONLY from the global `cfg` `build_app` holds, never off a registry Manager (verified: only `daemon/app.py` reads them) — a project's `.grove/config.json` can't widen daemon auth. The daemon + both TUI cross-project registries inject `load_config`; the per-repo cfg is cached with its Manager, so a mid-session edit to `.grove/config.json` is picked up only on the next fresh repo access (acceptable: same long-lived-cache contract the Manager already has).
- **`ActivityService` (`grove/core/activity.py`) is the cross-project aggregation hub: one engine source, two renderers.** Enumerates every workspace across every repo via `RepoRegistry`, resolves each session through the adapters, exposes `snapshot()` + `subscribe()`/`poll_once()`.
- **`_blend` is the single status-blend policy site** (the `_reconcile_status` analogue). Reuses the manager's already-reconciled `WorkspaceStatus` for the tmux dimension (no second tmux call): transcript WAITING/ERROR/UNKNOWN/**BLOCKED** pass through (BLOCKED was missing from the definitive set and got erased to IDLE on a quiet pane — exactly the wrong signal to drop); transcript WORKING → WORKING for a **remote adapter** (`adapter.remote`: the backend's status is authoritative, the local pane runs a bare shell), else WORKING when workspace ACTIVE **or the transcript itself is fresh** (`last_event_at` within the sidecar window — the adapter's abstraction outranks the tmux heuristic; a thinking/long-tool agent emits no pane output, and demoting on the quiet pane alone was the flaky WORKING→IDLE flapping; tmux is the tiebreak only once the transcript has gone stale), else IDLE; no transcript yet → STARTING. "Has a transcript" is generalized for remote adapters: a session is materialized when files exist **or** the parsed state is non-UNKNOWN, so UNKNOWN-and-fileless is the only true STARTING window.
- **A minted id that is a dead pointer yields the primary slot to discovery (the stuck-STARTING fix, 2026-06-12) — but only to a discovery `WorkspaceState.adopts_session` accepts (#107, 2026-07-04; extended #117, 2026-07-05).** `/clear` mints a NEW session id inside the same claude process (and a hand-restart or an outright end does the same), so the Grove-minted `--session-id` becomes a dead pointer while the live session sits under a different id in the same cwd — the workspace read STARTING (or IDLE) forever. `sessions_for` recovers via `_minted_unmaterialized` + `ClaudeHook.adopts`. **Rules `_minted_unmaterialized` encodes, each a trap:** (1) **a materialized session — one with a transcript on disk — is NEVER a dead pointer** (): both detectors require `transcript_path is None`, so a just-remapped/resumed session whose last hook event is `SessionEnd` stays primary showing its honest idle/done state instead of being demoted against the trusted pin. A dead pointer is a *transcript-less* minted id whose blend is STARTING/UNKNOWN **OR whose sidecar's latest event is `SessionEnd`** — the latter settles the blend to IDLE, so without the explicit check the dead pointer read as live and recovery never ran (the 2026-07-05 live incident: Grove minted M, the user resumed R in the pane, M's SessionEnd pinned the card on M's dead id); gated on the sidecar still superseding the poll. (2) The concurrent-session **extras are cheaply pre-filtered before any full parse ():** `_adopted_candidates` unions `adapter.discover_births` (id + BIRTH from a bounded head read, never a full transcript parse) across `state.scan_cwds`, applies the adoption gate on that cheap metadata, and only then pays a full `SessionActivity` parse — so per-tick cost is **O(new sessions), not O(history)**, and a transcript predating the workspace is excluded from the card entirely. (3) With the minted id dead, the newest adopted extra is promoted to primary; the minted entry rides behind and reclaims primary the moment it materializes. Discovery is **always ungated by hooks** (a read-only fs glob; #119), keyed by **`state.scan_cwds`** = the union of `agent_cwd` and the worktree root (see the agent_cwd invariant below), and each session's sidecar is **read once per tick and threaded** to the blend, the dead-pointer test, and the adoption evidence ().
- **Adoption weighs two evidence axes, and the live-here axis is PANE-verified (#117; pane rule from the 2026-07-05 review).** `WorkspaceState.adopts_session(born_at, *, live_here_at=None)` adopts on transcript BIRTH ≥ created_at **or** a hook sidecar ts ≥ created_at proving the session was live in this workspace — either alone suffices. Birth alone silently dropped every session the user **resumed** inside the pane (born *earlier* than the workspace); the sidecar arm recovers it. The predicate stays **pure** (never reads a sidecar); the boundary distills the evidence. **The live-here match is by tmux PANE, not just cwd:** a cwd-match alone was a cross-tenant hole — a fresh workspace at a shared cwd (ROOT placement, whose cwd is the repo root) would adopt a *different* live workspace's session, since that tenant's sidecar keeps refreshing `ts ≥ created_at` with the same cwd. The candidate sidecar's `tmux_pane` must equal the workspace's **reference pane** = the `tmux_pane` recorded on the MINTED session's sidecar (`state.agent_session_id`'s). **No minted-sidecar pane** (no minted id, no sidecar yet, `tmux_pane` None) → no live-here evidence, fall back to **birth-only** (the remap verb is the escape hatch). `ClaudeHook.adopts(state, born_at, *, candidate, reference_pane, cwd)` is the ONE composition seam both adoption sites (`sessions_for`, `SessionExplorer.for_workspace`) call — it takes **pre-read** `HookRecord`s (the caller reads each sidecar once per tick) and folds birth + pane-verified live-here so the two sites can't drift.
- **Discovery scans the UNION `state.scan_cwds` = {`agent_cwd`, worktree root}; parse keys by the cwd a session was DISCOVERED under (#118; union, 2026-07-05).** The agent runs — and its transcript/sidecar records its cwd — in `agent_cwd = worktree/project_subpath`, and both filesystem adapters *exact-string-match* that cwd; keying discovery to `agent_cwd` alone (#118) then dropped a session **hand-started at the worktree ROOT** of a nested project (cwd = `worktree_path`). `WorkspaceState.scan_cwds` is the deduped union (`agent_cwd` first; equal for a flat workspace, so the second entry only exists when nested), applied at both adoption sites (`sessions_for`, `for_workspace`) and `SessionExplorer.for_workspace`'s scan; candidates are merged **newest-first by mtime** across the union, and each session's `SessionActivity` parse keys off the cwd it was *found* under, not always `agent_cwd`. `scan_roots`/`list` already unioned `agent_cwd` + `worktree_path`. No adapter change.
- **The blend has memory: `_settle` keeps the last definitive state through a degraded read (2026-06-11).** A live session's read transiently collapses — a JSONL tail mid-write, a remote `/events` timeout, a glob racing a rotation — and a memoryless blend flashed the card back to STARTING/UNKNOWN on every such tick (the "running session shows as starting" flakiness; it also absorbs Mewbo fetch-failures with zero Mewbo-specific code). Per-session `(state, settled_at)` dict on `ActivityService`, consulted after blend + sidecar; the next clean read takes over. **A settled WORKING expires on the sidecar window** — with hooks on, `SessionStart` settles WORKING before any transcript exists, so an agent dead at boot (or never prompted) would otherwise answer degraded reads with WORKING forever, silently defeating the sidecar's own dead-agent guard; settled WAITING/BLOCKED/ERROR/IDLE stay age-less (nothing happened since → still true). Companion default change: `tmux.activity_threshold_seconds` 5 → 30 — at 5s every thinking/long-tool agent (no pane output) read IDLE, and the blend demotes WORKING on that signal.
- **`AgentActivityState` is a separate axis from `WorkspaceStatus` — never overload the workspace enum.** Agent axis and tmux axis are independent; a card renders both.
- **The timer lives at the edge.** Daemon lifespan / TUI ticker call `poll_once()`; the service keeps time-of-day out of its core. Engine emits `DashboardDelta` (dataclass) on its bus; the wire `DashboardEvent` + `*View` mirrors live in [contracts](contracts/CLAUDE.md) `activity.py`, importing engine dataclasses under `TYPE_CHECKING` only so a contracts import never drags in manager/registry.
- **A card carries three deliberately-separated signals; "latest activity" is the last commit, not the transcript.** *Ongoing action* (live, ephemeral) is the blended transcript state (with tmux fallback for sessionless workspaces — done client-side off `WorkspaceStatus`); *latest activity* (durable, timestamped) is `recent_commits[0]` on the workspace branch; *commit history* is the rest. The transcript `current_task` is kept ONLY as the live ongoing-action line — commits are the precise record of *what was done, and when*, where the transcript task text goes stale. `WorkspaceActivity` carries `recent_commits` (one cheap `git log -3` per row per tick, best-effort like `ahead_behind`/`diff_stats` — never breaks the snapshot) and `observed_at` (the per-card "updated" time). Three fingerprint invariants: **`observed_at` is excluded from `fingerprint`** (it changes every tick → would re-emit every card every poll), the **last commit sha IS in the fingerprint** so a fresh commit streams promptly even when it doesn't move ahead/behind (an amend on the tip), and the fingerprint covers **every session, not just `primary`** (a hand-started secondary's change must stream; a sessions set going empty — a discovery miss — is itself a change). `dirty_files` (uncommitted-path count, untracked included) is also in the fingerprint — the agent-is-editing signal must stream *before* anything is committed; it costs one more best-effort git call per row per tick and reads 0 for a paused workspace's missing dir.
- **`WorkspaceState.agent_kind` is persisted at create as a create-time fact, so the dashboard resolves an adapter without re-reading config.** Since the registry now resolves each repo's full cascade (the `config_loader` note above), `mgr.config.find_agent(state.agent_name)` resolves a project-scoped agent on BOTH the read path and lifecycle ops — the old "agent defined only in `<repo>/.grove/config.json` → `find_agent` returns `None` → `generic` → blank agent axis" failure is gone, and `/respawn` can now relaunch a repo-scoped agent (it goes through the per-repo Manager). `agent_kind` persistence stays as complementary belt-and-suspenders: `sessions_for` **prefers `state.agent_kind`** (config lookup only for legacy `None`), so the agent axis survives even if the agent is later removed from config, and it skips a redundant config read on the hot poll path. `AgentKind = Literal["claude_code","codex","generic","mewbo"]` lives in `config.py`, imported by `workspace.py` (no cycle). Operational corollary still holds: a custom-named Claude agent must declare `kind: "claude_code"` (merge-by-name doesn't inherit the built-in `"claude"`'s kind); pin/neutralize a Claude profile with `agents[].env` / `agents[].env_unset`, never the daemon's own env — that leaked daemon → tmux-server → pane and broke profile + status (#82; the launch boundary clears/sets exactly what the config names, no hard-coded var, see [agents](agents/CLAUDE.md)). `codex` is a filesystem adapter like `claude_code` but mints no id (no launch flag exists) — it is always adopted through discovery (see [agents](agents/CLAUDE.md)), so `_mint_agent_session_id` returns `None` for it and `sessions_for`'s null-id discovery path is its only correlation route.
- **A workspace with no minted `agent_session_id` still surfaces its live session via discovery — `sessions_for` (public seam since the TUI list tick became its second consumer alongside the daemon poll) must NOT early-return on a falsy id.** Three shapes have no id: a non-`claude_code` agent at create, a pre-minting record, a hand-started `claude`. The old `if not id: return []` blanked the entire agent axis though a transcript was on disk. Invariant: with no minted id, walk the cheap `adapter.discover_births` union over `state.scan_cwds` (newest-first by mtime) and adopt the single most-recent transcript `ClaudeHook.adopts` accepts as the `fs_discovered` primary. **With no minted id there is no reference pane, so adoption here is BIRTH-ONLY ()** — the live-here (resumed-in-pane) arm needs a minted sidecar to source the reference pane, so a hand-started/resumed session with no minted anchor adopts only on birth ≥ `created_at` (the remap verb is the escape hatch for the rest). With nothing adopted (every discovered transcript predates this workspace, e.g. a reused ROOT cwd) the workspace is honestly sessionless. **Adapter-gated** (generic/shell → no-op), **NOT gated by `cfg.hooks.enabled`** (discovery is a read-only fs glob, always runs; `hooks.enabled` gates only sidecar install — concurrent-hand-started augmentation is also ungated, #119), and keyed by **`scan_cwds`** (union of `agent_cwd` + worktree root). Discovery mechanics (newest-first-by-mtime, cwd-preamble scan, `CLAUDE_CONFIG_DIR` cascade) live in [agents](agents/CLAUDE.md). Operational corollary: a custom-named Claude agent must declare `kind: "claude_code"` (merge-by-name doesn't inherit the built-in `"claude"`'s kind); pin a non-default profile with `agents[].env`, never the daemon's own env (#82).

## Session exploration (`sessions.py` + `grove sessions`, issue #26)

- **`SessionExplorer` answers one question — "which agent sessions belong to this project, and how do I read one?" — and is read-only by construction.** It composes the adapters' scans (`list_sessions` per cwd, `locate_transcripts`/`read_turns` per session); it never launches, mutates, or deletes. A new agent tool needs zero changes here — `all_adapters()` picks its adapter up.
- **`from_cwd` binds the manager to the MAIN worktree root (`GitRepo.worktree_paths()[0]`), never to `detect_root(cwd)` directly.** The workspace store is keyed by the main root; binding to a linked worktree's own root finds zero workspaces. `worktree_paths()` works from inside any worktree (git reports the whole family) and returns main-first.
- **The scan set is the union of live `git worktree list` AND every workspace's persisted `worktree_path`.** The first covers hand-made worktrees Grove never managed; the second covers paused workspaces whose directory is gone — transcripts outlive worktrees (discovery scans the encoded-cwd projects folder, not the worktree itself).
- **Provenance is minted-id equality, workspace association is cwd equality — in that order.** A session whose id matches a workspace's `agent_session_id` is `grove_launched` and binds to that workspace even if found elsewhere; otherwise the workspace owning the scanned cwd annotates it (`fs_discovered`).
- The `grove sessions` CLI (`tui/cli_sessions.py`: `list` with `--agent/--workspace/--since/--limit/--json`, `show --last N`, `dump --jsonl`) is a thin renderer over the explorer — filters and resolution (unique id prefix) live engine-side so the daemon/webapp can reuse them later.
- **`for_workspace(id)` / `turns_for(listing)` are the bounded per-request variants the daemon serves.** `list()` full-parses every transcript across every worktree — fine per CLI invocation, too heavy per HTTP request; `for_workspace` scans exactly one cwd, `turns_for` reads from an already-resolved listing (skipping `resolve()`'s full scan). Inside this class body a `list[...]` return annotation resolves to the `list` *method*, not the builtin — return tuples (the same shadowing trap documented for `WorkspaceManager`).
- **`for_workspace` scans the `scan_cwds` union and gates a discovered listing on `ClaudeHook.adopts` (birth OR a PANE-verified live-here sidecar); `list()` and the project-scoped listing stay ungated (#107; pane + union/, 2026-07-05).** A workspace's cwd can already hold transcripts from before it existed (especially ROOT placement, whose cwd is the shared repo root) — without the gate, `for_workspace` presented the newest one as this workspace's own session regardless of birth. It mirrors `ActivityService.sessions_for` exactly: the same `ClaudeHook.adopts` seam (pane-verified live-here evidence against the minted session's reference pane, so a resumed session is kept but a shared cwd can't steal another workspace's live session) and the same `scan_cwds` union (so a nested project's root-recorded sessions are found). A `grove_launched` (minted-id) listing is never gated — Grove launched it for this workspace regardless of birth. `list()` and the project-scoped `GET /sessions?repo=` listing are deliberately left ungated: those are browse-everything history views (every session in the project, workspace-annotated where known), not per-workspace attribution, so nothing there should vanish.
- **`candidates_for(id)` is the ungated cwd-scoped sibling of `for_workspace` — the remap-picker seam (#132, 2026-07-05).** Both delegate to one private `_scan_workspace(state, *, adopt_gate)` so the gated and ungated reads can't drift; `candidates_for` runs it with `adopt_gate=False`, skipping `ClaudeHook.adopts` entirely (a `grove_launched` listing is never gated either way). **`_scan_workspace` is ALSO kind-scoped — it reads only the adapter for `mgr.effective_kind(state)`, never `all_adapters()` (#164, 2026-07-06).** Kind-scope is the counterpart of cwd-scope: a workspace runs exactly one agent kind, so only that adapter's sessions can be its own. The trap is again ROOT placement — its cwd is the shared repo root where the human runs *other* tools, so a foreign-kind transcript (a codex rollout under a claude_code workspace) sits right there; scanning every adapter let the *ungated* `candidates_for` OFFER those sessions, which `remap_session` then rejects on kind-equality — breaking the "picker never offers a session the pin would reject" invariant right below and letting the webapp display a foreign session (its first_prompt as a wrong title). `mgr.effective_kind` (promoted public from `_effective_kind`) is the one seam the remap gate, the create-resume gate, and now this scan share. `list()` stays `all_adapters()` — it's the browse-everything view, not per-workspace attribution — **but its `by_cwd` workspace-annotation is itself kind-gated (#164):** a cwd match tags a session with a workspace's id/title only when `summary.adapter_kind == mgr.effective_kind(state)`, so a foreign-kind session sharing a ROOT workspace's repo-root cwd renders UNMAPPED (`workspace_id=None`) instead of borrowing that workspace's identity — the "wrong title in the rail" half of the bug (minted-id equality stays authoritative and un-gated: that id was minted by the workspace's own adapter, so the kind matches by construction). **Why a distinct method, not a flag on the normal list:** the gate is *attribution correctness* (a fresh workspace's cwd may already hold older/foreign transcripts), but a remap picker is the one consumer where the **human supplies the attribution the gate withholds** — so it must show exactly the sessions the gate DROPS: a dead-minted-pointer's pre-birth live successor, or a foreign session sharing a ROOT cwd. This is the missing quadrant — `for_workspace` is cwd-scoped-but-gated, `list()` is ungated-but-whole-project; `candidates_for` is cwd-scoped-AND-ungated (one directory's parse, not the project's). It backs `GET /workspaces/{id}/sessions?candidates=true` and the TUI `RemapSessionScreen`; the write it feeds (`remap_session`, itself ungated) agrees with it, so the picker never offers a session the pin would reject. The exact incident: an attached ROOT workspace minted a session that died at `SessionEnd` without materializing (a dead pointer), while the real live conversation — born before the workspace, pane-unverifiable — was gated out of `for_workspace` (which returned **0**), leaving the dashboard blank with no reachable remap; `candidates_for` surfaces it so the human can pin it.

## CLI

- **`grove.cli` adopts the TUI's Typer app (does not `add_typer`-mount it) to preserve back-compat.** Mounting under a `tui` namespace would bury `grove ls` / `grove version`. Instead `grove.cli` IS the TUI app, then `add_typer`s the daemon subcommand. The daemon import is guarded (`try: ... except ImportError`), so a bare `pipx install grove` still has a working CLI.
- **The workspace verbs (`create` / `message` / `pause` / `resume` / `respawn` / `kill` / `attach`) are in-process, not daemon round-trips (issue #45 + CLI↔TUI↔MCP parity).** They build a `WorkspaceManager` via cwd-bound `build()` and call the matching method directly — the same engine path the TUI uses and the same as `config show` / `grove sessions`, never the daemon HTTP API (the multi-repo/remote surface). Because `build()` resolves the full per-repo cascade, `grove create` honors project-scoped agents + init scripts for free. The verb set deliberately mirrors the TUI keybindings and the `grove_*` MCP tools so a shell, an agent over MCP, and the TUI drive the *same* lifecycle (the webapp is read-only by design — write parity is "not applicable" there). Shared seams in `tui/cli_workspace.py` keep every verb a thin shell: `_resolve_workspace` resolves a unique id-prefix like `SessionExplorer.resolve` (exact → unique prefix → `GroveError` listing candidates); `_clean_exit()` (one contextmanager) funnels every `GroveError` to a one-line red message + exit 1, so the command bodies read as pure intent (build → resolve → run → report) with no repeated try/except. The only real logic is `BranchFlags.to_plan()` — the atomic flag→`BranchPlan` mapping + mutual-exclusion rules (four exclusive branch flags; `--base` only modifies a freshly-created branch), kept off the Typer body so it's unit-testable without `CliRunner`. `kill` confirms unless `--yes`; `attach` resolves then `os.execvp`s `tmux attach`/`switch-client` (the same client-side fork the core leaves to `AttachInstruction`, mirrored via the pure `_attach_argv`). The engine owns every precondition (a non-running pause, a non-OFFLINE respawn, a no-session attach) and raises the typed error the shell renders.
- **Loguru is configured once in the Typer callback.** Per-subcommand `_configure_logging()` leaks the default DEBUG handler. `@app.callback(invoke_without_command=True)` runs for every invocation including subcommands — the right home.
- **`grove show [<ref>]` is the read/inspect verb — the CLI analogue of the peek rail, closing CLI↔TUI↔MCP read parity (#51).** A thin shell over existing best-effort seams (`manager.peek` = git + pane, `SessionExplorer.for_workspace`/`turns_for` = transcript tail) composed in the atomic `WorkspaceInspection` (`gather` → `emit`, methods over its own state — no scattered render helpers); read-only, no new engine logic. `<ref>` optional → inferred from cwd as the *longest* worktree path that is an ancestor-or-equal of `Path.cwd().resolve()` (compare resolved `Path`s, never strings; a ROOT workspace's worktree is the repo root, so longest wins). **Fix that rode along and helps every flat verb:** binding to `worktree_paths()[0]` (the main root the store is keyed by), not `detect_root(cwd)` — the same rule `SessionExplorer.from_cwd` follows. Run from inside a *linked* worktree, the old `build(Path.cwd())` resolved to that worktree's own root and `manager.list()` returned **zero** workspaces, so `create`/`message`/`pause`/… were all subtly broken in-worktree, not just `show`. **Promoted into `build(None)` itself (#105, 2026-07-01):** the interim `_manager()` helper is gone; `grove ls` and the TUI entry had kept the broken `build(Path.cwd())` shape — outside any repo that treated the cwd AS the repo root, so they showed `[]`/an empty TUI instead of the documented "must be run inside a git repository" error. Never pass `Path.cwd()` as `repo_root`; call `build()` and let it detect + bind to the main root.

## Release-skew check (`release.py`, issue #80)

- **One engine-owned, best-effort, cached newer-release check — never a per-client GitHub poll.** `ReleaseChecker` GETs `https://api.github.com/repos/bearlike/Grove/releases/latest` (Grove's two-remote workflow puts *releases* on the GitHub mirror, so "newer release available" = latest GitHub tag > installed `grove.__version__`). The HTTPS side effect lives at the edge in the module-level `fetch_latest_release_tag` seam; the checker **never raises** into a caller (it feeds render paths) — a failure logs and the last-good result (or "unknown") stands. TTL-cached 6h: releases ship rarely, GitHub's unauthenticated budget is 60/hr, and a slow GitHub must never stall a render. `fetcher`/`clock` are injectable; the global `tests/conftest.py` autouse fixture patches `fetch_latest_release_tag` so no test ever hits the network (same discipline as the fake tmux/git seams).
- **Semver compare is a pure unit (`_Version`, zero-padded, pre-release suffix dropped) + `update_available()`** — no `packaging` dep (we deliberately add none; `httpx` was already core). Equal/older or unparseable/unknown latest → no nudge.
- **Result is a plain `ReleaseStatus` dataclass (in-process state), mirrored onto the `WhoamiView` wire fields `latest_version`/`update_available` by the daemon.** The browser reads those via whoami and **never polls GitHub itself** — one daemon-side check feeds the web footer (the daemon resolves `check()` in the executor so the route never blocks). The TUI is a *separate process* (in-process engine, no daemon), so it holds its **own** `ReleaseChecker`: same engine code + bounded cache, not a second polling implementation. `latest_version` is the bare version (`0.2.0`, normalized at the single store site) so every client renders `v{latest}` symmetrically with `__version__`.

## Cross-platform

- **Pin `mypy<2.0` until 2.0 ships Linux x86_64 wheels.** Use `pathlib.Path` everywhere, `os.replace` for atomic writes, `shell=False` with list args for every subprocess. tmux on Windows requires WSL2 — surface a clear `TmuxError`, never half-support Windows-native. Degrade unsupported platforms to a typed error, never an import failure (same for POSIX-only stdlib modules — guard them behind `if sys.platform != "win32":`).
