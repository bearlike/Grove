# grove.core.watches — register a callback, halt, and be woken

> ↑ [grove.core](../CLAUDE.md) · [root](../../../../CLAUDE.md)

One concern: an agent waiting on something slow says what it is waiting for and **stops**, and Grove delivers the outcome when it settles. Wire shapes live in [contracts/watches.py](../contracts/CLAUDE.md); delivery is [`core/mailboxes.py`](../CLAUDE.md) unchanged; the daemon owns the routes and the lifespan.

## The cost model IS the design

A naive implementation gives each waiter a thread, or wakes every few seconds and scans the registry. Both scale CPU with how many agents happen to be waiting, which on a fleet host is exactly backwards — **waiting should be free**.

- **One scheduler for the host**: a single asyncio task over a `heapq` keyed on `next_due`, plus one `asyncio.Event` that register/cancel set to wake it early. No thread, process, timer or sleeping coroutine per watch or per workspace.
- **Nothing periodic.** An empty registry returns `None` from `seconds_until_next()`, so the loop awaits an event rather than a clock and no timer exists to fire. There is no tick, no sweep, no scan — the heap's minimum IS the next wakeup.
- **One shared single-worker pool** (`grove-watch`). A probe must be ONE bounded observation: a single API read, or a command with a timeout. A watcher that called `gh run watch` would move the agent's sleep loop into Grove's one worker, where it stalls every other watch on the host. The deliberate trade is that probes serialize; the remedy if it ever bites is a small FIXED worker count, never one that scales with the fleet.
- **A probe decides; a lifecycle verb runs elsewhere.** Idle freeze and hibernate use the daemon lifecycle runner and return at submission, with one in-flight action per workspace. Completion failures log and leave the row eligible next tick, rather than raising into the scheduler or double-submitting a slow action.
- **Writes follow state changes, not elapsed time.** `reschedule` no-ops when the due time has not moved — a 6-hour watch at 30 s is 720 ticks, and rewriting the file on each is how a mechanism that should be free becomes a disk-I/O problem.
- **A reload re-arms with JITTER** across each row's own interval, or forty recovered watches fire forty probes in the same instant.
- **Nothing on the startup path may raise out of the lifespan over this subsystem.** On 2026-10-15 the scheduler's `prime` already tolerated an unreadable log, and `StandingWatches.reconcile_all`'s final orphan sweep read the same log outside any guard, so startup died with exit 3 for 97 restarts. The sweep is cleanup and now logs; the 2026-10-09 fix had guarded the loop, and this was the next unguarded caller of the same read. **Guarding call sites one at a time is the recurring shape here; `RecordFile` making the read itself recover is what closes the class.**
- **The loop task is the only thing that fires a watch, and nothing restarts it, so a pass that raises must not end it.** Measured 2026-10-09: a one-bit flip in `watches.json` made `WatchLog.get` raise inside `tick`, the task died with no log line, and after the file was REPAIRED registration worked again while nothing fired host-wide until a daemon restart. `_run` now logs and backs off, and `tick` re-pushes the entry whose visit raised, because a popped standing row would otherwise be gone until a reload. **A guarded per-probe `try` is not a guarded loop**: the log reads either side of the probe were outside it.

## Ordering rules that survive a crash

- **Persist the outcome BEFORE delivering it.** A crash between the two leaves a durable `fired` row with `receipt=unknown` — recoverable, and visible in `grove watch ls`. Delivering first and crashing loses the outcome entirely: the heap entry is gone and nothing records what the watch concluded. Same "cheap failure over unbounded failure" argument as [`HandoverLog.claim`](../issueops/CLAUDE.md).
- **`unknown` is NEVER retried**, inheriting the mailbox's rule: a second copy of a message whose first copy may have landed is worse than an uncertain one.
- **`rejected` settles `undeliverable`, which is neither success nor failure of the WATCH.** The predicate may well have gone terminal; the recipient had simply stopped being live. Collapsing that into either outcome is this tree's recurring "the degraded answer is indistinguishable from the confident one" bug.
- **Every watch has a deadline, and there is no "wait forever".** `WatchRegistration.deadline` is optional on the wire but `None` means *the default for this predicate*, resolved in the scheduler (the one place that knows "now"): `DEFAULT_DEADLINE` (15 min) for open-ended predicates, and for a timer its own instant plus a minute — capping a timer at the open-ended default would make every long timer expire instead of fire. The default lives in the contract and nowhere else; the CLI sends `None` rather than its own number, or the CLI and MCP drift on how long an agent may be left waiting.
- **The re-check cadence is STORED on the row (`WatchView.every`), not derived.** It was once recomputed as `next_due - created_at`, which grows on every re-arm — a 30 s watch was probed at 30, 60, 120, 240, 480 s, doubling each time, so a long wait learned its subject had settled minutes late. A value that is an input belongs on the record; deriving it from a field the code itself rewrites is how it drifts.
- **A deadline is itself DELIVERED.** An expired watch mails the expiry, so an agent that halted is never left with no signal — the one guarantee a sleep loop structurally cannot make, and the reason halting is safe to recommend.
- **A settled row is RETAINED, not deleted**, pruned by age at scheduler startup. It is the record that this callback already went out, which is what stops a restart from sending it twice; the seven-day retention window leaves cancellation and delivery diagnostics available long after the workspace record is gone.

## Who a watch BELONGS to is its recipient

`GET /watches?workspace=<id>` (what the webapp's per-workspace card reads) filters on `recipient.workspace_id`, never on a `command` predicate's `workspace_id` and never on who made the HTTP call. An orchestrator registering `--for` a worker, or a command that runs in one tree and calls back to another, are both ordinary — the watch appears where its callback LANDS, because that is the session it can wake. The filter lives in `WatchScheduler.list` so the CLI, MCP and HTTP share one rule; a malformed id is a 422, never an empty list that reads as "no watches here". **The recipient also owns lifecycle, but a pause is not a kill.** A workspace whose record is GONE has every pending row cancelled; one that is merely not `RUNNING` (paused, error) loses only the standing kinds reconcile itself registers (ticket, trigger). An agent's own wait (timer, ci, command) outlives the pause: it halted on that watch, and cancelling it withheld the fired-or-expired mail that is the whole reason halting is safe (#976, found by the restart suite). Attachment changes only add or remove the standing ticket rows. **A row that came due while no daemon ran is told so**: `prime` remembers it as overdue in memory and the first visit appends a "Late: due at …, checked … later" clause to the outcome, because "the timer elapsed" means something different an hour on. Lifecycle callbacks arrive from a worker while observations resume on the scheduler loop, so `cancel` and post-probe transition share one scheduler lock: cancellation that wins keeps its row cancelled and sends no stale mail.

## `Watcher[P]` is the whole extension story

A watcher answers exactly one question — *has this settled?* — and holds no scheduling, persistence, delivery or retry logic. Adding a predicate is a subclass plus one registry entry; it cannot change when Grove wakes up, what it writes, or how a callback is delivered.

- **It is GENERIC over its predicate variant, and that was not the first design.** Originally every watcher took the whole `WatchPredicate` union and re-narrowed it to its own helpers — boilerplate a type checker cannot verify is complete and a reader cannot tell is correct. Two independent implementations hit the identical wall, which is the signal a shared seam is missing rather than two files needing a fix. Now the union-narrowing happens once in the base `evaluate` and subclasses implement `observe(predicate: P, now)`.
- **Returning `None` is the load-bearing case, and it covers "I cannot tell".** A forge that timed out, a rate limit, a container that is gone — all answer `None`, never a failed outcome. "I could not tell" and "it failed" are answers a recipient acts on differently, and collapsing them is how a transient network error comes to read as a red build.
- **A wrong-kind predicate RAISES rather than answering `None`.** That is a routing bug in the registry, and a silent "not yet" would leave the watch pending forever while looking perfectly healthy.
- **A missing watcher is a real state, not a raise.** A durable row may name a predicate whose watcher was removed; it settles as unwatchable instead of taking down every tick behind it.
- **`None` from `observe` means "not this time"; a subject that can NEVER be observed is refused by `admit` at registration.** The two were one answer until 2026-09-23, when a `ci` watch named `github` on a daemon whose own ticket config enabled only Gitea. Every probe raised `ticket provider 'github' is not enabled`, the scheduler logged it and re-armed, and the watch sat `pending` for the whole hour after CI had passed, then would have expired as "condition NOT met". **The provider lookup is a CONFIG fact, so it is knowable before anything is written**, and an agent is about to halt on the watch. `admit` checks configuration only, never the network, because a forge that is down now may be up at the next interval. Registration also refuses a kind with no watcher at all, for the same reason: the log would otherwise hold a row that can only settle as unwatchable. The refusal is `WatchUnobservable`, 422 `watch_unobservable`, and the message names the setting to change. **The daemon's CI watcher reads the DAEMON-wide ticket config, not a repo's**, so the agent's own workspace can enable a forge the watcher still cannot read. That asymmetry is why this is a refusal rather than a fallback.

## Two rules the predicates paid for

- **`ci` keys on an immutable head SHA, never a branch name** — a force-push makes a DIFFERENT commit with the same name, and a watch following the name answers about work nobody asked about. Terminal requires at least one check to have APPEARED and none still running: the window right after a push legitimately has no checks, and reading that as success is the failure mode the whole predicate exists to avoid.
- **`command` runs in the workspace that REGISTERED it**, inside its container when that is where the agent lives. The daemon cannot claim to hold "the same environment the agent had". A timeout must TERMINATE the child, not merely stop awaiting it — and the guard is only real if the output reader's join is bounded too, which is the one guard here that survived its first mutation.

## Testing it

**`prime()` is split from `start()` because "ready" and "running" are different states.** Conflating them makes the loop untestable: a test driving `tick()` while the background task also drains gives two consumers of one heap, each stealing entries (measured: 26 of 50). Tests `prime()` and drive `tick()` with a fake clock; only a test genuinely about the background loop calls `start()`.

**An idle-cost assertion goes vacuous by default and three of eight did here.** `asyncio.wait_for` blocks on REAL time, so in a sub-second test the loop never runs and "zero evaluations" passes against a scheduler that scans every row. Assert on the SCHEDULE (`seconds_until_next()` is `None`) rather than on counted work, drive `tick()` explicitly, and mutate the guard to confirm it bites.

## Standing ticket watches (#837)

A watch an agent HALTS on is a *wait*: it settles once, has a deadline, and mails its expiry. Tracking an attached issue or PR is a *subscription*: nobody halts on it, and it lives as long as the workspace. `TicketPredicate` is the one standing predicate. It has no deadline (`expires_at` is `None`), and its watcher answers `StillWatching(predicate, outcome)`: the scheduler persists the new baseline (`WatchLog.carry_on`) BEFORE mailing, so a crash loses at most one notification and never repeats one. A failed or rejected send leaves the watch pending, because only the workspace's lifecycle ends it.

- **Nobody registers these by hand.** `StandingWatches` reconciles a workspace's watches against its RECORD (one per attached ref while the persisted status is `RUNNING`, none otherwise) and is idempotent, so a lost edge or a restart is repaired by the next reconcile. It rides the ACTIVITY BUS, not the manager's events, because `grove tickets attach` usually runs in ANOTHER process and reaches the daemon only through the store-file watcher. That is also why `WorkspaceActivity.fingerprint` now carries the attached refs: attaching moved no other member, so no delta was ever published for it.
- **Grove's own writes are excluded by what is COMPARED, not by a filter after the fact.** `TicketSnapshot` holds only fields a person changes (title, state, draft, a body digest taken after `splice_footer` strips the badge region, a comment count). It leaves out assignees (Grove assigns itself) and the last-updated time (a sticky edit moves it). A new comment counts only without either issue-ops marker AND not by `viewer_login()`. The markers alone must be enough, because a tracker that cannot report its login still must not echo the sticky comment. That is the one guard that survived its first mutation, and it has its own test.
- **One read attempt per ticket per minute, however many workspaces or consumers.** The daemon shares ONE `tickets.reads.TicketReads` between the watcher and sticky publisher. It coalesces concurrent same-ticket misses and holds even failures for the full interval: without both guards, a publisher flush raced the watch or retried a failing forge faster than a minute. Fresh entries remain until expiry rather than being LRU-evicted under a busy fleet; see [tickets](../tickets/CLAUDE.md) for the memory trade-off. The provider read is `read_state`: one GET whose payload already carries body and comment count, and the thread is listed only when the count rises.
- **The first check records the baseline silently.** Its guard is correct but does not survive mutation, and that is structural rather than a gap: with no previous snapshot there is nothing to diff, so the test fixture cannot observe the difference.

## Triggers: Grove's own instructions into a working session (`trigger`)

The second standing predicate, and the one place Grove speaks into a session on its OWN initiative. That inversion is what every rule below pays for: nobody chose to send this text, so it must never reach a session that is not demonstrably working. It replaced the single-purpose `phase_nudge` (#892) and the brief's two delivery roads with ONE watch per running workspace evaluating every rule in `triggers.rules`.

- **Rules are configuration; conditions are code.** `core/data/triggers.json` is cascade layer 0 (beside the agent roster), and `triggers.rules` merges by `name` across layers through the same `_merge_named` the roster uses, so a project changes one field of a built-in without restating it. `TriggerWhen` is a closed set because each member is a check the watcher must know how to evaluate; a new RULE over an existing condition is config only. Rules are read from each workspace's OWN repo cascade at every check (`TriggerEvidence.rules`).
- **Eligibility is a PURE function (`TriggerWatcher.decide`) over `TriggerEvidence`, with one shared gate every automatic rule passes first**: live reconciled status, a WORKING primary, and replies + tool calls moved since the previous check. That last clause is the discriminator between "working on" and one long tool call or a stall, both of which freeze the counts while the blend can still say WORKING. Then each condition adds only what it can know (start window, compaction count, report age, generated title).
- **At most ONE rule per check, in config order**, so a brief and a reminder never arrive as one wall of text; the later one waits a check.
- **Every count is scoped to the PRIMARY SESSION id** (`TriggerPredicate.session_id`): a respawn or rotated session starts over, because a cap is a promise about one conversation's context window. A session first seen mid-life ADOPTS its compaction count as accounted for, or a resumed session would be reminded about compactions it went through before Grove looked.
- **A compaction is never consumed by the baseline, only by a firing.** `/compact` is usually typed into an idle session, so the reminder must wait for the next WORKING check rather than be dropped. The count comes from the spine fold the activity poll already pays for (`SpineFactsCache.compactions`), never a second transcript read.
- **`session_start` fires only inside `_START_WINDOW` of the session's first record**, so deploying triggers does not brief every session on the host that is already deep in its task.
- **`max_sends` is counted at the ATTEMPT and persisted BEFORE delivery** (`carry_on`), so a crash or a lost receipt can only under-send. The `unnamed` rule's cap of two is the guard against an agent that refuses to rename: without it, one reminder per check fills its context.
- **Manual dispatch (`grove trigger fire`, `POST /watches/triggers/fire`) advances the SAME standing watch** through `WatchScheduler.advance`, under the transition lock a probe result uses. So a dispatch and a scheduled check share one cap and one delivery road and cannot both count from one value. It keeps the live-status gate and skips only the rule's own condition. A workspace that is not RUNNING holds no trigger watch, so it is `skipped` without being touched, and an EMPTY selector is refused rather than read as "everyone".
- **Evidence is a FRESH row (`prepare_workspace_refresh`), never the maintained projection.** The poll waits on `_PollAudience`, so with no dashboard open the projection can hold WORKING for an agent that stopped hours ago. One row read per workspace per `check_seconds`.
- **Delivery is `MailboxDelivery.notify`, not `send`, and the difference is the safety property.** `can_receive` is TRUE for a dead native session because a message REVIVES it; `notify` re-checks the reconciled status at send time and calls `send_message(revive=False)`.
- **A trigger's text is fenced ONCE, by `trigger_text`, and the courier forwards it untouched.** Both used to fence, and every unit test was green because each half was tested alone: the first live reminder after the deploy arrived as `<grove-instruction>` nested in `<grove-instruction>`. The guard asserts on the COMPOSED text (renderer output through the real courier), the one place a double fence is visible. **When two components each own half of a format, test the seam, not the halves.**
- **The check interval is NOT the staleness threshold.** `phase_nudge` checked every `every_minutes`, so a 10-minute threshold reminded at up to 20 (the first live reminder read "15m ago"). Checks now run every `check_seconds` (60) and each rule carries its own `after_minutes`.
- **A retired kind is DROPPED from the log, not held aside** (`RETIRED_KINDS`). The per-row tolerance below exists for a kind a NEWER build owns; a kind this release replaced has no build that will ever read it, so holding it aside would carry an unreadable row forever.
- **A watch kind added by a release is a row an OLDER daemon will read, and strict per-row validation made one such row a host-wide outage.** Measured during #892: 13 `phase_nudge` rows reached the live log while the running daemon predated the kind, and every `grove watch` registration answered 500 until they were removed. `WatchLog` now applies tolerance per ROW (the unit that can be wrong on its own): an unparseable row is held aside verbatim and written back on every write, so it is invisible to this reader and never erased from under the newer build that owns it. Since #936 the log is a `RecordFile` ([core](../CLAUDE.md)): a version mismatch stays a loud refusal, but a file with no trustworthy header is moved aside and the log starts empty, because refusing made one flipped bit a daemon crash loop and every row here is either rebuilt by reconcile or bounded by a deadline.
