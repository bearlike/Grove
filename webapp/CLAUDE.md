# Grove Webapp Engineering Guidelines

> ↑ [root](../CLAUDE.md)

The webapp under `webapp/` is the **mobile-first dashboard** for Grove workspaces — Next.js 15 (App Router) + React 19 + Tailwind v4 + shadcn/ui, talking to the Grove daemon (`grove daemon serve`) via a Backend-for-Frontend route. Phone-friendly grid + project facets + live agent peek + comprehensive per-workspace commit history. **Observability-first, with a thin action layer (#56):** the reads are the bulk of the surface; the only mutations are the ones the engine already exposes (create + pause/resume/respawn/kill steering), driven as a faithful client of the daemon's existing wire contract — never new backend logic, never engine semantics re-implemented client-side.

This file composes **on top of** the repo-root [`CLAUDE.md`](../CLAUDE.md). Inherited principles (KISS, DRY, YAGNI, code-as-poem, side-effects-at-edges, tests-pin-contracts, Pydantic at public boundaries) all still apply — this file captures only what is *additional* or *different* for the Next.js stack. Engine + cross-cutting lessons stay upstream.

**Rules**

- Webapp engineering lessons live here; the **webapp visual contract** (color tokens, typography, component specs, do's and don'ts) lives in [`webapp/design-system.md`](design-system.md). Read that file before writing or reviewing any webapp component.
- Anything that crosses the wire (request/response shapes, error envelope, status palette) lives upstream — engine `grove/core/contracts/`, TUI palette `grove.core.contracts.status_palette` — and the webapp consumes via codegen. Don't redefine wire shapes here. Don't redefine status colors here either; mirror the upstream Python source through `lib/grove/status-tokens.ts` (drift-tested).
- A change that affects both the engine wire and this client lives in the engine commit; the webapp commit follows by re-running `npm run codegen`. Same commit if small, separate commits if large — but never invert the order.

## Stack contract (what we use, why, where)

| Layer | Choice | Notes |
|---|---|---|
| Framework | Next.js 15 App Router (React 19) | RSC where it pays, `"use client"` for interactivity. SSG for static pages, dynamic for `/api/*` and `/w/[id]`. |
| Styling | Tailwind v4 via `@tailwindcss/postcss` | Config lives in `app/globals.css` `@theme` block — NOT in a JS config. See `Tailwind v4 traps` below. |
| Component primitives | shadcn/ui via `npx shadcn@latest add <name>` | Compose, don't reinvent. All primitives go to `components/ui/`. |
| Animation utilities | `tw-animate-css` | Required for radix's `animate-in`, `slide-in-from-*`, `zoom-in-*`, `fade-in-*` classes (Tooltip, Sheet, Dropdown). Imported once in `globals.css`. |
| Icons | `lucide-react` | One icon set, never mix. |
| Theme | `next-themes` | `attribute="class"`, `defaultTheme="system"`. Mounting guard required (jsdom: see Testing). |
| Data fetching (server state) | TanStack Query 5 + SSE | The unified `/` grid rides one SSE stream (`useActivityStream`, 4 s poll fallback). Remaining polls pinned by hook: peek 2 s + commits 15 s (detail page), workspaces 5 s (rail footer), project sessions 15 s (session rail — SSE-invalidated on top, #158), turns 30 s (detail transcript — SSE-invalidated on top, #166). The poll interval on an SSE-backed resource is a BACKSTOP, not the freshness mechanism; a fingerprint diff on the shared snapshot is. Never fetch in components — go through `lib/grove/hooks.ts`. |
| Client UI state | Zustand 5 (`lib/grove/ui-store.ts`) | The ONE client-state store (#96). Owns ALL cross-component *UI* intent: composer draft, sidebar collapse, the persisted landing view (`landingView`, ADE #140), view scope/filter/search, and the single live-pane focus. SERVER state stays in TanStack Query — the two layers never mix (a TanStack cache mirrors the daemon; the store is local intent the daemon never sees). Persists the durable prefs (`sidebarCollapsed`, `landingView`, `hiddenStates`, `attentionOnly`) via `persist`+`skipHydration`, rehydrated once on mount in `providers.tsx` (so SSR/first-paint render defaults then flip — `hydrated` gates the persisted value); `query`/`scopeRepo`/the composer draft/`liveId` stay transient. Chosen over context+reducer: selector subscriptions mean a composer keystroke never re-renders the grid, zero provider boilerplate. **No server-derived mirror lives here anymore** — the ADE reframe (#138) moved the session page INTO the shared shell, so its live agent state renders from the header `ContextBar`'s `session-state-live` sr-only region (the in-page `context-task` subheader that briefly held it was deleted in #153) instead of round-tripping through a store slice for chrome that used to live outside the page tree (see the App shell section). |
| Type generation | `openapi-typescript` | `npm run codegen` writes `lib/grove/types.gen.ts` from daemon's `/openapi.json`. CI gate: `npm run codegen:check`. **Never hand-edit `types.gen.ts`.** |
| Tests | Vitest (unit + component) + Playwright (E2E) | Hermetic E2E uses fake daemon at `tests/e2e/_fake-daemon.ts`; live smoke (`tests/e2e/_live-smoke.ts`) is opt-in `npx tsx`. |

## Architecture

```
Browser ──http──▶ Next.js  ──http──▶ Grove daemon (loopback only)
                  │
                  ├ /api/grove/[...path] = thin proxy (BFF)
                  ├ /            = the landing surface: Hero (composer) | Overview (grid)
                  ├ /activity    = redirect("/") (kept so bookmarks don't 404)
                  └ /w/[id]      = session page (three-zone: rail | transcript | work panel)

All four routes render through ONE shared `app/(shell)/layout.tsx` (the ADE
reframe, #138) — the session page moved INTO this group and lost its own
standalone header/rail-less shell.
```

- **BFF (Backend-for-Frontend)**: `app/api/grove/[...path]/route.ts` is the **only** network boundary the browser hits. Daemon URL comes from `GROVE_DAEMON_URL` env (default `http://127.0.0.1:7421`). The browser never sees the daemon directly: no CORS, no client-side daemon URL config. LAN reachability comes from binding Next on `0.0.0.0` and forwarding through the BFF.
- **Wire types**: `lib/grove/types.ts` re-exports schemas from `lib/grove/types.gen.ts` (auto-generated). Components import from `lib/grove/types`, never from `types.gen.ts` directly. The codegen pipeline IS the DRY anchor for the engine ↔ webapp contract.
- **Domain models**: `lib/grove/{client,repo-facet,agent-activity}.ts` — class-encapsulated, methods on the type that owns the state (mirrors the engine's "code as poem" principle). `GroveClient` wraps the BFF; `RepoFacet` groups workspaces by repo; `AgentLiveStatus` owns the card's live-signal derived state. (The old `WorkspaceCardModel` was deleted in the #89 merge — the unified card reads `WorkspaceActivityView` + `AgentLiveStatus` directly, so a parallel card model was dead duplication.)
- **Client UI state**: `lib/grove/ui-store.ts` (Zustand) is the SINGLE home for cross-component UI intent (composer draft, sidebar collapse, the persisted landing view, scope/filter/search, live-pane focus) — see the stack table. Components select narrowly (`useUiStore(s => s.query)`); never thread UI state through props or one-off hooks. **There is no server-derived mirror in the store anymore.** Before the ADE reframe, the session page's live agent state had to round-trip through a `sessionStatus` slice because the status bar was fixed global chrome outside the page tree and couldn't receive props; the ADE (#138) deleted the status bar and moved the session page INTO the shared shell, so the page renders its live state directly off its own data — via the header `ContextBar`'s `session-state-live` sr-only `aria-live` region (#153), no store slice needed (the interim in-page `context-task` subheader was deleted). Don't reintroduce a server-derived slice here without re-checking whether the consuming chrome can just live inside the page instead.
- **Shared presentational atoms**: `components/shared/{state-mark,dot,meta,stat,relative-time,role-label,landing-ring}.tsx` are the tiny pure leaves reused everywhere a glyph/dot/count/middot-row appears — defined once (DRY), restyled in one place. `AgentStateMark` is THE agent-state glyph/color system (used by card, status pill, detail, rail); `MetaRow` is THE middot-separated meta row; `Stat` (#161) is THE countable-metric leaf (icon + compacted tabular value, zero-suppressing, unit-in-tooltip — the card META grammar); `RoleLabel` is THE transcript speaker label. (`CountChip` was retired with the ADE overhaul — no remaining consumer.)
- **Hooks**: `lib/grove/hooks.ts` is the single SERVER-state subscription surface. One hook per resource. Components consume hooks; **components never fetch directly**. The unified `/` grid subscribes to the one `useActivityStream`; the detail page's per-workspace resources poll as a backstop, with the open transcript additionally SSE-invalidated off that same stream (#166 — see the session lesson below).
- **The composer's repo chip sources from `useActivityStream()`'s `snapshot.projects`, NOT `useWorkspaces()` (#95).** Deriving repos from the workspace list silently hides empty projects — a repo with zero workspaces (fresh, or config-declared via the engine's `projects` field) contributes no rows, so you couldn't create the *first* workspace in it. The `/activity` snapshot is the authoritative project list (the engine emits a `ProjectGroup` per `known_roots()` entry, empty groups included), and each group already carries `repo_root` + `repo_name`. No new endpoint was needed — reusing the existing snapshot was the smaller diff than a `GET /projects`. Note this also makes the default-repo selection the snapshot's order (engine sorts roots), not workspace-recency order.
- **Per-create model selection rides the existing wire (#96), not new client logic.** The composer's `Model ▾` sets `CreateWorkspaceRequest.model` — an optional field threaded engine-side into the agent launch as `--model <id>` (claude_code/codex) or the mewbo REST create; the webapp only *forwards* the parameter, never interprets the model (the provider boundary). The pill shows for every kind except a bare `generic` shell; **its offered ids come from the DAEMON's per-agent catalog** (`AgentSummaryView.models`, resolved by `agents.resolve_models`), not a client-side list — and the custom-id row is always the escape hatch.

## Tailwind v4 traps (every one of these silently breaks the design)

1. **The `@theme` block in `app/globals.css` is mandatory.** Tailwind v4 + `@tailwindcss/postcss` does **not** consume `tailwind.config.{ts,js}`. Color utilities like `bg-background`, `bg-card`, `bg-muted`, `bg-primary`, `border-border`, `ring-ring`, `text-foreground`, `text-muted-foreground` are silently absent in compiled CSS unless declared via:
   ```css
   @theme inline {
     --color-background: hsl(var(--background));
     --color-card: hsl(var(--card));
     /* ...one entry per shadcn token... */
   }
   ```
   This is THE biggest gotcha and was the root cause of an entire session's worth of "the design looks broken" feedback. Verification probe: `curl http://127.0.0.1:3000/_next/static/css/app/layout.css | grep -c '\.bg-card'` should return `>0`. A green build does **not** mean the design system is wired — only the CSS-utility audit does.
2. **Animations and keyframes belong inside `@theme`.** `--animate-grove-pulse: grove-pulse 1s ...` and the `@keyframes grove-pulse { ... }` block both go inside the `@theme` block, not as siblings. The JS-config `theme.extend.animation` route is dead in v4.
3. **Radix animation classes need `tw-animate-css`.** Without `@import "tw-animate-css";` in `globals.css`, classes like `animate-in fade-in-0 zoom-in-95 slide-in-from-top-2` (used by Tooltip / Sheet / Dropdown / Dialog) compile to nothing and the corresponding components appear without animation.
4. **Tailwind v4 reverted v3's `currentColor` border default.** A bare `border` utility uses `currentColor` instead of the theme border. Reset explicitly:
   ```css
   @layer base {
     *, ::after, ::before, ::backdrop, ::file-selector-button {
       border-color: hsl(var(--border));
     }
   }
   ```
   Without this, every `border` looks like body text color, and `border-border` only works where it's the explicit utility.
5. **`tailwind.config.ts` should not exist in this repo.** PostCSS plugin ignores it; its presence misleads the next reader. If you add one back, you're working against the grain. Theme, fonts, keyframes, content paths — all of it goes in `globals.css` (`@theme`, `@source` in v4).
6. **`@source` is automatic in v4 for files imported transitively, but explicit for non-imported assets.** Currently we don't need it because every TSX file lands in the import graph; if you ever colocate a CSS file or use a class only emitted from a string template, add `@source "./components/foo.tsx"` to keep it scanned.

## shadcn/ui patterns

1. **Look in `components/ui/` first.** Available primitives: `Button`, `Badge`, `Card`, `Separator`, `Tabs`, `Sheet`, `Skeleton`, `Tooltip`, `Popover`, `DropdownMenu` (menus — Agent/Model pickers, overflow; via `@radix-ui/react-dropdown-menu`), `Resizable` (split panes, via `react-resizable-panels`). If a primitive exists, compose it; never hand-roll the same chrome. (`ScrollArea` is gone — see the scrollbar note below.)
2. **Pull new primitives via the CLI**: `npx shadcn@latest add scroll-area tooltip` (etc.). The CLI uses `components.json` for path aliases and writes canonical-shadcn output. Don't paste primitives in by hand — drift from canonical breaks future `shadcn add --overwrite` refreshes.
3. **`asChild` is the canonical pill-as-link pattern.** Use it for nav links so a single `<a>` carries pill geometry, focus ring, and SPA routing simultaneously:
   ```tsx
   <Button asChild variant="ghost" size="sm">
     <Link href="/" aria-label="Back to all workspaces">
       <ArrowLeft />
       <span>All workspaces</span>
     </Link>
   </Button>
   ```
   Never wrap a `<Link>` inside a `<button>`; never wrap a `<button>` inside an `<a>`. The Slot primitive solves both.
4. **All Button variants and sizes flow through `components/ui/button.tsx` (CVA).** New visual treatments add a CVA variant — they don't fork into a sibling component. Sizes: `xs`/`icon-xs` (h-7, dense chrome) · `sm`/`icon-sm` (h-8/h-9) · `default` (h-10) · `lg`. **SVG sizing lives per-size, not in the base** (`xs`/`icon-xs` → `size-3.5`, the rest → `size-4`) — a 16px glyph swamps a 28px control, so the compact toolbar controls only read correctly when the icon shrinks with the button. **Stroke width is a single global rule, not a per-component prop** (`svg.lucide { stroke-width: 1.75 }` in `globals.css` @layer base, #139) — lucide-react has no theme provider, so this CSS selector (targeting the `lucide` class every lucide icon carries) is the one seam for an app-wide stroke tune. Never pass `strokeWidth` on individual `<Icon>` instances to work around it.
5. **`<Badge>` is the right base for any pill** (status, identity, count). Compose with `className` / inline `style` for color tokens; do NOT introduce a sibling pill primitive.
6. **`ScrollArea` is no longer the app-wide scrollbar mechanism (ADE overhaul #139).** A global `@layer base` rule in `globals.css` (`scrollbar-width: thin; scrollbar-color: var(--scrollbar-thumb) transparent`) themes every native `overflow-auto`/`overflow-y-auto` element for free — Baseline since late 2024, no JS, no wrapper. `CommitList` and `TurnsView` migrated to a plain `overflow-y-auto` div under this rule. **Do not add `::-webkit-scrollbar`** — current Chrome deprioritizes it and styling it force-renders a classic always-visible bar, killing native overlay auto-hide. `ScrollArea` is now **fully deleted** — the `components/ui/scroll-area.tsx` primitive and the `@radix-ui/react-scroll-area` dependency are both gone; every former consumer (the rail body included, #152) rides a plain `overflow-y-auto` div under the global rule. Don't reintroduce it.

## Design language (visual contract)

This section is the canonical visual contract for the webapp. Update it in the same commit as any change that affects look or feel.

### Theme (the space-black redesign, #98-followup; detuned + contrast-contracted in the ADE overhaul, #139)

Two cohesive themes, defined ONLY as the neutral ramp in `globals.css` (`:root` light, `.dark`). **Dark = "space black":** a deep near-black canvas, still the dark-first identity, but **detuned from a cool-blue cast (hue ~224) to near-neutral/barely-warm (hue ~45-60, chroma unchanged, #139)** — the blue cast was the one thing fighting the warm terracotta accent (design-direction.md §4.4, ruling 1.3). **Light = a warm-neutral off-white** (`#faf9f5`, hue ~48, replacing the earlier cool slate at hue ~220) so it reads closer to the Claude benchmark. The whole neutral ramp is ONE hue family per theme with **wide lightness steps** so elevation reads without borrowing chroma. The **semantic palettes (`--status-*` / `--agent-*` / `--ref-*`) are unchanged** — still mirrored from Python and drift-synced; only neutrals + the terracotta trio moved. When you touch theme, touch the neutral ramp, never the semantic hexes here.

**Terracotta is three tokens, not one** (#139): `--primary` stays the brand MARK only (logo, dark-mode ring) — white text on it is only 3.12:1 and fails AA, so it is never a text-bearing fill. `--primary-fg` is terracotta AS TEXT (the `you` speaker label, links). `--primary-strong` is the deepened CTA fill for send/create buttons (white label clears AA in both themes). `components/ui/button.tsx`'s `default` variant still renders `bg-primary text-primary-foreground` — that pre-existing AA gap was flagged but deliberately NOT touched in the #139 token pass (component-class changes are a later phase); fix it by swapping to `bg-primary-strong` when that component is next restyled.

**The contrast contract is enforced, not eyeballed:** `tests/unit/contrast.test.ts` parses the `:root`/`.dark` HSL tokens straight out of `globals.css` and asserts the WCAG floors from design-direction.md §4.4 (AA 4.5 for all text including 12-13px meta, AAA 7 for prose, 3:1 for non-text) — mirrors the `status-tokens.test.ts` drift-test pattern, so a future edit that lightens a token below floor fails the build. It reads only HSL-triplet tokens (`H S% L%`); the frozen hex-based `--status`/`--agent`/`--ref` vars and the `rgba()` `--scrollbar-thumb` are outside its regex and untouched.

### Surfaces (elevation tiers)

A deliberate elevation LADDER — climbing in lightness so depth is legible without chroma. Chrome (header · session rail, incl. its footer) shares ONE tone so the persistent frame reads as a single surface around the content canvas. (The standalone status bar this table used to also list is deleted — the ADE reframe, #138 — its content moved into the rail's footer, see App shell.)

| Token | Use | Class |
|---|---|---|
| Base canvas | Body, page background, deepest terminal well | `bg-background` |
| Chrome | Header · session rail (incl. rail footer) — the persistent frame | `bg-sidebar` (+ `border-sidebar-border`) |
| Panel | Cards, primary surfaces | `bg-card` |
| Overlay | Tooltips, dropdowns, dialogs | `bg-popover` |
| Raised | Composer hero, raised wells above a card | `bg-elevated` |
| Subtle well | Card footer strips | `bg-muted/40` |
| Active fill | Pressed scope/filter chip, hover | `bg-accent` / `bg-muted/60` |

Borders are `border-border` on content and `border-sidebar-border` on chrome, unless an indicator is meaningful (e.g. `border-l-2` in a tier accent var for an attention card / active commit row).

The session page (`/w/[id]`) once stacked three of these into an explicit elevation ladder (#90: `bg-background` canvas → lifted `bg-card` transcript card with an `m-3/lg:m-4` gutter → rows; terminal on a deeper `bg-background` well, #92). **Superseded by the #124 density pass, then the #130 chrome teardown, then the ADE reframe (#138, 2026-07-06):** the card, its lift gutter, the nested transcript frame, and the terminal frame all dissolved; the page moved INTO the shared shell (rail + header now persistent there too) and its former standalone status bar was deleted outright. The page is a full-bleed three-zone shell (rail | transcript | work panel) whose depth is surface **tone + space**, never lift and never lines. See the App shell section and the density/teardown/ADE session lessons below.

**No drop shadow on dark surfaces — depth is the surface ladder, not `box-shadow`.** [`design-system.md`](design-system.md) is the authoritative visual contract; this section must never contradict it. Cards, panels, buttons, tabs, and inputs carry depth through their `bg-*` tier + a hairline border, never a `shadow-*` utility (enforced repo-wide). The *only* shadow exception is floating overlays that genuinely leave the page plane — `Tooltip`/`Dialog`/`Sheet`/`DropdownMenu`/`Popover` keep their shadcn shadow. Likewise `rounded-full` is for status pills and toggle pills (the composer's quiet `Agent ▾`/`Model ▾` selectors) only — momentary action buttons, including the terracotta send button, are `rounded-md`. A previous redesign drifted shadows onto cards/buttons; re-adding them is the regression to watch for.

**Quiet-chrome discipline (the redesign's core rule, tightened in #96).** Surfaces are neutral graphite; **saturated hue appears ONLY to carry state** (the status / agent / ref tokens below — unchanged, still TUI-drift-synced), and only as a **small mark** — a glyph, a `Dot`, a thin `border-l-2` accent bar — **never a large fill or a full-card border/glow** (the old gold-bordered WAITING card was the loudest noise on the wall). Terracotta `--primary` is reserved for the **composer's create/send CTA** + the brand mark + the `you` speaker label, nothing else — scarcity is what makes the send button read as the one primary action. When something looks flat, the fix is structure (a tone well, spacing, a section label), not color — and since #130, tone + space before a drawn line. Quiet-chrome is the *color* clause of the broader calm-first philosophy; the named philosophy (calm technology, one focal surface, progressive disclosure, tone-over-lines) lives in [`design-system.md`](design-system.md) under **Design philosophy**.

### Color language (semantic tokens, not hex)

Defined once in `globals.css`, mirrored at component layer via `[var(--token)]` arbitrary values.

| Token | Hue | Use | Sparingly? |
|---|---|---|---|
| `--primary` | terracotta | Brand (the Grove logo mark) + the composer's create/send CTA + the `you` transcript speaker label (`RoleLabel` — the TUI's human-prompt clay). | Yes — exactly those three; never card chrome, never a second CTA. |
| `--ref-branch` | teal | Current branch identifier (mono text + outline borders). | Wherever a branch name appears. |
| `--ref-info` | blue | Agent identifier. | Wherever an agent name appears. |
| `--ref-add` | green | Diff additions, "ahead" stat polarity. | Wherever a positive count is meaningful. |
| `--ref-remove` | red | Diff removals, "behind" stat polarity. | Wherever a negative count is meaningful. |
| `--status-active`, `--status-running` | lime / olive | Lifecycle: ACTIVE, RUNNING. | Status badge + accent stripe + the rail footer's daemon-reachability dot only. |
| `--status-idle` | blue (light) / pale-blue (dark) | Lifecycle: IDLE. | Same. |
| `--status-offline`, `--status-paused` | neutral gray | Lifecycle: OFFLINE / PAUSED. | Same. |
| `--status-orphaned` | amber | Lifecycle: ORPHANED. | Same. |
| `--status-error` | red | Lifecycle: ERROR. | Same. Also the "daemon unreachable" indicator. |

The status palette is **mirrored** from `grove/core/contracts/status_palette.py` — the Python source is canonical. The drift test in `tests/unit/status-tokens.test.ts` reads the Python file at test time and asserts the JS constants match. **If you change a status hex, change it in Python.**

### Typography

Three families, all self-hosted via next/font (no CDN, no layout shift) and declared in ONE place — `app/fonts.ts` — then mapped to Tailwind tokens in the `globals.css` `@theme`: **Geist Sans** (`--font-sans`, UI chrome), **Geist Mono** (`--font-mono`, code + git identifiers), and the terminal **JetBrains Mono Nerd Font** (`--font-terminal` → `--font-jetbrains-nerd`, #92). Geist's `.variable`s ride `<html>` in `app/layout.tsx`; the Nerd Font's `.variable` is dropped ONLY on the terminal subtree (`terminal-pane` / `peek-snapshot`), never `<html>` — its full (un-subset) powerline/private-use glyph ranges are the point for agent TUIs but must not bleed into app chrome. Body carries `letter-spacing: 0.01em`.

A **compact, dense type scale** — the redesign's defining move (quiet IDE feel, max info per row):

| Tier | Class | Use |
|---|---|---|
| Title | `text-base` (16px) `font-semibold` | Page + card titles, prominent stat values. |
| Body | `text-sm` (14px) | Body copy, descriptions, transcript prose. |
| Dense row | `text-[13px]` | Sidebar entries, metric one-liners, AND **all code** (inline + fenced + tool args, forced `font-mono text-[13px]`). |
| Metadata | `text-xs` (12px) `text-muted-foreground` | Relative times, byline copy, secondary info. |
| Section label | `text-[11px] font-semibold uppercase tracking-[0.08em] text-muted-foreground` | Panel section headers ("SUMMARY", "AGENT"). The terminal-feel cue. |
| Micro label | `text-[10px] uppercase tracking-wider` | Stat units (AHEAD / BEHIND / DIRTY under numbers). |

`font-mono` for **every** git/code identifier: branches, base branches, agent names, SHAs, commit subjects (no — bodies stay sans), file paths. The terminal `<pre>` uses `font-terminal` (~12–13px) instead, so the Nerd Font glyphs resolve.

**A second, dormant type scale lives in `globals.css`'s `@theme inline`** (`--text-page-title`/`--card-title`/`--prose`/`--caption`/`--code`/`--micro` + matching `--tracking-*`, #139, design-direction.md §4.3) — named tiers for sizes/line-heights the table above doesn't cover (20px titles, 16px/1.6 chat prose, 11px uppercase micro-labels). Defined but **not yet applied to any component** — later phases (rail, chat, work panel) consume the resulting `text-page-title` etc. utilities as they restyle. Don't rewrite the table above until a phase actually switches components onto it.

### Spacing

4 px grid. Allowed gap values: `{1, 1.5, 2, 3, 4, 5, 6}`. Allowed padding values: `{2, 3, 4, 6}`. Card padding `p-4` standard, `p-3` compact, `p-6` spacious.

**Layout (full-bleed shell, ADE reframe #138).** The chrome is full-bleed: the session rail (`w-70`, animating to `w-0`/full-hide when collapsed — no icon strip, #152) hugs the viewport's left edge and runs full height below the header; the header (`h-13`, 52px) spans the full width — both on `bg-sidebar`. There is no status bar anymore (deleted in the reframe; its content moved into the rail footer). The CONTENT re-centers inside each route's own `<main>` (the landing centers at `max-w-[100rem]`; the session page is a fixed-height three-zone shell), so an ultrawide reads "rail flush-left · wide centered canvas", never "everything stranded in a narrow middle column". The viewport-fill magic number is now `3.25rem` (`h-13`, the header alone) — used by the (shell) rail height (`top-13`/`h-[calc(100dvh-3.25rem)]`) and the session page's `<main>`; change it in both if the header height ever moves.

## Testing pyramid

```
tests/unit/         — Vitest, pure logic (status palette, contrast ratios, ANSI strip, RepoFacet, AgentLiveStatus, GroveClient)
tests/component/    — Vitest + jsdom + RTL, single-component contracts
tests/e2e/          — Playwright, mobile-chrome + desktop-chrome projects
tests/e2e/_fake-daemon.ts — Hermetic Express server used by Playwright
tests/e2e/_live-smoke.ts  — Manual `npx tsx` against a real daemon for screenshot capture
```

- **Vitest config requires** `esbuild: { jsx: "automatic", jsxImportSource: "react" }` — without it the JSX runtime path errors on every component test. **`vitest.setup.ts` polyfills `matchMedia`** because next-themes calls it on mount and jsdom doesn't provide it, **and `ResizeObserver`** because radix ScrollArea constructs one when its scrollbar/thumb mounts — which happens lazily on the first `userEvent` hover/click inside a ScrollArea, so the crash only appears in interaction tests, not render-only ones.
- **`next/font` is a build-time transform Vitest can't run** (`next/font/local` is a directory import that throws under jsdom/ESM). So `@/app/fonts` is **aliased to a stub** (`tests/_helpers/fonts-stub.ts`) via a `vitest.config.ts` `alias` entry that must come *before* the generic `@` alias (Vite matches in order). The stub returns inert `{ variable: "" }` font objects; any component that imports a font (terminal panes, the layout) needs this or its test errors at import.
- **jsdom serializes hex colors to `rgb()`.** Tests that assert on color use the `expectColor()` helper (in `tests/_helpers/`) which converts hex → rgb before comparing. Don't compare raw style strings.
- **Test seam = the component's testid + ARIA + visible text.** Tests pin `data-testid="status-badge"`, `data-testid="stat-trio"`, `data-testid="commit-list"`, `data-testid="workspace-card"`, `data-testid="context-bar" / "identity-trigger" / "branch-summary" / "detail-panel" / "agent-panel" / "work-panel"` (the session page's identity popover + panes seams — `identity-strip`/`context-task` are the #153-deleted flatten and `identity-panel`/`summary-panel` are pre-ADE names; none exist in the codebase). New visual treatments must preserve those testids and the first-child structure that tests depend on (e.g. `StatusBadge`'s firstChild is the pulse-eligible glyph). Update both in the same commit if the contract truly changed.
- **Playwright uses port 3101**, NOT 3100. Some machines have a root-owned next-server bound to 3100 from another project; we side-step it. The fake daemon binds 8421.
- **`E2E_LIVE_DAEMON=1 npm run test:e2e`** runs Playwright against a real daemon instead of the fake (only useful when iterating on something the fake doesn't fully model — keep it the exception). The auth setup project polls for up to 60 s in live mode so you can `grove auth approve` the printed code from another terminal.
- **Playwright is hermetic since #32 — auth included.** A `setup` project (`tests/e2e/auth.setup.ts`) pairs once through the BFF (`POST /api/auth/pair` → poll `GET /api/auth/pair/{id}`), saves the resulting HttpOnly `grove_session` cookie as storageState (`tests/e2e/.auth/`, gitignored), and both browser projects depend on it. The fake daemon auto-approves (first poll consumes, deterministic `FAKE_DAEMON_TOKEN`) and **bearer-gates every data endpoint**, so the suite pins the full cookie → BFF → bearer chain, not just rendering. The webServer env sets `XDG_CONFIG_HOME` to `test-results/xdg-config` so the BFF's cookie store never touches the real `~/.config/grove/webapp-sessions.json`. Expected baseline: all green locally with zero running daemons (25 passed as of 2026-06-11).

## Production hosting (systemd-user)

For "leave it running on a host" deployments — typically the same machine that hosts the daemon — install the user-scope systemd unit shipped under [`packaging/systemd/`](../packaging/systemd):

```bash
make webapp-build           # one-shot: npm ci + npm run build (required before enabling)
WITH_WEBAPP=1 make systemd  # writes both unit files
WITH_WEBAPP=1 make systemd-enable  # enable + start now
```

Webapp install is **opt-in** (default `WITH_WEBAPP=` is empty). The webapp service `Wants=` (not `Requires=`) the daemon — daemon hiccups don't tear the webapp down, the session rail's footer surfaces the unreachable state instead (`daemon-status`, see App shell). The unit binds `0.0.0.0:3000` so the dashboard is reachable from a phone on the same Wi-Fi without extra port forwarding.

After webapp source changes: `make webapp-build && systemctl --user restart grove-webapp`. The service does NOT auto-rebuild — production mode reads `.next/` build output and runs cold-fast, dev mode's hot-reload would be wrong here.

## Local dev / tmux orchestration

The standard layout is a tmux session named `grove-webapp-dev` with two windows:

```
window 0: daemon  → uv run grove daemon serve --port 7421
window 1: webapp  → npm run dev   (binds 0.0.0.0:3000, LAN-reachable)
```

LAN URL is announced in the dev log (`http://192.168.x.x:3000`). Phone testing: open the LAN URL on your phone while connected to the same Wi-Fi.

**When `next dev` errors with `Cannot find module './<chunk>.js'` (e.g. `611.js`):** the `.next` cache is stale. Fix is `rm -rf .next && npm run dev` (NOT `--clear-cache`, NOT `npm install`). Same shape applies to a `_not-found` collection error during `next build` — clean cache, rebuild. **Do not** `rm -rf .next` while a `next dev` is running; it corrupts in-flight pack files and leaves the dev server in a degraded state. Stop dev → clear → start dev.

**Never run `next dev` inside the checkout that also serves the production `grove-webapp` systemd unit** — `next dev` and `next start` both read/write the same `.next/` directory, so a dev instance launched in-place can race the running production build (observed: a `next dev` on a spare port threw `next/font: Cannot find module '../../../../lib/picocolors'` mid-request against the shared `.next`). This host runs several concurrent agent workspaces, each a separate git worktree — for any live-browser check of a webapp change, verify inside YOUR OWN worktree (fresh `.next`, no shared state), never the main checkout that systemd points at. Point `GROVE_DAEMON_URL` at a spare fake-daemon or daemon port and pick a dev port that isn't 3000.

## Repo-level gotchas (specific to webapp's location in the monorepo)

- **`/webapp/lib/` was previously caught by the repo-root `.gitignore` rule for Python `lib/`**. Resolved by adding `!/webapp/lib` and `!/webapp/lib/**` negations to repo `.gitignore`. If a new top-level dir under `webapp/` shares a name with a Python directory we ignore (e.g. `dist/`, `build/`), apply the same negation pattern.
- **The webapp does NOT depend on the Python venv**. It has its own `node_modules` and `package.json`. CI matrices that build webapp can skip the Python toolchain.
- **When your branch changes a wire shape, `codegen` / `codegen:check` against the *running* daemon (7421) is wrong — it serves the main checkout's OLD openapi.** The daemon `~/.local/bin/grove` resolves to the last-installed checkout, not your worktree, so a new/changed field never appears and `codegen:check` "passes" stale (or diffs forever). Boot a throwaway daemon from the worktree on a spare port and point codegen at it: `uv run grove daemon serve --port 7422 &` then `GROVE_DAEMON_URL=http://127.0.0.1:7422 npm run codegen` (and `codegen:check`). Kill it after. The engine commit + the regenerated `types.gen.ts` land together; on deploy the real daemon must be restarted on the new code (the #96 `CreateWorkspaceRequest.model` field rode in this way).

## Session lessons (non-trivial)

Things that took real time to figure out. Capture *why* and the *invariant*, not line numbers — when code moves, update the bullet, don't delete it.

- **The "5 minutes before the transcript renders" bug (2026-07-11) was the DAEMON, not this client — measure the server seam before touching the fetch/render pipeline.** The session page's data path was already right (bounded `last=100` turns fetch, SSE fingerprint-gated invalidation, lazy panel chunk): the wait came from the daemon full-re-JSON-parsing every session in the workspace's cwd on EVERY `/sessions` + `/turns` request, while the 2 s activity poll pegged two executor threads doing the same — every webapp request queued behind GIL-saturated full parses of a multi-GB transcript tree, and the SSE invalidation re-paid it per progress tick. Fixed at the engine seam (`core/agents/transcript_cache.py`: incremental fold cache + stat-signature memo, see [agents](../src/grove/core/agents/CLAUDE.md)); measured after: worst-case session 0.49 s cold / ~5 ms warm / ~50 ms per live append, transcript visibly rendered <3 s from navigation against the live daemon. **Invariant for future "webapp feels slow" reports:** time `SessionExplorer.for_workspace` + `turns_for` at the engine first (`uv run python`, two timed calls) — if warm reads are >50 ms the server cache regressed; only then look at client memoization. The one candidate CLIENT lever, deliberately NOT built (no observed jank): `chatItemsFromTurns` mints new object identities per refetch, so assistant-ui re-converts/re-renders every message on each SSE-driven refetch — stabilizing item identity across refetches is the seam if transcript-scroll jank ever shows up while an agent works.

- **The #98-followup overhaul = a frozen-token FOUNDATION + a fleet over disjoint surfaces.** The cohesive "feel" (the space-black/light neutral ramp + elevation tokens in `globals.css`, the compact Button scale, the full-bleed shell) was authored SOLO first and frozen as the contract; surface agents (composer · card · detail · chrome) then only restyled internals against those tokens, conflict-free (the stable-public-surface pattern from root CLAUDE.md). Three non-obvious invariants the overhaul re-confirmed: (1) **only the NEUTRAL ramp + `--primary` are free to retheme** — `--status-*`/`--agent-*`/`--ref-*` are mirrored from Python and drift-tested (`status-tokens`/`agent-state-tokens`), so a theme change touches neutrals only or the drift tests fail; (2) **a new chrome token (`bg-sidebar`, `bg-elevated`) is invisible until added to BOTH the `@theme` bridge AND the `:root`/`.dark` var blocks** — same Tailwind-v4 trap as below, re-verified by the `grep -o bg-sidebar .next/**/*.css` count after build; (3) the viewport-fill magic number (`h-12` header + `h-7` status = `4.75rem`) is duplicated in the (shell) rail height and `/w/[id]` `<main>` — move a chrome height, change both.
- **streamdown stays lazy on EVERY surface that renders it, including the composer (#98).** The composer's fullscreen Markdown Preview imports `Response` via `next/dynamic({ ssr:false })`, not a static import — a static import would pull streamdown (the chat panel's whole bundle cost) into the home `/` route bundle, which must stay lean. Verified by the build report (`/` First Load stayed ~194 kB). Same discipline as `ai-elements/response` being its own module behind the chat panel's `next/dynamic`. - **The BFF cookie store is file-as-source-of-truth with single-entry deltas — never a whole-memory dump (#40, the repeated-re-pairing bug).** `next start` runs several worker processes, each holding its own in-memory `Map`; the old `flush()` rewrote the entire file from one worker's memory, so a flush from a worker whose memory was stale silently deleted a cookie another worker had *just* minted → the browser's cookie id mapped to nothing → forced re-pair ("re-pairs over and over for no reason, especially on mobile").
