# Grove Webapp Engineering Guidelines

> ↑ [root](../CLAUDE.md)

The webapp under `webapp/` is the **mobile-first dashboard** for Grove workspaces — Next.js 15 (App Router) + React 19 + Tailwind v4 + shadcn/ui, talking to the Grove daemon (`grove daemon serve`) via a Backend-for-Frontend route. Phone-friendly grid + project facets + live agent peek + comprehensive per-workspace commit history. **Observability-first, with a thin action layer (#56):** the reads are the bulk of the surface; the only mutations are the ones the engine already exposes (create + pause/resume/respawn/kill steering), driven as a faithful client of the daemon's existing wire contract — never new backend logic, never engine semantics re-implemented client-side.

This file composes **on top of** the repo-root [`CLAUDE.md`](../CLAUDE.md). Inherited principles (KISS, DRY, YAGNI, code-as-poem, side-effects-at-edges, tests-pin-contracts, Pydantic at public boundaries) all still apply — this file captures only what is *additional* or *different* for the Next.js stack. Engine + cross-cutting lessons stay upstream.

**Rules**

- Webapp engineering lessons and webapp visual contract both live in *this* file. Splitting them into two adds friction without payoff at our current scale; promote to a sibling `webapp/design-system.md` only when this file exceeds ~500 lines.
- Anything that crosses the wire (request/response shapes, error envelope, status palette) lives upstream — engine `grove/core/contracts/`, TUI palette `grove.core.contracts.status_palette` — and the webapp consumes via codegen. Don't redefine wire shapes here. Don't redefine status colors here either; mirror the upstream Python source through `lib/grove/status-tokens.ts` (drift-tested).
- A change that affects both the engine wire and this client lives in the engine commit; the webapp commit follows by re-running `npm run codegen`. Same commit if small, separate commits if large — but never invert the order.

## Stack contract (what we use, why, where)

| Layer | Choice | Notes |
|---|---|---|
| Framework | Next.js 15 App Router (React 19) | RSC where it pays, `"use client"` for interactivity. SSG for static pages, dynamic for `/api/*` and `/w/[id]`. |
| Styling | Tailwind v4 via `@tailwindcss/postcss` | Config lives in `app/globals.css` `@theme` block — NOT in a JS config. See `Tailwind v4 traps` below. |
| Component primitives | shadcn/ui via `npx shadcn@latest add <name>` | Compose, don't reinvent. All primitives go to `components/ui/`. |
| Animation utilities | `tw-animate-css` | Required for radix's `animate-in`, `slide-in-from-*`, `zoom-in-*`, `fade-in-*` classes (Tooltip, Sheet, Dropdown). Imported once in `globals.css`. |
| Icons | `lucide-react` | One icon set, never mix. |
| Theme | `next-themes` | `attribute="class"`, `defaultTheme="system"`. Mounting guard required (jsdom: see Testing). |
| Data fetching (server state) | TanStack Query 5 + SSE | The unified `/` grid rides one SSE stream (`useActivityStream`, 4 s poll fallback). Remaining polls pinned by hook: peek 2 s + commits 15 s (detail page), workspaces 5 s (status bar). Never fetch in components — go through `lib/grove/hooks.ts`. |
| Client UI state | Zustand 5 (`lib/grove/ui-store.ts`) | The ONE client-state store (#96). Owns ALL cross-component *UI* intent: composer draft, sidebar collapse, view scope/filter/search, the single live-pane focus. SERVER state stays in TanStack Query — the two layers never mix (a TanStack cache mirrors the daemon; the store is local intent the daemon never sees). Persists only the durable prefs (`sidebarCollapsed`, `hiddenStates`, `attentionOnly`) via `persist`+`skipHydration`, rehydrated once on mount in `providers.tsx` (so SSR/first-paint render defaults then flip — `hydrated` gates the persisted value). Chosen over context+reducer: selector subscriptions mean a composer keystroke never re-renders the grid, zero provider boilerplate; it replaced three ad-hoc state homes (`use-sidebar-state.ts`, `filter-persistence.ts`, page-local `useState`) — a net deletion. |
| Type generation | `openapi-typescript` | `npm run codegen` writes `lib/grove/types.gen.ts` from daemon's `/openapi.json`. CI gate: `npm run codegen:check`. **Never hand-edit `types.gen.ts`.** |
| Tests | Vitest (unit + component) + Playwright (E2E) | Hermetic E2E uses fake daemon at `tests/e2e/_fake-daemon.ts`; live smoke (`tests/e2e/_live-smoke.ts`) is opt-in `npx tsx`. |

## Architecture

```
Browser ──http──▶ Next.js  ──http──▶ Grove daemon (loopback only)
                  │
                  ├ /api/grove/[...path] = thin proxy (BFF)
                  ├ /            = the ONE unified workspace surface (shell group)
                  ├ /activity    = redirect("/") (kept so bookmarks don't 404)
                  └ /w/[id]      = detail page
```

- **BFF (Backend-for-Frontend)**: `app/api/grove/[...path]/route.ts` is the **only** network boundary the browser hits. Daemon URL comes from `GROVE_DAEMON_URL` env (default `http://127.0.0.1:7421`). The browser never sees the daemon directly: no CORS, no client-side daemon URL config. LAN reachability comes from binding Next on `0.0.0.0` and forwarding through the BFF.
- **Wire types**: `lib/grove/types.ts` re-exports schemas from `lib/grove/types.gen.ts` (auto-generated). Components import from `lib/grove/types`, never from `types.gen.ts` directly. The codegen pipeline IS the DRY anchor for the engine ↔ webapp contract.
- **Domain models**: `lib/grove/{client,repo-facet,agent-activity}.ts` — class-encapsulated, methods on the type that owns the state (mirrors the engine's "code as poem" principle). `GroveClient` wraps the BFF; `RepoFacet` groups workspaces by repo; `AgentLiveStatus` owns the card's live-signal derived state. (The old `WorkspaceCardModel` was deleted in the #89 merge — the unified card reads `WorkspaceActivityView` + `AgentLiveStatus` directly, so a parallel card model was dead duplication.)
- **Client UI state**: `lib/grove/ui-store.ts` (Zustand) is the SINGLE home for cross-component UI intent (composer draft, sidebar collapse, scope/filter/search, live-pane focus) — see the stack table. Components select narrowly (`useUiStore(s => s.query)`); never thread UI state through props or one-off hooks.
- **Shared presentational atoms**: `components/shared/{state-mark,dot,count-chip,meta}.tsx` are the tiny pure leaves reused everywhere a glyph/dot/count/middot-row appears — defined once (DRY), restyled in one place. `AgentStateMark` is THE agent-state glyph/color system (used by card, status pill, detail); `MetaRow` is THE middot-separated meta row.
- **Hooks**: `lib/grove/hooks.ts` is the single SERVER-state subscription surface. One hook per resource. Components consume hooks; **components never fetch directly**. The unified `/` grid subscribes to the one `useActivityStream`; only the detail page still polls per-workspace resources.
- **The composer's repo chip sources from `useActivityStream()`'s `snapshot.projects`, NOT `useWorkspaces()` (#95).** Deriving repos from the workspace list silently hides empty projects — a repo with zero workspaces (fresh, or config-declared via the engine's `projects` field) contributes no rows, so you couldn't create the *first* workspace in it. The `/activity` snapshot is the authoritative project list (the engine emits a `ProjectGroup` per `known_roots()` entry, empty groups included), and each group already carries `repo_root` + `repo_name`. No new endpoint was needed — reusing the existing snapshot was the smaller diff than a `GET /projects`. Note this also makes the default-repo selection the snapshot's order (engine sorts roots), not workspace-recency order.
- **Per-create model selection rides the existing wire (#96), not new client logic.** The composer's `Model ▾` (Claude/Codex models + a custom-id row) sets `CreateWorkspaceRequest.model` — an optional field threaded engine-side into the agent launch as `--model <id>` (claude_code/codex; mewbo/generic have no launch model flag, so the pill is hidden). The webapp only *forwards* the parameter; it never interprets the model (the provider boundary). Model id defaults live in `components/composer/models.ts` (mechanism, not policy — the custom-id row is always the escape hatch).

## Tailwind v4 traps (every one of these silently breaks the design)

1. **The `@theme` block in `app/globals.css` is mandatory.** Tailwind v4 + `@tailwindcss/postcss` does **not** consume `tailwind.config.{ts,js}`. Color utilities like `bg-background`, `bg-card`, `bg-muted`, `bg-primary`, `border-border`, `ring-ring`, `text-foreground`, `text-muted-foreground` are silently absent in compiled CSS unless declared via:
   ```css
   @theme inline {
     --color-background: hsl(var(--background));
     --color-card: hsl(var(--card));
     /* ...one entry per shadcn token... */
   }
   ```
   This is THE biggest gotcha and was the root cause of an entire session's worth of "the design looks broken" feedback. Verification probe: `curl http://127.0.0.1:3000/_next/static/css/app/layout.css | grep -c '\.bg-card'` should return `>0`. A green build does **not** mean the design system is wired — only the CSS-utility audit does.
2. **Animations and keyframes belong inside `@theme`.** `--animate-grove-pulse: grove-pulse 1s ...` and the `@keyframes grove-pulse { ... }` block both go inside the `@theme` block, not as siblings. The JS-config `theme.extend.animation` route is dead in v4.
3. **Radix animation classes need `tw-animate-css`.** Without `@import "tw-animate-css";` in `globals.css`, classes like `animate-in fade-in-0 zoom-in-95 slide-in-from-top-2` (used by Tooltip / Sheet / Dropdown / Dialog) compile to nothing and the corresponding components appear without animation.
4. **Tailwind v4 reverted v3's `currentColor` border default.** A bare `border` utility uses `currentColor` instead of the theme border. Reset explicitly:
   ```css
   @layer base {
     *, ::after, ::before, ::backdrop, ::file-selector-button {
       border-color: hsl(var(--border));
     }
   }
   ```
   Without this, every `border` looks like body text color, and `border-border` only works where it's the explicit utility.
5. **`tailwind.config.ts` should not exist in this repo.** PostCSS plugin ignores it; its presence misleads the next reader. If you add one back, you're working against the grain. Theme, fonts, keyframes, content paths — all of it goes in `globals.css` (`@theme`, `@source` in v4).
6. **`@source` is automatic in v4 for files imported transitively, but explicit for non-imported assets.** Currently we don't need it because every TSX file lands in the import graph; if you ever colocate a CSS file or use a class only emitted from a string template, add `@source "./components/foo.tsx"` to keep it scanned.

## shadcn/ui patterns

1. **Look in `components/ui/` first.** Available primitives: `Button`, `Badge`, `Card`, `Separator`, `ScrollArea`, `Tabs`, `Sheet`, `Skeleton`, `Tooltip`, `Popover`, `DropdownMenu` (menus — Agent/Model pickers, overflow; via `@radix-ui/react-dropdown-menu`), `Resizable` (split panes, via `react-resizable-panels`). If a primitive exists, compose it; never hand-roll the same chrome.
2. **Pull new primitives via the CLI**: `npx shadcn@latest add scroll-area tooltip` (etc.). The CLI uses `components.json` for path aliases and writes canonical-shadcn output. Don't paste primitives in by hand — drift from canonical breaks future `shadcn add --overwrite` refreshes.
3. **`asChild` is the canonical pill-as-link pattern.** Use it for nav links so a single `<a>` carries pill geometry, focus ring, and SPA routing simultaneously:
   ```tsx
   <Button asChild variant="ghost" size="sm">
     <Link href="/" aria-label="Back to all workspaces">
       <ArrowLeft />
       <span>All workspaces</span>
     </Link>
   </Button>
   ```
   Never wrap a `<Link>` inside a `<button>`; never wrap a `<button>` inside an `<a>`. The Slot primitive solves both.
4. **All Button variants and sizes flow through `components/ui/button.tsx` (CVA).** New visual treatments add a CVA variant — they don't fork into a sibling component. Sizes: `xs`/`icon-xs` (h-7, dense chrome) · `sm`/`icon-sm` (h-8/h-9) · `default` (h-10) · `lg`. **SVG sizing lives per-size, not in the base** (`xs`/`icon-xs` → `size-3.5`, the rest → `size-4`) — a 16px glyph swamps a 28px control, so the compact toolbar controls only read correctly when the icon shrinks with the button.
5. **`<Badge>` is the right base for any pill** (status, identity, count). Compose with `className` / inline `style` for color tokens; do NOT introduce a sibling pill primitive.
6. **`<ScrollArea>` everywhere we'd otherwise reach for `overflow-auto`.** Cross-browser-consistent thumb, theme-aware track. Used in `CommitList` and `PeekSnapshot`. The native scrollbar otherwise ranges from invisible (Chrome on macOS) to chunky-and-distracting (Firefox), and theme switches don't propagate.

## Design language (visual contract)

This section is the canonical visual contract for the webapp. Update it in the same commit as any change that affects look or feel.

### Theme (the space-black redesign, #98-followup)

Two cohesive themes, defined ONLY as the neutral ramp in `globals.css` (`:root` light, `.dark`). **Dark = "space black":** a deep, cool near-black canvas (hue ~224, very low chroma) that replaced the old warm-olive `hsl(60 4% 17%)` monotone (which read as dead grey). **Light = a calm low-glare slate** (hue ~220, soft off-white canvas so white `card` panels lift). The whole neutral ramp is ONE hue family per theme with **wide lightness steps** so elevation reads without borrowing chroma. The **semantic palettes (`--status-*` / `--agent-*` / `--ref-*`) are unchanged** — still mirrored from Python and drift-synced; only neutrals + `--primary` (deepened in light for AA) moved. When you touch theme, touch the neutral ramp, never the semantic hexes here.

### Surfaces (elevation tiers)

A deliberate elevation LADDER — climbing in lightness so depth is legible without chroma. Chrome (header · rail · status bar) shares ONE tone so the persistent frame reads as a single surface around the content canvas.

| Token | Use | Class |
|---|---|---|
| Base canvas | Body, page background, deepest terminal well | `bg-background` |
| Chrome | Header · left rail · status bar (the persistent frame) | `bg-sidebar` (+ `border-sidebar-border`) |
| Panel | Cards, primary surfaces | `bg-card` |
| Overlay | Tooltips, dropdowns, dialogs | `bg-popover` |
| Raised | Composer hero, raised wells above a card | `bg-elevated` |
| Subtle well | Card footer strips | `bg-muted/40` |
| Active fill | Pressed scope/filter chip, hover | `bg-accent` / `bg-muted/60` |

Borders are `border-border` on content and `border-sidebar-border` on chrome, unless an indicator is meaningful (e.g. `border-l-2` in a tier accent var for an attention card / active commit row).

The detail page stacks three of these into an explicit elevation ladder (#90): `bg-background` canvas → the lifted `bg-card` transcript panel (`detail-panel`, `rounded-lg border shadow-sm`, gutter `m-3/lg:m-4`) → message rows; the terminal pane sits on a *deeper* well (`bg-background`, #92) so it reads as distinct from the transcript card.

**Quiet-chrome discipline (the redesign's core rule, tightened in #96).** Surfaces are neutral graphite; **saturated hue appears ONLY to carry state** (the status / agent / ref tokens below — unchanged, still TUI-drift-synced), and only as a **small mark** — a glyph, a `Dot`, a thin `border-l-2` accent bar — **never a large fill or a full-card border/glow** (the old gold-bordered WAITING card was the loudest noise on the wall). Terracotta `--primary` is reserved for the **composer's create/send CTA** + the brand mark + the `you` speaker label, nothing else — scarcity is what makes the send button read as the one primary action. When something looks flat, the fix is structure (a border, a well, a section label), not color.

### Color language (semantic tokens, not hex)

Defined once in `globals.css`, mirrored at component layer via `[var(--token)]` arbitrary values.

| Token | Hue | Use | Sparingly? |
|---|---|---|---|
| `--primary` | terracotta | Brand (the Grove logo mark) + the composer's create/send CTA + the `you` transcript speaker label (`RoleLabel` — the TUI's human-prompt clay). | Yes — exactly those three; never card chrome, never a second CTA. |
| `--ref-branch` | teal | Current branch identifier (mono text + outline borders). | Wherever a branch name appears. |
| `--ref-info` | blue | Agent identifier. | Wherever an agent name appears. |
| `--ref-add` | green | Diff additions, "ahead" stat polarity. | Wherever a positive count is meaningful. |
| `--ref-remove` | red | Diff removals, "behind" stat polarity. | Wherever a negative count is meaningful. |
| `--status-active`, `--status-running` | lime / olive | Lifecycle: ACTIVE, RUNNING. | Status badge + accent stripe + status-bar dot only. |
| `--status-idle` | blue (light) / pale-blue (dark) | Lifecycle: IDLE. | Same. |
| `--status-offline`, `--status-paused` | neutral gray | Lifecycle: OFFLINE / PAUSED. | Same. |
| `--status-orphaned` | amber | Lifecycle: ORPHANED. | Same. |
| `--status-error` | red | Lifecycle: ERROR. | Same. Also the "daemon unreachable" indicator. |

The status palette is **mirrored** from `grove/core/contracts/status_palette.py` — the Python source is canonical. The drift test in `tests/unit/status-tokens.test.ts` reads the Python file at test time and asserts the JS constants match. **If you change a status hex, change it in Python.**

### Typography

Three families, all self-hosted via next/font (no CDN, no layout shift) and declared in ONE place — `app/fonts.ts` — then mapped to Tailwind tokens in the `globals.css` `@theme`: **Geist Sans** (`--font-sans`, UI chrome), **Geist Mono** (`--font-mono`, code + git identifiers), and the terminal **JetBrains Mono Nerd Font** (`--font-terminal` → `--font-jetbrains-nerd`, #92). Geist's `.variable`s ride `<html>` in `app/layout.tsx`; the Nerd Font's `.variable` is dropped ONLY on the terminal subtree (`terminal-pane` / `peek-snapshot`), never `<html>` — its full (un-subset) powerline/private-use glyph ranges are the point for agent TUIs but must not bleed into app chrome. Body carries `letter-spacing: 0.01em`.

A **compact, dense type scale** — the redesign's defining move (quiet IDE feel, max info per row):

| Tier | Class | Use |
|---|---|---|
| Title | `text-base` (16px) `font-semibold` | Page + card titles, prominent stat values. |
| Body | `text-sm` (14px) | Body copy, descriptions, transcript prose. |
| Dense row | `text-[13px]` | Sidebar entries, metric one-liners, AND **all code** (inline + fenced + tool args, forced `font-mono text-[13px]`). |
| Metadata | `text-xs` (12px) `text-muted-foreground` | Relative times, byline copy, secondary info. |
| Section label | `text-[11px] font-semibold uppercase tracking-[0.08em] text-muted-foreground` | Panel section headers ("SUMMARY", "AGENT"). The terminal-feel cue. |
| Micro label | `text-[10px] uppercase tracking-wider` | Stat units (AHEAD / BEHIND / DIRTY under numbers). |

`font-mono` for **every** git/code identifier: branches, base branches, agent names, SHAs, commit subjects (no — bodies stay sans), file paths. The terminal `<pre>` uses `font-terminal` (~12–13px) instead, so the Nerd Font glyphs resolve.

### Spacing

4 px grid. Allowed gap values: `{1, 1.5, 2, 3, 4, 5, 6}`. Allowed padding values: `{2, 3, 4, 6}`. Card padding `p-4` standard, `p-3` compact, `p-6` spacious.

**Layout (full-bleed shell, #98-followup).** The chrome is full-bleed: the left rail (`w-64`) hugs the viewport's left edge and runs full height; the header (`h-12`) and status bar (`h-7`) span the full width — all three on `bg-sidebar`. The CONTENT re-centers inside `<main>` at `max-w-[100rem]` (`mx-auto`), so an ultrawide reads "rail flush-left · wide centered canvas", never "everything stranded in a narrow middle column". The viewport-fill magic number is `4.75rem` (h-12 header + h-7 status bar) — used by the (shell) rail height and the `/w/[id]` `<main>`; change it in both if a chrome height moves.

### Density (VS Code influence)

Heights tightened in the #98-followup compact pass (everything dropped one notch for an information-dense, IDE-like feel):

| Element | Height | Why |
|---|---|---|
| `xs` / `icon-xs` button | `h-7` (28 px) | Dense toolbar chrome (sidebar, context bar). Glyph is `size-3.5` not `size-4` (see Button note). |
| Status bar | `h-7` (28 px) | Persistent chrome, max info per row. |
| `sm` / Tab triggers | `h-8` (32 px) | Compact tabs, file-tab feel; `icon-sm` is also `h-8`. |
| Default button | `h-9 px-4` (36 px) | Standard interactive control (was h-10). |
| `lg` button | `h-10` (40 px) | The rare emphasis case. |
| Header | `h-12` (48 px) | Brand + actions, deliberately tight (was h-14). |

WCAG-mobile recommends 44 px tap targets; we hold the line at 32–36 inside the chrome (acceptable for dense desktop chrome) and use the larger sizes for primary actions. When in doubt, prefer the larger size.

### Transitions

200 ms ease-out across the board. **Never** `transition-all` — animate only `transform`, `box-shadow`, `colors`, `border-color` selectively to avoid color flicker on text. Card hover = `-translate-y-[1px] + shadow-md + border-t thickening`. Reserved animations: `animate-grove-pulse` for ACTIVE / RUNNING status badges only (4 Hz step pulse — terminal-cursor-like).

### Focus + a11y

- Every interactive element gets `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background`. The Button primitive bakes this in; if you build something that isn't a Button, copy the contract.
- All icon-only buttons need `aria-label`. All decorative icons get `aria-hidden`.
- Polling indicators use `aria-live="polite"`.
- Status colors are an enhancement — the badge **also** carries text labels and glyph characters so colorblind / monochrome users still get the signal.
- Animations honor `motion-reduce:animate-none`.

### App shell (the VS Code analogy)

Persistent regions:

1. **Header** (`components/layout/header.tsx`) — sticky top, **h-12, full-bleed on the shared chrome tone** (`bg-sidebar/85 backdrop-blur-md`, `border-sidebar-border`), brand block on the left (the **Grove logo** `img` from `public/grove-logo.png` + wordmark), actions group on the right (GitHub link + theme toggle). The inner row is **full-width** (no max-width) so the brand sits at the true viewport edge, aligned above the flush-left rail. **No create button here** — the composer is the single create affordance (#96); a second header CTA would split attention (the old two-orange-CTAs problem). Optional `onOpenSidebar` prop renders a `lg:hidden` hamburger (the mobile drawer trigger) — omitted by routes with no sidebar (detail, login), so the header stays verbatim for them.
2. **Left rail** (`components/layout/workspace-sidebar.tsx`, #81; collapsible #88; **nav/scope-only since #96**; **flush-left full-bleed chrome since #98-followup**) — the `app/(shell)/layout.tsx` route group adds a persistent left `WorkspaceSidebar` on `bg-sidebar` that hugs the viewport's left edge (the shell no longer centers it inside a `max-w` wrapper). It NO LONGER mirrors the card grid (workspaces render once, in the main grid). Rail order top→bottom: **search input** (an inset control on `bg-card` so it reads against the chrome) **→ repo SCOPE switcher** (an "All workspaces" row + one row per repo with a count; clicking sets `scopeRepo` to narrow the grid — AND the composer's create-target follows it, see below) **→ agent-state filter chips + attention toggle → daemon/user footer** (`user@host` monogram only — version lives ONLY in the status bar, de-duplicated). All controls write the one client-state store, which the grid reads; there is **no route nav** and **no per-workspace rows**. **Collapsible on demand:** the store (`sidebarCollapsed`) is the single source of truth, toggled by the header button (`sidebar-collapse-toggle`) or `[` (ignored while a field is focused; the shortcut lives in the (shell) layout). The collapse animates the rail **wrapper** `w-64→w-0` while the inner `<aside>` keeps a stable `w-64` so content never reflows mid-animation. SSR mount-guard: server + first paint render expanded, then the store's `hydrated` flag flips the stored value on mount — the width transition disguises the one-frame correction. Desktop = sticky rail; mobile = a left `Sheet` drawer from the header hamburger (collapse toggle is `lg`-only).
3. **Main content — composer-first (`app/(shell)/page.tsx`, #96).** `/` leads with the **always-present composer** (`components/composer/Composer`), the hero that holds the visual center (Devin-style) under a faint brand watermark; below it the repo-grouped **`WorkspaceGrid`** renders every workspace ONCE (one `project-section` per repo, attention-first within). It renders inside the (shell) `<main>` (centers at `max-w-screen-2xl`, flexes as the rail collapses); it no longer renders its own `<Header>`/`<main>`. The **workspace detail page (`/w/[id]`) lives OUTSIDE the (shell) group**: it keeps its full-bleed, contained app-shell (`flex flex-col lg:h-[calc(100dvh-5.25rem)] lg:min-h-0`, the magic number = h-14 header + h-7 status bar, no max-width, no sidebar) and renders its own `<Header>`. It is an IDE editor, not a scrolling document — but **never `overflow-hidden` on this `<main>`** (it hangs Playwright actionability — see the scroll-trap lesson). Bottom padding for the status bar comes from the root layout wrapper's `pb-7`.
4. **Status bar** (`components/layout/status-bar.tsx`) — fixed bottom, h-7, full-width across every route (root layout), on the shared chrome tone (`bg-sidebar/90`, `border-sidebar-border`) so header · rail · status bar read as one frame. Daemon health (colored dot + "online"/"unreachable") + workspace count + "web dashboard" + GitHub link. Information density over chrome. (Was "read-only dashboard" before the #56 action layer shipped; the label dropped "read-only" once create + lifecycle landed.) The **newer-release nudge (#80)** is an amber (`--status-orphaned`) link to `…/releases/latest`, gated on `whoami.update_available` (testid `update-available`). The daemon ran the **single** GitHub check and put `latest_version`/`update_available` on `WhoamiView` — the browser only reads whoami via `useDaemonWhoami`, it **never polls GitHub itself** (engine owns the check; see [core](../src/grove/core/CLAUDE.md)). Amber mirrors the TUI chip's "work to pull" hue.

This shape is deliberate VS Code mimicry. The TUI uses a similar header-content-statusbar layout (see `docs/design-system.md`); web and TUI feel like siblings, not strangers. Header and status bar are **shared verbatim** across every route — when a per-page design (e.g. the detail revamp, the (shell) sidebar) ships its own chrome, it reuses these rather than forking page-local twins; design consistency is one header/footer, not three that look alike.

### Composer-first surface & card hierarchy (#96)

The home surface is a calm, Devin-style composer-first layout. Two pieces:

- **The composer (`components/composer/`, the hero).** An always-present `rounded-xl` card: the textarea IS the create surface (type → Enter creates; title auto-derives from the first line, the full text rides as `initial_prompt`). Toolbar: an `Agent ▾` pill, a `Model ▾` pill, a quiet **fullscreen** toggle, and the single high-contrast **send** button (the only `--primary` mark in the view). A borderless context-chip row (repo · base · branch mode) sits below, with branch source + skip-init behind an `Advanced ▾` disclosure (collapsed by default). Decomposed: `composer.tsx` (container, wires store + hooks) over presentational pickers/chips that share `pill.tsx`.
  - **Model menus are CONFIG, not code (#98).** The values live in `lib/grove/models.json` (policy, user-editable, OUT of the code); `models.ts` is only the typed loader (mechanism). The `Model ▾` pill shows for ANY kind with declared models — `claude_code`, `codex`, AND `mewbo` (mewbo forwards the id to its REST session-create, see [agents](../src/grove/core/agents/CLAUDE.md)); a kind absent from the JSON (`generic`) gets no pill. The "Custom model id…" row is always the escape hatch, so the JSON is a convenience list, never a closed set. Still rides the wire as `CreateWorkspaceRequest.model`.
  - **Expand-on-focus + fullscreen markdown (#98).** The inline textarea grows + the card lifts (200ms tween) while focused or non-empty. A `Maximize` toggle opens a near-viewport `Dialog` with a `Write | Preview` split — Preview renders the prompt as Markdown via the **lazy** `Response` (streamdown is `next/dynamic`-imported so the home bundle pays nothing until preview opens). Inline + fullscreen share ONE store-backed draft; fullscreen submits on ⌘/Ctrl+Enter (Enter = newline for long Markdown), inline keeps Enter = submit.
  - **Repo-follows-scope (#98).** Selecting a repo in the left rail (`scopeRepo`) retargets the create (`composer.repoRoot`), so "what you're viewing" and "what you'll create in" agree; a manual repo-chip pick afterward still wins until the scope changes again.
- **The card (`components/workspace/card.tsx`) — THREE regions, metrics demoted (restructured #98-followup).** Wider track (`minmax(22rem,1fr)`) and `p-0` Card with three explicit regions: **HEADER** (`p-4 pb-3`) — `AgentStateMark` glyph + title link (`line-clamp-2`, top-aligned pill so a two-line title never shoves it) + ONE right-aligned status pill, then a quiet branch sub-row (mono teal `--ref-branch`); **BODY** (`px-4`) — "happening now" (`line-clamp-2`, so a long task line reads instead of single-truncating; error detail wins while erroring); **FOOTER** — a muted well (`bg-muted/40 border-t`) with the metrics one-liner + WORKING-gated Live toggle on row one and a `MetaRow` of `StatTrio` · last commit (`parseCommitSubject` → muted tag + clean subject, **no emoji**) · placement on row two. No repo badge (repo is the `project-section` header), no agent brand ring. Attention (waiting/blocked/error) = a thin left `border-l-2` accent bar in the tier var, never a full-card glow. Cards render ONCE, grouped by repo in `WorkspaceGrid` (`project-section` per repo, attention-first within).

The unified glyph/color system is `AgentStateMark` (`components/shared/state-mark.tsx`): `▶` working (lime, pulse) · `◑` waiting · `⚠` blocked · `✗` error · `○` idle — one home, reused on card, status pill, and detail. Three type roles hold throughout: **title** (foreground, medium) · **prompt/body** (foreground, normal, truncated) · **meta** (muted, small).

## Testing pyramid

```
tests/unit/         — Vitest, pure logic (status palette, ANSI strip, RepoFacet, AgentLiveStatus, GroveClient)
tests/component/    — Vitest + jsdom + RTL, single-component contracts
tests/e2e/          — Playwright, mobile-chrome + desktop-chrome projects
tests/e2e/_fake-daemon.ts — Hermetic Express server used by Playwright
tests/e2e/_live-smoke.ts  — Manual `npx tsx` against a real daemon for screenshot capture
```

- **Vitest config requires** `esbuild: { jsx: "automatic", jsxImportSource: "react" }` — without it the JSX runtime path errors on every component test. **`vitest.setup.ts` polyfills `matchMedia`** because next-themes calls it on mount and jsdom doesn't provide it, **and `ResizeObserver`** because radix ScrollArea constructs one when its scrollbar/thumb mounts — which happens lazily on the first `userEvent` hover/click inside a ScrollArea, so the crash only appears in interaction tests, not render-only ones.
- **`next/font` is a build-time transform Vitest can't run** (`next/font/local` is a directory import that throws under jsdom/ESM). So `@/app/fonts` is **aliased to a stub** (`tests/_helpers/fonts-stub.ts`) via a `vitest.config.ts` `alias` entry that must come *before* the generic `@` alias (Vite matches in order). The stub returns inert `{ variable: "" }` font objects; any component that imports a font (terminal panes, the layout) needs this or its test errors at import.
- **jsdom serializes hex colors to `rgb()`.** Tests that assert on color use the `expectColor()` helper (in `tests/_helpers/`) which converts hex → rgb before comparing. Don't compare raw style strings.
- **Test seam = the component's testid + ARIA + visible text.** Tests pin `data-testid="status-badge"`, `data-testid="stat-trio"`, `data-testid="commit-list"`, `data-testid="workspace-card"`, `data-testid="identity-panel" / "summary-panel" / "agent-panel"`. New visual treatments must preserve those testids and the first-child structure that tests depend on (e.g. `StatusBadge`'s firstChild is the pulse-eligible glyph). Update both in the same commit if the contract truly changed.
- **Playwright uses port 3101**, NOT 3100. Some machines have a root-owned next-server bound to 3100 from another project; we side-step it. The fake daemon binds 8421.
- **`E2E_LIVE_DAEMON=1 npm run test:e2e`** runs Playwright against a real daemon instead of the fake (only useful when iterating on something the fake doesn't fully model — keep it the exception). The auth setup project polls for up to 60 s in live mode so you can `grove auth approve` the printed code from another terminal.
- **Playwright is hermetic since #32 — auth included.** A `setup` project (`tests/e2e/auth.setup.ts`) pairs once through the BFF (`POST /api/auth/pair` → poll `GET /api/auth/pair/{id}`), saves the resulting HttpOnly `grove_session` cookie as storageState (`tests/e2e/.auth/`, gitignored), and both browser projects depend on it. The fake daemon auto-approves (first poll consumes, deterministic `FAKE_DAEMON_TOKEN`) and **bearer-gates every data endpoint**, so the suite pins the full cookie → BFF → bearer chain, not just rendering. The webServer env sets `XDG_CONFIG_HOME` to `test-results/xdg-config` so the BFF's cookie store never touches the real `~/.config/grove/webapp-sessions.json`. Expected baseline: all green locally with zero running daemons (25 passed as of 2026-06-11).

## Production hosting (systemd-user)

For "leave it running on a host" deployments — typically the same machine that hosts the daemon — install the user-scope systemd unit shipped under [`packaging/systemd/`](../packaging/systemd):

```bash
make webapp-build           # one-shot: npm ci + npm run build (required before enabling)
WITH_WEBAPP=1 make systemd  # writes both unit files
WITH_WEBAPP=1 make systemd-enable  # enable + start now
```

Webapp install is **opt-in** (default `WITH_WEBAPP=` is empty). The webapp service `Wants=` (not `Requires=`) the daemon — daemon hiccups don't tear the webapp down, the in-app status bar surfaces the unreachable state instead. The unit binds `0.0.0.0:3000` so the dashboard is reachable from a phone on the same Wi-Fi without extra port forwarding.

After webapp source changes: `make webapp-build && systemctl --user restart grove-webapp`. The service does NOT auto-rebuild — production mode reads `.next/` build output and runs cold-fast, dev mode's hot-reload would be wrong here.

## Local dev / tmux orchestration

The standard layout is a tmux session named `grove-webapp-dev` with two windows:

```
window 0: daemon  → uv run grove daemon serve --port 7421
window 1: webapp  → npm run dev   (binds 0.0.0.0:3000, LAN-reachable)
```

LAN URL is announced in the dev log (`http://192.168.x.x:3000`). Phone testing: open the LAN URL on your phone while connected to the same Wi-Fi.

**When `next dev` errors with `Cannot find module './<chunk>.js'` (e.g. `611.js`):** the `.next` cache is stale. Fix is `rm -rf .next && npm run dev` (NOT `--clear-cache`, NOT `npm install`). Same shape applies to a `_not-found` collection error during `next build` — clean cache, rebuild. **Do not** `rm -rf .next` while a `next dev` is running; it corrupts in-flight pack files and leaves the dev server in a degraded state. Stop dev → clear → start dev.

## Repo-level gotchas (specific to webapp's location in the monorepo)

- **`/webapp/lib/` was previously caught by the repo-root `.gitignore` rule for Python `lib/`**. Resolved by adding `!/webapp/lib` and `!/webapp/lib/**` negations to repo `.gitignore`. If a new top-level dir under `webapp/` shares a name with a Python directory we ignore (e.g. `dist/`, `build/`), apply the same negation pattern.
- **The webapp does NOT depend on the Python venv**. It has its own `node_modules` and `package.json`. CI matrices that build webapp can skip the Python toolchain.
- **When your branch changes a wire shape, `codegen` / `codegen:check` against the *running* daemon (7421) is wrong — it serves the main checkout's OLD openapi.** The daemon `~/.local/bin/grove` resolves to the last-installed checkout, not your worktree, so a new/changed field never appears and `codegen:check` "passes" stale (or diffs forever). Boot a throwaway daemon from the worktree on a spare port and point codegen at it: `uv run grove daemon serve --port 7422 &` then `GROVE_DAEMON_URL=http://127.0.0.1:7422 npm run codegen` (and `codegen:check`). Kill it after. The engine commit + the regenerated `types.gen.ts` land together; on deploy the real daemon must be restarted on the new code (the #96 `CreateWorkspaceRequest.model` field rode in this way).

## Session lessons (non-trivial)

Things that took real time to figure out. Capture *why* and the *invariant*, not line numbers — when code moves, update the bullet, don't delete it.

- **The #98-followup overhaul = a frozen-token FOUNDATION + a fleet over disjoint surfaces.** The cohesive "feel" (the space-black/light neutral ramp + elevation tokens in `globals.css`, the compact Button scale, the full-bleed shell) was authored SOLO first and frozen as the contract; surface agents (composer · card · detail · chrome) then only restyled internals against those tokens, conflict-free (the stable-public-surface pattern from root CLAUDE.md). Three non-obvious invariants the overhaul re-confirmed: (1) **only the NEUTRAL ramp + `--primary` are free to retheme** — `--status-*`/`--agent-*`/`--ref-*` are mirrored from Python and drift-tested (`status-tokens`/`agent-state-tokens`), so a theme change touches neutrals only or the drift tests fail; (2) **a new chrome token (`bg-sidebar`, `bg-elevated`) is invisible until added to BOTH the `@theme` bridge AND the `:root`/`.dark` var blocks** — same Tailwind-v4 trap as below, re-verified by the `grep -o bg-sidebar .next/**/*.css` count after build; (3) the viewport-fill magic number (`h-12` header + `h-7` status = `4.75rem`) is duplicated in the (shell) rail height and `/w/[id]` `<main>` — move a chrome height, change both.
- **streamdown stays lazy on EVERY surface that renders it, including the composer (#98).** The composer's fullscreen Markdown Preview imports `Response` via `next/dynamic({ ssr:false })`, not a static import — a static import would pull streamdown (the chat panel's whole bundle cost) into the home `/` route bundle, which must stay lean. Verified by the build report (`/` First Load stayed ~194 kB). Same discipline as `ai-elements/response` being its own module behind the chat panel's `next/dynamic`. Any new place that wants Markdown rendering: lazy-load it.
- **Per-create model menus are CONFIG (`lib/grove/models.json`), not a code literal (#98).** `components/composer/models.ts` is only the typed loader; the values live in the JSON (user-editable, no rebuild, no hard-coding). The picker shows for any kind with declared models (now incl. `mewbo`, whose model is forwarded engine-side at REST session-create — see [agents](../src/grove/core/agents/CLAUDE.md)); the custom-id row is always the escape hatch. JSON import needs `resolveJsonModule` (Next default on); the `$comment` doc key is skipped by the loader (it filters to array values).
- **Tailwind v4 silently no-ops every shadcn color utility without an `@theme` block.** Compiled CSS for `bg-card`, `bg-primary`, `text-foreground`, `border-border`, `ring-ring`, `bg-muted`, `bg-accent`, etc. is empty. Body still has a background only because of the explicit `@layer base { body { background-color: hsl(var(--background)); } }` rule. The visible result is a layout that "looks fine but feels off" — surfaces blur into one another, no card boundaries, no muted strips, no focus rings, no hover affordances. The `tailwind.config.ts` JS theme is **dead** in v4 — moving theme tokens, fonts, and keyframes into `@theme` in `globals.css` is the only path. Verification probe: `curl /_next/static/css/app/layout.css | grep -c '\.bg-card'` returns `>0`. A clean build is not enough.
- **`tailwindcss-animate` (v3 plugin) is replaced by `tw-animate-css` in v4.** Without `@import "tw-animate-css";` in `globals.css`, radix component animations (Tooltip enter, Sheet slide, Dialog fade, Dropdown zoom) all silently no-op. The components still mount and dismiss correctly — they just teleport instead of animating, which makes the app feel cheap without any clear cause.
- **`animate-grove-pulse` (custom keyframe) lived in `tailwind.config.ts` for months and never compiled.** Same root cause as the `@theme` issue. Custom keyframes for v4 go in `@theme` via `--animate-<name>: <name> ...; @keyframes <name> { ... }`. No JS config layer participates in the build.
- **`shadcn add` writes to `components/ui/` based on `components.json`'s alias config.** Verify the file exists and has `aliases.{components,ui,utils}` before relying on the CLI. Without it, `shadcn add` errors with a misleading "couldn't read config" message; the fix is to keep `components.json` checked in even though it looks like CLI scaffolding.
- **Compose shadcn primitives — never hand-roll a sibling pill / divider / scrollbar.** Bespoke chrome was the cause of "no design language" feedback. The signal that it's time to delete custom code: the new file replicates the geometry of an existing `Button` / `Badge` / `Separator` / `ScrollArea` with no semantic difference. Use the canonical shadcn primitive with `className` overrides; reach for a new primitive only when truly novel (and even then, prefer adding a CVA variant to an existing one).
- **Use `asChild` to make a `<Link>` *be* a Button**, not a Button *containing* a Link. Slot replaces the wrapper element with the child while merging className + props + ref. The result: pill geometry + focus ring + SPA routing in a single anchor tag. Common mistake: nesting `<Link>` inside `<button>` (HTML invalid — interactive content nested in interactive content) or wrapping `<Button>` in `<Link>` (focus ring wraps the wrong element).
- **`next-themes` calls `window.matchMedia` on mount.** Vitest with jsdom doesn't ship the API. Polyfill in `vitest.setup.ts`:
  ```ts
  Object.defineProperty(window, "matchMedia", {
    value: (q: string) => ({
      matches: false, media: q, onchange: null,
      addListener: () => {}, removeListener: () => {},
      addEventListener: () => {}, removeEventListener: () => {},
      dispatchEvent: () => false,
    }),
  });
  ```
  Without it, every component that imports something that imports `next-themes` (transitively, almost everything) errors during render.
- **jsdom serializes `style={{ color: "#abc"" }}` to `rgb(...)`** at the DOM layer. RTL assertions like `expect(el).toHaveStyle({ color: "#aabbcc" })` fail because the DOM serialized to `rgb(170, 187, 204)`. Helper `expectColor()` in `tests/_helpers/` converts hex → rgb before comparing. Don't compare raw style strings.
- **If you ever need fan-out fetches again, `useQueries` is the shape** — an array of query objects in stable order, paired with `useMemo` for the id list so the keys don't churn. A loop of `useQuery` violates the rules-of-hooks (hook count changes with the workspace list). The home grid USED this for per-card peeks and no longer does (see the home-grid-on-stream lesson); the detail page never fans out.
- **`peek` polls at 2 s, `commits` at 15 s, `workspaces` at 5 s; the activity poll fallback is 4 s.** Cadences are tuned to how fast each resource changes: agent panes update second-by-second, commits arrive minutes apart, workspace lifecycle changes are user-driven. The list surfaces don't poll at all on the happy path — they ride the SSE stream.
- **Don't hand-edit `lib/grove/types.gen.ts`.** It's regenerated by `npm run codegen` from the daemon's `/openapi.json`. CI runs `npm run codegen:check` and fails if the file drifts from the live OpenAPI. To add a field, change the daemon's Pydantic view in `grove/core/contracts/views.py`, run codegen, commit both files in the same PR. Engine first; webapp follows.
- **`peek.recent_commits` ≠ `commits()`.** The peek's recent_commits is a tight 3-row rail-shaped summary (no fork-point filter, capped). The detail page's commit list uses the `/workspaces/{id}/commits` endpoint, which is fork-point-filtered (`git log base..branch`) and uncapped. Don't conflate them — both exist on purpose and have different consumers.
- **Strip ANSI escapes in `peek-snapshot.tsx` via `stripAnsi` (in `lib/grove/ansi.ts`)**, don't render them as text. The daemon emits `tmux capture-pane -e` output with SGR codes intact; the TUI renders those via Rich, but the webapp's monospace `<pre>` would display them as literal `\x1b[31m` text. Color is not load-bearing for the dashboard — structure is.
- **Auto-scroll `<pre>` to bottom only when the user is already within 40 px of the bottom.** Otherwise we fight a deliberate scroll-up. Same pattern used in chat/log UIs everywhere; codified in `components/workspace/peek-snapshot.tsx`.
- **`<ScrollArea>` is a wrapper around `overflow-hidden` + a viewport** — its child's scroll happens on the viewport, not the root. Don't put `overflow-auto` on a child you've already wrapped in `<ScrollArea>`; you'll end up with two scrollbars.
- **The Next.js `_not-found` static collection error during `next build` is a stale `.next` symptom**, same family as `Cannot find module './611.js'` during dev. Fix: clean `.next`, rebuild. Do **not** clean `.next` while `next dev` is running (corrupts in-flight pack files; the dev server enters a permanent error loop until restart).
- **Port 3100 is contested on dev machines** — the workspace picked up a root-owned `next-server` from another project that we couldn't kill. Playwright uses 3101 instead. If 3101 ever clashes, increment further; do **not** add complex port-discovery logic — the fixed port is the contract that makes the fake-daemon webserver pair deterministic.
- **`.gitignore` negation**: the repo-root rule `lib/` (Python) catches `webapp/lib/`. Solved by `!/webapp/lib` + `!/webapp/lib/**` in root `.gitignore`. Same approach if a new ignored Python directory name (`build/`, `dist/`) shows up under `webapp/` later.
- **Dev mode bottom-left "N" / "Issues" badge** is the Next.js dev indicator. Production builds don't render it. Stop chasing it in screenshots — it's not part of the design.
- **VS Code-style status bar is a *single* persistent footer**, not per-page. Lives in `app/layout.tsx` so it appears regardless of route. Subscribes to the workspace list directly via `useWorkspaces()` — the polling cadence is shared with the rest of the app via TanStack Query's cache, so it costs nothing extra. Padding-bottom on the wrapper (`pb-7`) reserves the strip's footprint so content doesn't disappear underneath.
- **Color contrast is the failure mode of "color the label AND the surface".** Original status pill colored both the badge text and the badge background with the same status hue, which produced AA-borderline contrast in light mode (lime green text on near-white tinted surface). Decoupling glyph color from text color (text = `text-foreground`, glyph = status hue) fixes contrast while keeping the status cue. Apply the same rule any time a "tinted pill" lands in the design.
- **The fix for "the design feels inconsistent" is rarely more design.** It was almost always missing utilities, missing focus rings, hand-rolled chrome that drifted from a primitive that already existed, or a hex token that was never wired to a Tailwind class. Audit is `curl /CSS | grep -c utility-name` first, screenshot diff second, design talk last.
- **`placement: "worktree" | "root"` rides on `WorkspaceStateView` (and its embedded `state` inside `WorkspacePeekView`), surfaced by `PlacementBadge`.** Root workspaces run in the repo root with no isolated worktree; worktree is the default and common case. The badge is silence-by-default: `PlacementBadge` returns `null` for worktree (nothing to flag) and renders a tasteful neutral-outline "root" pill (FolderRoot glyph) only for root. It sits next to `StatusBadge` in both the card header and the detail identity panel, wrapped in a `flex gap-1.5` group. Neutral chrome on purpose: placement is orthogonal to lifecycle status, so it must not borrow a `--status-*` hue. Test seam mirrors `StatusBadge`: `data-testid="placement-badge"` + `data-placement` + the visible "root" label, and returning `null` makes absence assertable via `queryByTestId(...).toBeNull()`. Codegen wrinkle worth remembering: a live daemon was not reachable and `uv run` is broken here, but the schema needs no network. Import the app and dump OpenAPI to a file (`.venv/bin/python -c "...; build_app(cfg=GroveConfig.model_validate({'auth':{'enabled':False}}), store=JsonWorkspaceStore()).openapi()"` — store is `grove.core.store`, factory needs `cfg`/`store` kwargs), then point `openapi-typescript` at the JSON file instead of a URL. Same generated output as the live pipeline, so `codegen:check` stays green.
- **The agent terminal preview owns its scroll viewport via `h-full min-h-[28rem]`, NOT a fixed cap.** First cut of the detail page (`/w/[id]`) used `h-[min(60vh,28rem)]` directly on `PeekSnapshot`'s ScrollArea — the same pattern showed up on `CommitList`'s ScrollArea. Locked at ~448px on every viewport, leaving 400-500px of empty page below the panels on any 1080p+ display. Fix shape, codified now: (1) the page becomes a flex column with `lg:min-h-[calc(100dvh-5.25rem)]` (5.25rem = h-14 header + h-7 status-bar reserved by `pb-7`); (2) the side-by-side row is `lg:flex-1 lg:auto-rows-fr lg:grid-cols-12` so both columns stretch to the remaining viewport; (3) each card inside the row is `flex flex-col`, its CardContent is `flex min-h-0 flex-1 flex-col` (the `min-h-0` is load-bearing — without it, flex children with `overflow:auto` can't shrink below content and the scroll viewport breaks); (4) the leaf scroll components (`PeekSnapshot`, `CommitList`) default to `h-full` with a generous `min-h-[Xrem]` floor for mobile / short viewports. The leaf components do NOT bake in viewport caps — that's policy-at-the-page, not mechanism-at-the-leaf, and it's why one consumer can flex-fill while another (a future modal preview, etc.) can pass a `className` to constrain. Generalizes: any "fill the viewport" pattern in this codebase = flex column on the page + `flex-1 + min-h-0` on the row + `h-full + min-h-floor` on the leaf. The `min-h-0` trap is the part everyone forgets.
- **The Activity Dashboard (`/activity`) streams over SSE through the BFF, with a poll fallback — and adds NO new npm deps.** The epic floated `fancy-ansi` + `@xterm/xterm`; we shipped neither. Adding a dep needs `npm install` (network) and the codebase's own convention is `stripAnsi` + `<pre>` ("color is not load-bearing; structure is"), so the dashboard card is a *glance* tile that links to `/w/[id]` for the live pane (which already renders via `PeekSnapshot`); the dedicated streaming pane wall is #19. (1) **SSE pass-through:** `app/api/grove/[...path]/route.ts` pipes the event-streams (predicate `isEventStreamPath` = `GET /events` OR the focused-pane `GET /workspaces/{id}/pane/stream`, #19) — it pipes `upstream.body` (not `await res.text()`), sets `export const runtime = "nodejs"` + `dynamic = "force-dynamic"`, forwards `req.signal` (a browser disconnect aborts the upstream fetch — no `ResponseAborted` leak) and the `last-event-id` header (replay), and returns `cache-control: no-cache, no-transform` + `x-accel-buffering: no`. The browser uses a **cookie-auth `EventSource`**; the daemon bearer is injected server-side and never reaches the browser. (2) **`useActivityStream` = EventSource primary + `/activity` poll fallback** (`useQuery` `enabled: !connected`, so the happy path is one stream and zero polls). jsdom has no `EventSource`, so the hook guards `typeof EventSource === "undefined"` and falls back to the poll — which is how the component/unit tests exercise it. The fold logic is the pure `applyDashboardEvent` reducer in `lib/grove/activity-stream.ts` (`snapshot` → replace, `session_activity` → patch the one workspace + recompute counts, else no-op); that's the unit-test seam, not the hook. (3) **Agent-state palette is a separate axis from workspace status**, mirrored like `status-tokens`: `lib/grove/agent-state-tokens.ts` hex mirrors `grove.core.contracts.agent_palette.py` (drift-tested in `tests/unit/agent-state-tokens.test.ts`), glyphs/labels mirror `grove/tui/_status.py`, and `globals.css` carries `--agent-*` CSS vars (light + dark) the card reads via `var(--agent-<state>)`. Lens default is `"all"` (mirror the TUI — never open to an empty wall). - **The live preview is ANSI→HTML in a real `<pre>` (`components/terminal/terminal-view.tsx` via `fancy-ansi`), NOT a terminal emulator.** First cut used `@xterm/xterm`; it regressed the rendering three ways and was reverted.
