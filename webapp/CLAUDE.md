# Grove Webapp Engineering Guidelines

> ↑ [root](../CLAUDE.md)

The webapp under `webapp/` is the **mobile-first dashboard** for Grove workspaces — Next.js 15 (App Router) + React 19 + Tailwind v4 + shadcn/ui, talking to the Grove daemon (`grove daemon serve`) through a Backend-for-Frontend route. **Observability-first with a thin action layer:** reads are the bulk of the surface; the only mutations are ones the engine already exposes (create · pause/resume/respawn/kill · message send · question answer), driven as a faithful client of the daemon's wire contract — never new backend logic, never engine semantics re-implemented client-side.

This file composes **on top of** the repo-root [`CLAUDE.md`](../CLAUDE.md). Inherited principles (KISS, DRY, YAGNI, code-as-poem, side-effects-at-edges, tests-pin-contracts, Pydantic at public boundaries) all still apply — this file captures only what is *additional* or *different* for the Next.js stack. Engine + cross-cutting lessons stay upstream.

**Rules**

- Webapp engineering lessons live here; the **webapp visual contract** (color tokens, typography, component specs, do's and don'ts) lives in [`webapp/design-system.md`](design-system.md). Read that file before writing or reviewing any webapp component.
- Anything that crosses the wire (request/response shapes, error envelope, status palette) lives upstream — engine `grove/core/contracts/`, TUI palette `grove.core.contracts.status_palette` — and the webapp consumes via codegen. Don't redefine wire shapes here. Don't redefine status colors here either; mirror the upstream Python source through `lib/grove/status-tokens.ts` (drift-tested).
- A change that affects both the engine wire and this client lives in the engine commit; the webapp commit follows by re-running `npm run codegen`. Same commit if small, separate commits if large — but never invert the order.

## Stack contract (what we use, why, where)

| Layer | Choice | Notes |
|---|---|---|
| Framework | Next.js 15 App Router (React 19) | RSC where it pays, `"use client"` for interactivity. SSG for static pages, dynamic for `/api/*` and `/w/[id]`. |
| Styling | Tailwind v4 via `@tailwindcss/postcss` | Config lives in `app/globals.css` `@theme` block — NOT in a JS config. See `Tailwind v4 traps` below. |
| Component primitives | shadcn/ui via `npx shadcn@latest add <name>` | Compose, don't reinvent. All primitives go to `components/ui/`. |
| Animation utilities | `tw-animate-css` | Required for radix's `animate-in`, `slide-in-from-*`, `zoom-in-*`, `fade-in-*` classes (Tooltip, Sheet, Dropdown). Imported once in `globals.css`. |
| Icons | `lucide-react` | One icon set, never mix. |
| Theme | `next-themes` | `attribute="class"`, `defaultTheme="system"`. Mounting guard required (jsdom: see Testing). |
| Data fetching (server state) | TanStack Query 5 + SSE | The unified `/` grid rides one SSE stream (`useActivityStream`, 4 s poll fallback). Remaining polls, by hook: peek 2 s + commits 15 s (detail page), workspaces 5 s (rail), project sessions 15 s (session rail — SSE-invalidated on top), turns 30 s (detail transcript — SSE-invalidated on top), session catalog 30 s (`/sessions`, a browse-history surface the daemon deliberately keeps off the activity tick), catalog turns NEVER (an archived transcript does not grow under you), provision progress 2 s but ONLY while a workspace is `provisioning` — its consumers are conditionally mounted on that status, so the SSE status flip is what arms and disarms the poll, and a fleet that is not building costs zero requests. **The poll interval on an SSE-backed resource is a BACKSTOP, not the freshness mechanism**; a fingerprint diff on the shared snapshot is. Never fetch in components — go through `lib/grove/hooks.ts`. |
| Client UI state | Zustand 5 (`lib/grove/ui-store.ts`) | The ONE client-state store. Owns ALL cross-component *UI* intent: composer draft, sidebar collapse, the persisted landing view (`landingView`), view scope/filter/search, and the single live-pane focus. SERVER state stays in TanStack Query — the two layers never mix (a TanStack cache mirrors the daemon; the store is local intent the daemon never sees). Persists the durable prefs (`sidebarCollapsed`, `landingView`, `hiddenStates`, `attentionOnly`) via `persist`+`skipHydration`, rehydrated once on mount in `providers.tsx` (SSR/first paint render defaults then flip — `hydrated` gates the persisted value); `query`/`scopeRepo`/the composer draft/`liveId` stay transient. Chosen over context+reducer: selector subscriptions mean a composer keystroke never re-renders the grid, zero provider boilerplate. **No server-derived mirror belongs here** — chrome that needs live session state lives inside the page tree instead (see App shell). |
| Type generation | `openapi-typescript` | `npm run codegen` writes `lib/grove/types.gen.ts` from daemon's `/openapi.json`. CI gate: `npm run codegen:check`. **Never hand-edit `types.gen.ts`.** |
| Tests | Vitest (unit + component) + Playwright (E2E) | Hermetic E2E uses fake daemon at `tests/e2e/_fake-daemon.ts`; live smoke (`tests/e2e/_live-smoke.ts`) is opt-in `npx tsx`. |

## Architecture

```
Browser ──http──▶ Next.js  ──http──▶ Grove daemon (loopback only)
                  │
                  ├ /api/grove/[...path] = thin proxy (BFF)
                  ├ /               = the landing surface: Hero (composer) | Overview (grid)
                  ├ /activity       = redirect("/") (kept so bookmarks don't 404)
                  ├ /w/[id]         = session page (three-zone: rail | transcript | work panel)
                  ├ /sessions       = the host-wide Session Catalog
                  └ /sessions/[id]  = one catalog session's transcript, read-only
```

Every non-login route renders through ONE shared `app/(shell)/layout.tsx`, session page included.

- **BFF (Backend-for-Frontend)**: `app/api/grove/[...path]/route.ts` is the **only** network boundary the browser hits. Daemon URL comes from `GROVE_DAEMON_URL` env (default `http://127.0.0.1:7421`). The browser never sees the daemon directly: no CORS, no client-side daemon URL config. LAN reachability comes from binding Next on `0.0.0.0` and forwarding through the BFF.
- **Wire types**: `lib/grove/types.ts` re-exports schemas from `lib/grove/types.gen.ts` (auto-generated). Components import from `lib/grove/types`, never from `types.gen.ts` directly. The codegen pipeline IS the DRY anchor for the engine ↔ webapp contract.
- **Domain models**: `lib/grove/{client,repo-facet,agent-activity}.ts` — class-encapsulated, methods on the type that owns the state (mirrors the engine's "code as poem" principle). `GroveClient` wraps the BFF; `RepoFacet` groups workspaces by repo; `AgentLiveStatus` owns a card's live-signal derived state. There is exactly ONE card model — don't add a parallel one.
- **Client UI state**: `lib/grove/ui-store.ts` (Zustand) is the SINGLE home for cross-component UI intent — see the stack table. Components select narrowly (`useUiStore(s => s.query)`); never thread UI state through props or one-off hooks.
- **Shared presentational atoms**: `components/shared/{state-mark,dot,meta,stat,relative-time,role-label,landing-ring}.tsx` are the tiny pure leaves reused everywhere a glyph/dot/count/middot-row appears — defined once, restyled in one place. `AgentStateMark` is THE agent-state glyph/color system (card, status pill, detail, rail); `MetaRow` is THE middot-separated meta row; `Stat` is THE countable-metric leaf (icon + compacted tabular value, zero-suppressing, unit-in-tooltip); `RoleLabel` is THE transcript speaker label.
- **Hooks**: `lib/grove/hooks.ts` is the single SERVER-state subscription surface. One hook per resource. Components consume hooks; **components never fetch directly**.
- **The composer's repo chip sources from `useActivityStream()`'s `snapshot.projects`, NOT `useWorkspaces()`.** Deriving repos from the workspace list silently hides empty projects — a repo with zero workspaces (fresh, or config-declared via the engine's `projects` field) contributes no rows, so you could not create the *first* workspace in it. The `/activity` snapshot is the authoritative project list (the engine emits a `ProjectGroup` per `known_roots()` entry, empty groups included), and each group already carries `repo_root` + `repo_name`. Consequence: default-repo selection follows the snapshot's order (engine sorts roots), not workspace recency.
- **Per-create model selection rides the existing wire, not new client logic.** The composer's `Model ▾` sets `CreateWorkspaceRequest.model` — an optional field threaded engine-side into the agent launch; the webapp only *forwards* the parameter, never interprets the model (the provider boundary). The pill shows for every kind except a bare `generic` shell; **its offered ids come from the DAEMON's per-agent catalog** (`AgentSummaryView.models`, resolved by `agents.resolve_models`), never a client-side list — and the custom-id row is always the escape hatch, so an empty catalog still lets you type any id.

## Tailwind v4 traps (every one of these silently breaks the design)

1. **The `@theme` block in `app/globals.css` is mandatory.** Tailwind v4 + `@tailwindcss/postcss` does **not** consume `tailwind.config.{ts,js}`. Color utilities like `bg-background`, `bg-card`, `bg-muted`, `bg-primary`, `border-border`, `ring-ring`, `text-foreground`, `text-muted-foreground` are silently absent from compiled CSS unless declared via:
   ```css
   @theme inline {
     --color-background: hsl(var(--background));
     --color-card: hsl(var(--card));
     /* ...one entry per shadcn token... */
   }
   ```
   The visible result of getting this wrong is a layout that "looks fine but feels off" — surfaces blur together, no card boundaries, no muted strips, no focus rings, no hover affordances (body still has a background only because of the explicit `@layer base { body { background-color: hsl(var(--background)) } }` rule). Verification probe: `curl http://127.0.0.1:3000/_next/static/css/app/layout.css | grep -c '\.bg-card'` must return `>0`. **A green build does not mean the design system is wired — only the CSS-utility audit does.**
2. **Animations and keyframes belong inside `@theme`.** `--animate-grove-pulse: grove-pulse 1s ...` and the `@keyframes grove-pulse { ... }` block both go inside `@theme`, not as siblings. The JS-config `theme.extend.animation` route is dead in v4 — a custom keyframe declared there compiles to nothing.
3. **Radix animation classes need `tw-animate-css`.** Without `@import "tw-animate-css";` in `globals.css`, classes like `animate-in fade-in-0 zoom-in-95 slide-in-from-top-2` (Tooltip / Sheet / Dropdown / Dialog) compile to nothing. The components still mount and dismiss correctly — they just teleport instead of animating, which reads as cheap with no obvious cause.
4. **Tailwind v4 does not default borders to the theme color.** A bare `border` utility uses `currentColor`. Reset explicitly:
   ```css
   @layer base {
     *, ::after, ::before, ::backdrop, ::file-selector-button {
       border-color: hsl(var(--border));
     }
   }
   ```
   Without this, every `border` looks like body text color, and `border-border` only works where it's the explicit utility.
5. **`tailwind.config.ts` exists in this directory and is DEAD.** The PostCSS plugin ignores it entirely; it misleads the next reader. Do not add tokens to it, and do not trust anything it declares. Theme, fonts, keyframes, content paths — all of it goes in `globals.css` (`@theme`, `@source`).
6. **A new chrome token is invisible until it is in BOTH the `@theme` bridge AND the `:root`/`.dark` var blocks.** Same root cause as trap 1; verify with a `grep -o <utility> .next/**/*.css` count after a build.
7. **`@source` is automatic for files in the import graph, explicit for everything else.** Every TSX file currently lands in the graph, so nothing is needed for app code. But **classes emitted from `node_modules` `dist` are invisible to the scan** — `assistant-ui` and `streamdown` each need an explicit `@source "../node_modules/…/dist/**/*.js"` line in `globals.css`. Same for a colocated CSS file or a class only ever built from a string template.

## shadcn/ui patterns

1. **Look in `components/ui/` first** and compose what is already there — that directory listing is the census; never hand-roll chrome a primitive already provides. (`ScrollArea` is deliberately absent — see the scrollbar note.)
2. **Pull new primitives via the CLI**: `npx shadcn@latest add tooltip` (etc.). The CLI uses `components.json` for path aliases and writes canonical-shadcn output. Don't paste primitives in by hand — drift from canonical breaks future `shadcn add --overwrite` refreshes. Keep `components.json` checked in even though it looks like CLI scaffolding; without it `shadcn add` fails with a misleading "couldn't read config".
3. **`asChild` is the canonical pill-as-link pattern.** Use it for nav links so a single `<a>` carries pill geometry, focus ring, and SPA routing at once:
   ```tsx
   <Button asChild variant="ghost" size="sm">
     <Link href="/" aria-label="Back to all workspaces">
       <ArrowLeft />
       <span>All workspaces</span>
     </Link>
   </Button>
   ```
   Never wrap a `<Link>` inside a `<button>` (invalid HTML — interactive content nested in interactive content); never wrap a `<button>` inside an `<a>` (the focus ring lands on the wrong element). Slot solves both.
4. **All Button variants and sizes flow through `components/ui/button.tsx` (CVA).** New visual treatments add a CVA variant — they don't fork into a sibling component. Sizes: `xs`/`icon-xs` (h-7, dense chrome) · `sm`/`icon-sm` (h-8/h-9) · `default` (h-9) · `lg` (h-10). **SVG sizing lives per-size, not in the base** (`xs`/`icon-xs` → `size-3.5`, the rest → `size-4`) — a 16px glyph swamps a 28px control. **Stroke width is a single global rule, not a per-component prop** (`svg.lucide { stroke-width: 1.75 }` in `globals.css` `@layer base`) — lucide-react has no theme provider, so that CSS selector is the one seam for an app-wide stroke tune. Never pass `strokeWidth` on individual `<Icon>` instances.
5. **`<Badge>` is the right base for any pill** (status, identity, count). Compose with `className` / inline `style` for color tokens; do NOT introduce a sibling pill primitive. Trap: `Badge` renders a `<div>` (flow content) and therefore **cannot nest inside a `<button>`** — a leading state mark next to a trigger must be a SIBLING of it.
6. **Native scrollbars, not `ScrollArea`.** A global `@layer base` rule in `globals.css` (`scrollbar-width: thin; scrollbar-color: var(--scrollbar-thumb) transparent`) themes every `overflow-auto`/`overflow-y-auto` element for free — no JS, no wrapper, theme-aware, zero gutter. The `components/ui/scroll-area.tsx` primitive and the `@radix-ui/react-scroll-area` dependency are both **deleted**; don't reintroduce them (the only conceivable exception is a surface needing genuine JS idle-hide, and none exists). **Do not add `::-webkit-scrollbar` rules** — current Chrome deprioritizes them, and styling one force-renders a classic always-visible bar, killing native overlay auto-hide.

## Design language (visual contract)

This section is the canonical visual contract for the webapp. Update it in the same commit as any change that affects look or feel. [`design-system.md`](design-system.md) is authoritative; this section must never contradict it.

### Theme

Two cohesive themes, defined ONLY as the neutral ramp in `globals.css` (`:root` light, `.dark`). **Dark = "space black":** a deep near-black canvas at a near-neutral/barely-warm hue (~45-60) — a cool-blue cast fights the warm terracotta accent. **Light = a warm-neutral off-white** (`#faf9f5`, hue ~48). The whole neutral ramp is ONE hue family per theme with **wide lightness steps** so elevation reads without borrowing chroma.

**Only the NEUTRAL ramp and the terracotta trio are free to retheme.** The semantic palettes (`--status-*` / `--agent-*` / `--ref-*`) are mirrored from Python and drift-tested (`status-tokens`, `agent-state-tokens`), so a theme edit that touches them fails the build. When you touch theme, touch the neutral ramp — never the semantic hexes.

**Terracotta is three tokens, not one.** `--primary` is the brand MARK only (logo, dark-mode ring) — white on it is 3.12:1 and fails AA, so it is never a text-bearing fill. `--primary-fg` is terracotta AS TEXT (the `you` speaker label, links). `--primary-strong` (`#b95230`, 4.8:1) is the CTA fill for send/create buttons. Any new CTA that carries a label fills with `--primary-strong`.

**The contrast contract is enforced, not eyeballed:** `tests/unit/contrast.test.ts` parses the `:root`/`.dark` HSL tokens straight out of `globals.css` and asserts the WCAG floors (AA 4.5 for all text including 12-13px meta, AAA 7 for prose, 3:1 for non-text), so an edit that lightens a token below floor fails the build. It reads only HSL-triplet tokens (`H S% L%`) — the hex-based `--status`/`--agent`/`--ref` vars and the `rgba()` `--scrollbar-thumb` are outside its regex.

### Surfaces (elevation tiers)

A deliberate elevation LADDER — climbing in lightness so depth is legible without chroma. Chrome (header · session rail, incl. its footer) shares ONE tone so the persistent frame reads as a single surface around the content canvas.

| Token | Use | Class |
|---|---|---|
| Base canvas | Body, page background, deepest terminal well | `bg-background` |
| Chrome | Header · session rail (incl. rail footer) — the persistent frame | `bg-sidebar` (+ `border-sidebar-border`) |
| Panel | Cards, primary surfaces | `bg-card` |
| Overlay | Tooltips, dropdowns, dialogs | `bg-popover` |
| Raised | Composer hero, raised wells above a card | `bg-elevated` |
| Subtle well | Card footer strips | `bg-muted/40` |
| Active fill | Pressed scope/filter chip, hover | `bg-accent` / `bg-muted/60` |

Borders are `border-border` on content and `border-sidebar-border` on chrome, unless an indicator is meaningful (e.g. `border-l-2` in a tier accent var for an attention card / active commit row).

The session page (`/w/[id]`) is a full-bleed three-zone shell (rail | transcript | work panel) whose depth is surface **tone + space**, never lift and never lines — no card, no lift gutter, no nested transcript frame, no terminal frame.

**No drop shadow on dark surfaces — depth is the surface ladder, not `box-shadow`.** Cards, panels, buttons, tabs, and inputs carry depth through their `bg-*` tier + a hairline border, never a `shadow-*` utility (enforced repo-wide). The *only* exception is floating overlays that genuinely leave the page plane — `Tooltip`/`Dialog`/`Sheet`/`DropdownMenu`/`Popover` keep their shadcn shadow. Shadows drifting back onto cards and buttons is the regression to watch for. Likewise `rounded-full` is for status pills and toggle pills (the composer's quiet `Agent ▾`/`Model ▾` selectors) only — momentary action buttons, terracotta send included, are `rounded-md`.

**Quiet-chrome discipline.** Surfaces are neutral graphite; **saturated hue appears ONLY to carry state** (the status / agent / ref tokens), and only as a **small mark** — a glyph, a `Dot`, a thin `border-l-2` accent bar — **never a large fill or a full-card border/glow**. Terracotta is reserved for the composer's create/send CTA + the brand mark + the `you` speaker label, nothing else; scarcity is what makes the send button read as the one primary action. **When something looks flat, the fix is structure — a tone well, spacing, a section label — not color**, and tone + space before a drawn line. Quiet-chrome is the *color* clause of the broader calm-first philosophy; the named philosophy lives in [`design-system.md`](design-system.md) under **Design philosophy**.

### Color language (semantic tokens, not hex)

Defined once in `globals.css`, mirrored at component layer via `[var(--token)]` arbitrary values.

| Token | Hue | Use | Sparingly? |
|---|---|---|---|
| `--primary` | terracotta | Brand mark + the composer's create/send CTA + the `you` transcript speaker label. | Yes — exactly those three; never card chrome, never a second CTA. |
| `--ref-branch` | teal | Current branch identifier (mono text + outline borders). | Wherever a branch name appears. |
| `--ref-info` | blue | Agent identifier. | Wherever an agent name appears. |
| `--ref-add` | green | Diff additions, "ahead" stat polarity. | Wherever a positive count is meaningful. |
| `--ref-remove` | red | Diff removals, "behind" stat polarity. | Wherever a negative count is meaningful. |
| `--status-active`, `--status-running` | lime / olive | Lifecycle: ACTIVE, RUNNING. | Status badge + accent stripe + the rail footer's daemon-reachability dot only. |
| `--status-idle` | blue (light) / pale-blue (dark) | Lifecycle: IDLE. | Same. |
| `--status-provisioning` | aliased to `--status-idle` | Lifecycle: PROVISIONING (container being built). | Same. Never the muted gray — see design-system.md's status-axes section for why. |
| `--status-offline`, `--status-paused` | neutral gray | Lifecycle: OFFLINE / PAUSED. | Same. |
| `--status-orphaned` | amber | Lifecycle: ORPHANED. | Same. |
| `--status-error` | red | Lifecycle: ERROR. | Same. Also the "daemon unreachable" indicator. |

The status palette is **mirrored** from `grove/core/contracts/status_palette.py` — the Python source is canonical. The drift test in `tests/unit/status-tokens.test.ts` reads the Python file at test time and asserts the JS constants match. **If you change a status hex, change it in Python.**

**Never color the label AND the surface with the same status hue** — it lands AA-borderline (lime text on a near-white tinted surface in light mode). Decouple: text = `text-foreground`, glyph = status hue. Applies to any tinted pill.

### Typography

Three families, all self-hosted via next/font (no CDN, no layout shift) and declared in ONE place — `app/fonts.ts` — then mapped to Tailwind tokens in the `globals.css` `@theme`: **Geist Sans** (`--font-sans`, UI chrome), **Geist Mono** (`--font-mono`, code + git identifiers), and the terminal **JetBrains Mono Nerd Font** (`--font-terminal` → `--font-jetbrains-nerd`). Geist's `.variable`s ride `<html>` in `app/layout.tsx`; the Nerd Font's `.variable` is dropped ONLY on the terminal subtree (`terminal-pane` / `peek-snapshot`), never `<html>` — its full un-subset powerline/private-use glyph ranges are the point for agent TUIs but must not bleed into app chrome. Body carries `letter-spacing: 0.01em`.

A **compact, dense type scale** (quiet IDE feel, max info per row):

| Tier | Class | Use |
|---|---|---|
| Title | `text-base` (16px) `font-semibold` | Page + card titles, prominent stat values. |
| Body | `text-sm` (14px) | Body copy, descriptions, transcript prose. |
| Dense row | `text-[13px]` | Sidebar entries, metric one-liners, AND **all code** (inline + fenced + tool args, forced `font-mono text-[13px]`). |
| Metadata | `text-xs` (12px) `text-muted-foreground` | Relative times, byline copy, secondary info. |
| Section label | `text-[11px] font-semibold uppercase tracking-[0.08em] text-muted-foreground` | Panel section headers ("SUMMARY", "AGENT"). The terminal-feel cue. |
| Micro label | `text-[10px] uppercase tracking-wider` | Stat units (AHEAD / BEHIND / DIRTY under numbers). |

`font-mono` for **every** git/code identifier: branches, base branches, agent names, SHAs, commit subjects (bodies stay sans), file paths. The terminal `<pre>` uses `font-terminal` (~12–13px) so the Nerd Font glyphs resolve.

**A second, dormant type scale lives in `globals.css`'s `@theme inline`** (`--text-page-title`/`--card-title`/`--prose`/`--caption`/`--code`/`--micro` + matching `--tracking-*`) — named tiers for sizes/line-heights the table above doesn't cover (20px titles, 16px/1.6 chat prose, 11px uppercase micro-labels). Defined but **applied to no component**. Don't rewrite the table above until a component actually switches onto it.

### Spacing

4 px grid. Allowed gap values: `{1, 1.5, 2, 3, 4, 5, 6}`. Allowed padding values: `{2, 3, 4, 6}`. Card padding `p-4` standard, `p-3` compact, `p-6` spacious.

**Layout (full-bleed shell).** The chrome is full-bleed: the session rail (`w-70`, animating to `w-0`/full-hide when collapsed — no icon strip) hugs the viewport's left edge and runs full height below the header; the header (`h-13`, 52px) spans the full width — both on `bg-sidebar`. The CONTENT re-centers inside each route's own `<main>` (the landing centers at `max-w-[100rem]`; the session page is a fixed-height three-zone shell), so an ultrawide reads "rail flush-left · wide centered canvas", never "everything stranded in a narrow middle column". **The viewport-fill magic number is `3.25rem` (`h-13`, the header alone)** — used by the (shell) rail height (`top-13`/`h-[calc(100dvh-3.25rem)]`) and the session page's `<main>`. Move the header height and you must change both.

### Density

| Element | Height | Why |
|---|---|---|
| `xs` / `icon-xs` button | `h-7` (28 px) | Dense toolbar chrome (rail, identity strip). Glyph is `size-3.5` not `size-4`. |
| Session-rail row | `h-8` (32 px) | Thread-list row — a `StateDot` + title, single line. |
| `sm` / Tab triggers | `h-8` (32 px) | Compact tabs, file-tab feel; `icon-sm` is also `h-8`. |
| Default button | `h-9 px-4` (36 px) | Standard interactive control. |
| `lg` button | `h-10` (40 px) | The rare emphasis case. |
| Header | `h-13` (52 px) | Chat-app header height; brand + actions + the portaled session identity strip. |

WCAG-mobile recommends 44 px tap targets; we hold the line at 32–36 inside the chrome (acceptable for dense desktop chrome) and use the larger sizes for primary actions. When in doubt, prefer the larger size.

### Transitions

200 ms ease-out across the board. **Never** `transition-all` — animate only `transform`, `colors`, `border-color` selectively, to avoid color flicker on text. Card hover = `-translate-y-[1px] + border thickening` (no shadow). Reserved animations: `animate-grove-pulse` for ACTIVE / RUNNING status badges only (4 Hz step pulse — terminal-cursor-like), and the same cadence for the transcript "working" indicator (`chat-shimmer`), in the working hue so terracotta stays scarce there.

**Two keyframes are the ONLY sanctioned places terracotta *moves*** — both decay <1 s, never steady-state, so accent scarcity holds. **`grove-shimmer`** is the loading-skeleton sweep, a ~5%-opacity terracotta band across the muted base (`components/ui/skeleton.tsx`, `motion-safe:` only → a static `bg-muted` block under reduced motion; this is the ONE `Skeleton`, reused everywhere data loads). **`grove-ring`** is the one-shot "just landed" ring on a freshly-created card/row (`components/shared/landing-ring.tsx`): an absolutely-positioned `pointer-events-none` overlay SIBLING (never on the host's own className, so the host's `ring-*`/`border-*` test contracts stay intact — the host just needs `relative`), gated to fire once on mount only when `created_at` is within a 15 s window, using an **INSET** box-shadow ring so an `overflow-hidden` card doesn't clip it, with `forwards` holding it transparent so it can't persist.

Press tactility: the composer send buttons carry `active:scale-[0.97] motion-reduce:active:scale-100` (transform listed explicitly, never `transition-all`). Safe-area: the header pads `env(safe-area-inset-top/left/right)` and the session composer pads `env(safe-area-inset-bottom)`, all `max(…)`-floored so they resolve to 0 on a non-notched viewport and never perturb the E2E DOM; the keyboard-aware composer relies on the root `interactiveWidget: "resizes-content"` viewport meta. Empty states are a quiet lucide icon + headline (not italic muted prose); login gets the one display-scale wordmark.

### Focus + a11y

- Every interactive element gets `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background`. The Button primitive bakes this in; if you build something that isn't a Button, copy the contract.
- All icon-only buttons need `aria-label`. All decorative icons get `aria-hidden`.
- Polling indicators use `aria-live="polite"`.
- Status colors are an enhancement — the badge **also** carries text labels and glyph characters so colorblind / monochrome users still get the signal.
- Animations honor `motion-reduce:animate-none`.

## App shell (rail + header on every route)

ONE persistent shell wraps **every** non-login route, session page included: `app/(shell)/layout.tsx` contains `/`, the `/activity` redirect, `/w/[id]`, and `/sessions`. There is no status bar — the system-status strip lives in the session rail's footer. Persistent regions:

1. **Header** (`components/layout/header.tsx`) — sticky top, **h-13 (52px), full-bleed on the shared chrome tone** (`bg-sidebar/85 backdrop-blur-md`), borderless (tone alone separates it from the canvas). Brand block on the left (Grove logo `img` + wordmark; `hidden sm:block` in `back` mode so a phone spends that width on the identity title), actions on the right (theme toggle + the `/sessions` nav link). Rendered ONCE by the shared layout, so a page that needs to fill its middle **cannot pass a `context` prop up to it** — instead the layout captures the header's middle DOM node via `contextSlotRef` and publishes it through `HeaderSlotContext` (`components/layout/header-slot.tsx`); the session page reads it with `useHeaderSlot()` and `createPortal`s its identity cluster in. A portal (not a node threaded through props/state) is deliberate: the portaled subtree re-renders WITH the page, so live session data stays fresh without pushing an ever-changing node through React state. Every other route leaves the slot empty (a plain `flex-1` spacer). **No create button here** — the composer is the single create affordance. `back?: boolean` is route-derived by the layout itself (`pathname?.startsWith("/w/")`) — no page threads it up: when true the wordmark disappears (logo-only, static) and an explicit `ArrowLeft` button takes its place, because a bare brand-click as the only "home" affordance is not discoverable.
2. **Session rail** (`components/layout/workspace-sidebar.tsx`) — persistent on every route, `w-70` (280px), sticky below the header (`top-13`, `h-[calc(100dvh-3.25rem)]`). Its scrollable BODY is the **session tree** (`SessionRail`): a FLAT, cross-project list sorted `modified_at` DESC, two-line rows (state dot + title, then a `project · branch · +N/−M` provenance line) — no project sections, no date buckets, no attention pin (see `design-system.md`'s "The session rail" for the full row/filter contract). A quiet **"New session"** ghost row leads the rail; each row reveals a hover `⋯` menu (`session-rail-row-menu` → "Make primary"). Rail order top→bottom: **search input** (writes the one `query` store field, filters the tree AND the Overview grid) **→ compact filter dropdown** (`SidebarFilter` — the single organizing instrument: states, attention, per-project, show-unmapped) **→ session list → `RailFooter`** (daemon health + live uptime, version + update nudge, workspace count, then a `user@host` identity row + GitHub link). **Collapse fully HIDES the rail:** `sidebarCollapsed` (persisted in `ui-store`) drives the shell to animate the wrapper to `w-0` **and mark it `inert`**; there is NO collapsed icon-strip variant. The header button or `[` (ignored while a field is focused, so it never eats a filter keystroke) reopen it. Desktop = sticky rail; mobile = a left `Sheet` drawer from the header hamburger.
3. **Landing (`app/(shell)/page.tsx`) — persisted Hero | Overview.** `/` reads one persisted `ui-store` slice, `landingView`: **Hero** (default) is a centered composer (`components/composer/Composer`) plus a "Recent" strip of recently-active workspaces — the fleet lives in the rail, not on this surface. **Overview** is the rich repo-grouped `WorkspaceGrid` (one `project-section` per repo, attention-first within, plus the Live focused-pane toggle) — a click away for a power user who wants the whole wall. The toggle is a quiet two-button segmented control, never terracotta.
4. **Session page (`app/(shell)/w/[id]/page.tsx`) — three-zone.** Rail (region 2, shared) | transcript column | tabbed work panel. The page builds its own `ContextBar` and portals it into the header slot — exactly one `context-bar` mount at every breakpoint, no separate below-`lg` band. `ContextBar` (`components/workspace/context-bar.tsx`) is a **state-led title trigger opening ONE session popover** (`identity-trigger` → `branch-summary`: Identity · Changes · Actions · Danger zone), NOT an always-visible strip. The live state rides a `session-state-live` sr-only `aria-live` region beside the mark — **ONLY the state word, never the raw task/prompt text**. The page is a fixed-height flex column, `h-[calc(100dvh-3.25rem)]` — the header alone is the only chrome subtracted. **Never add `overflow-hidden`** to this column or `detail-panel` (see the scroll-trap rule below).

**Anything the session rail imports lands in EVERY route's module graph, and `next dev` does not tree-shake it out.** A component mounted by the rail — or anything else in `(shell)/layout.tsx` — must import only leaves; co-locating a badge with a meter that pulls a Radix dependency drags that dependency into the shared shell chunk. Production `next build` shakes it out; **dev does not**, and the e2e suite runs against `npm run dev`, where the extra module compile can push a margin-thin navigation past a 5 s assertion on throttled mobile-chrome. Corollary: when an unrelated e2e test starts timing out after a UI addition, suspect the module graph before the logic, and confirm with `next build`'s per-route sizes.

Header and rail are **shared verbatim** across every route; a page that needs chrome reuses them via the slot/props above rather than forking a page-local twin. The TUI uses an analogous header-content-footer layout (see `docs/design-system.md`) — web and TUI stay siblings.

**Don't copy non-functional chrome from a mock — match the system, not the pixels.** A `⌘K` search, an "Agents" nav item, an account avatar: none have a route or a backend, so none ship. "Implement the design" means incorporating its intent into the system's grain, not transcribing every element.

**Header shape, four rules** (validated against a sibling console's navbar, kept while implementing): (1) ONE header row splits into a **truncating identity zone** (`flex-1 min-w-0` — the title shrinks first) + a **fixed action zone** (`shrink-0` with a guaranteed gap, so the right icons never crowd the title); (2) **status in exactly ONE place; live telemetry is a separate, named surface** — never the same readout twice; (3) every secondary surface is **exactly one click away** (popover/dropdown), never inline; (4) metadata drops as a **whole unit** on small widths (`hidden md:flex`), not element-by-element.

## The Session Catalog (`/sessions`) — host scope is a different question, not a wider rail

`/sessions` lists **every agent session on the host** and `/sessions/[id]?kind=&cwd=` opens one **read-only**. Both live in the shared shell, inheriting header + rail. The engine/daemon/wire halves are upstream ([core](../src/grove/core/CLAUDE.md), [daemon](../src/grove/daemon/CLAUDE.md), [contracts](../src/grove/core/contracts/CLAUDE.md)); what follows is what the client decides.

- **The rail stays on `useProjectSessionsAll`; the screen has its own `useSessionCatalog`. The two are not the same list at two widths.** `useProjectSessionsAll` fans N parallel `GET /sessions?repo=X` calls **across the repos Grove already knows** (`facets.projects`), so it can *never* surface a session in a repo Grove has never managed — which is the entire point of the catalog. It is also N full transcript parses. `useSessionCatalog` is ONE `GET /sessions` with `repo` omitted: whole-host, metadata-only, one bounded head read per row. Beyond data, the two rows do different jobs — a rail row navigates into a *live workspace* to steer it; a catalog row opens an *archive*. Two scopes, two jobs, two hooks.
- **The nav entry is in the header's `<nav>`, not the rail footer, and collapse is the deciding argument.** A collapsed rail is `w-0` **and `inert`**, so a footer link would be unreachable by pointer AND keyboard in a state one keystroke reaches. The header `<nav aria-label="Site actions">` is also the app's only navigation region; the rail footer is a system-status strip, where a route link reads as chrome. It stays quiet: ghost button, `History` glyph, label hidden below `sm`.
- **`SessionSummaryView.activity` and `.size_bytes` are NULLABLE, and null means "not measured at this scope" — never zero.** One view serves both listing scopes; the host scan never parses a transcript, so it cannot fill them. Every reader degrades to the `unknown` state token rather than fabricating an idle mark: `SessionRail` (`RailEntry.activity` is nullable), `SessionPicker`, and the session page's `agentState`. **A catalog row also has no `title` and no prompts**, so the label falls back workspace-title → branch → bare session id (`catalogRowLabel`); rendering "untitled session" would hide *which* of the three you are looking at.
- **Two honest-degradation rows, both listed and never hidden.** A row whose `cwd` is null has no `(kind, cwd, id)` coordinate, so it renders inert + dimmed with the reason in its tooltip — hiding it would misreport the host. A row whose `cwd` resolves to no git repo joins one "No git repository" group, ordered by recency like any other.
- **`cwd` round-trips byte-for-byte through the URL.** The adapters match a *recorded* cwd by string, so the drill-in link carries the row's `cwd` verbatim (URL-encoded, never normalized or re-joined) — a "tidied" path is a guaranteed 404. This is why the detail route's identity is a triple in the query string rather than a bare id in the path.
- **Read-only is structural, not a disabled prop.** `ReadOnlyTranscript` reuses the SAME assistant-ui headless path as `ChatPanel` — `useTranscriptRuntime` under `ThreadPrimitive.Viewport`/`.Messages` with the one `GroveMessage` — and simply has no composer, interrupt, todo card, or pending-question sibling. A catalog session usually has no workspace behind it, so a greyed-out composer would promise an affordance the wire cannot honor. `ThreadList`/`ThreadListPrimitive` are used NOWHERE: the list is Grove's own row model, deliberately.
- **Pure shaping lives in `lib/grove/session-catalog.ts`** (grouping, ordering, label fallback, drillability, cwd relativization, query match) — the `dashboard-filter.ts` / `chat-turns.ts` precedent, so the honesty rules are unit-testable without a DOM.
- **The `/sessions` search is page-local `useState`, NOT `ui-store.query`.** That store field is contracted as the rail-and-grid filter; a third consumer at a different scope would mean typing in the rail silently narrows a full-page catalog.
- **Test seams:** `sessions-page`, `sessions-search`, `sessions-count`, `sessions-limit-note`, `session-catalog`, `session-catalog-group` (+ `data-repo-root`), `session-catalog-group-name`, `session-catalog-row` (+ `data-session-id`/`data-drillable`/`data-live`/`data-grove`), `session-catalog-live`, `session-catalog-branch`, `session-catalog-empty`, `session-detail`, `session-detail-back`, `session-detail-title`, `session-detail-error`, `read-only-transcript`, `read-only-transcript-empty`, `nav-sessions`.
- **`/sessions/[id]` is a `next/dynamic` leaf, so its FIRST visit in a dev server pays an on-demand chunk compile (~15 s measured) that outruns Playwright's 5 s expect default.** The transcript assertion carries an explicit long timeout; that is build latency, not product latency, and shortening it just buys a flake. Same file: wait for the row list to SETTLE (`toHaveCount`) before clicking a row — a click landing inside the skeleton→rows commit gets swallowed by the node replacement.

## Composer & card

- **The composer (`components/composer/`, the Hero).** An always-present `rounded-3xl` (24px) card: the textarea IS the create surface (type → Enter creates; title auto-derives from the first line, the full text rides as `initial_prompt`). Toolbar: an `Agent ▾` pill, a `Model ▾` pill, a quiet **fullscreen** toggle, and the single high-contrast **send** button (`bg-primary-strong`, never bare `--primary`). A borderless context-chip row (repo · base · branch mode) sits below, with branch source + skip-init behind an `Advanced ▾` disclosure (collapsed by default). Decomposed: `composer.tsx` (container, wires store + hooks) over presentational pickers/chips that share `pill.tsx`.
  - **Model menus come from the daemon's per-agent catalog.** `AgentSummaryView.models` (≤10, resolved daemon-side by `agents.resolve_models` — see [agents](../src/grove/core/agents/CLAUDE.md)) is the source; there is no hand-edited model list client-side. `ModelPicker` takes a `models: string[]` prop (bare ids, id === label); rows are the agent's offered ids plus the always-present "Custom model id…" escape hatch — **the catalog is a hint, never a closed set.** The value rides the wire as `CreateWorkspaceRequest.model`, forwarded verbatim.
  - **Expand-on-focus + fullscreen markdown.** The inline textarea grows + the card lifts (200 ms tween) while focused or non-empty. A `Maximize` toggle opens a near-viewport `Dialog` with a `Write | Preview` split — Preview renders the prompt as Markdown via the **lazy** `Response` (streamdown is `next/dynamic`-imported so the home bundle pays nothing until preview opens). Inline + fullscreen share ONE store-backed draft; fullscreen submits on ⌘/Ctrl+Enter (Enter = newline for long Markdown), inline keeps Enter = submit.
  - **`scopeRepo` is live wiring with no control attached.** The composer guards on it (`useEffect` in `composer.tsx`) and `WorkspaceGrid`/`dashboard-filter.ts` still read it, but no rail control sets it — the rail offers a session tree, not a repo-scope switcher. Harmless dormant wiring, not a bug to silently "fix" by deleting; if the rail ever grows a repo-scope affordance, this is the seam it reconnects to.
- **The card (`components/workspace/card.tsx`) — calm two-tier tile.** `rounded-xl bg-card` on a `border-border/60` hairline; hover is a tonal shift + border-strengthen, NO shadow/lift/glow. Two visual tiers separated by space, not a tinted well: **HEADER** — the bare `AgentStateMark` glyph (NOT a badge) + title link (`line-clamp`ped to one line) + a right-aligned `RelativeTime`; the lifecycle `StatusBadge` returns ONLY when it is itself the signal (no agent session, or `orphaned`/`error`) — a healthy card wears zero pills. **CONTEXT** — "happening now" (`line-clamp-1`; error detail wins while erroring, keeping the `· N bg` suffix). **META** — TWO aligned `Stat` rows on one 11px `h-5` baseline grid (shared `gap-3`, so card heights stay uniform), then the prose last-commit line (`parseCommitSubject`, no emoji): row 1 provenance (teal `GitBranch` + mono branch · ahead · behind · dirty · placement-when-root), row 2 activity (turns · tool calls · tokens in/out) with the WORKING-gated Live toggle pinned right. Every count is the shared **`Stat`** atom — icon + tabular value, unit in the tooltip, `tone` colors the value only (`--ref-add`/`--ref-remove`), and a **zero renders NOTHING** (no "0 ahead 0 behind"). Attention (waiting/blocked/error) = a thin left `border-l-2` accent bar in the tier var, never a full-card glow. Cards render ONCE, grouped by repo in `WorkspaceGrid` (`project-section` per repo, attention-first within).
- **The rail meta line deliberately does NOT share `Stat`** — it stays an icon-free quiet `MetaRow` with `+N/−M` line-changed sigils + plain-muted branch: same `--ref-*` tone grammar, different register and different fields (±lines vs ahead/behind). Sharing the atom is right in spirit; forcing it across both is false uniformity.

- **A "silence is the signal" component is only right when the silent case is a boring default — for the ISOLATION axis it was actively wrong.** `RuntimeBadge` opened with `if (runtime !== "container") return null`, copying `PlacementBadge`'s philosophy, and had exactly one mount (the work-panel Info tab). Placement's default is an implementation detail; runtime says whether the agent can reach the host filesystem, host network and the user's credentials, so a silent host badge left "runs on your machine" indistinguishable from "this component didn't render". Both states now carry a mark, on the card, the rail row, the identity popover and the Info tab — the per-surface audit applied to a fourth axis, and again the components were fine and the MOUNTS were the gap. **The test for the next axis: is the silent case boring, or is it merely common?**
- **A vocabulary shared with the TUI must be a shared SOURCE, and for a glyph that rules out lucide.** `lib/grove/runtime-tokens.ts` mirrors `grove/core/contracts/runtime_palette.py` — the same file the TUI imports — and `tests/unit/runtime-tokens.test.ts` reads that Python for glyph AND label AND hex (the older `status-tokens`/`agent-state-tokens` drift tests pin hex only). So the runtime mark is a text glyph (`■`/`▣`) rather than a `Box` icon: an icon set only this client can render cannot be the same mark a terminal draws, which is the whole requirement. Precedent already existed in `AgentStateMark`; the new part is that the CHARACTER is now contract rather than convention. Prove such a test by MUTATION (change the TS glyph, watch it fail) — a drift test that reads a file by regex can silently stop matching and keep passing.
- **Two registers, not one component with a `size` prop, when the surfaces differ in kind:** `RuntimeMark` (bare glyph — card META, rail meta line) and `RuntimeBadge` (glyph + word + the degradation tones — Info tab, identity popover), mirroring the established `StateDot` / `AgentStateMark` split. The degradations (`fallback` amber, "default container" notice) live only on the labeled register: a dense surface has room for the axis, not for its exceptions.

The unified glyph/color system is `AgentStateMark` (`components/shared/state-mark.tsx`): `▶` working (lime, pulse) · `◑` waiting · `⚠` blocked · `✗` error · `○` idle — one home, reused on card, status pill, rail and detail. **The state vocabulary is two-tier:** the rail's minimal `StateDot` vs. the card/trigger's full `AgentStateMark` — one `--agent-*` color system, two densities. Three type roles hold throughout: **title** (foreground, medium) · **prompt/body** (foreground, normal, truncated) · **meta** (muted, small).

**A status axis is only shipped once EVERY surface that shows a workspace shows it — and the audit that catches a gap is per-surface, not per-component.** A well-designed badge mounted by exactly one caller passes every component-level review while the user still loses the axis on the way from the wall into a workspace. Enumerate the surfaces instead: card, rail row, header identity cluster, work-panel Info tab. **The structural cause is a data-shape trap:** phase rides `WorkspaceActivityView` (the SSE snapshot) while the detail page's identity chrome is built from `WorkspacePeekView` (a poll), so an axis added to the activity view is invisible to every peek-fed surface until someone threads it. The seam is `findWorkspaceActivity(snapshot, id)` — the page and `AgentWorkspace` already hold that snapshot, so surfacing it costs a prop, never a new fetch. **When the engine adds a field to the activity view, grep for the peek-fed surfaces before declaring it done.**

**"Absence is not a state" means ZERO renders nothing — it never means "an incomplete state renders nothing".** `TicketLinkage` mounts on an issue alone; requiring a `pull_request` first blanks the linkage for most of a workspace's life, since an orchestrator attaches the issue at create and the PR appears near the end. **Test a render rule against the *lifecycle* of the data, not one snapshot of it.** The hue budget still holds: issues stay muted text and the arrow mounts only when there is an outcome to point at, so widening visibility costs zero new color.

**shadcn's `Progress` swallows `value` before the Radix Root**, so the bar self-reports `indeterminate` and emits no `aria-valuenow` — **fix it at the CONSUMER, never in `components/ui/`.** The wrapper destructures `value` purely to compute the indicator's `translateX`; the Root never receives it. Radix spreads incoming props *after* its own `aria-*`, so passing `aria-valuenow`/`aria-valuemax`/`aria-valuetext` on the `<Progress>` element wins — and lets you state the honest domain scale (`3` of `6`) rather than the percentage the fill needs. Patching the primitive would drift from the registry and be silently reverted by the next `shadcn add --overwrite`. Same reasoning for the indicator's color: inject a CSS var on the Root and reach the child with the `[&>div]:` arbitrary variant.

**Agent brand logos go through one extensible registry (`lib/grove/agent-icon.tsx`), never hand-authored SVGs.** `simple-icons` ships only `siClaude` / `siAnthropic` off the shelf; OpenAI, Codex and OpenCode have no brand icon in simple-icons or lucide (lucide carries zero brands by policy), so they fall back to a lucide glyph (`Bot` / `Terminal`) behind the same `AGENT_ICON` map — adding a real glyph later, or a new agent, is a one-line map edit. `resolveAgentIcon(agentName, adapterKind)` matches `adapterKind` first, then an `agentName` substring; the map mirrors the backend's `AgentAdapter` registry. `simple-icons` exports `SimpleIcon` as a *type*, so the wrapper re-exports it as `SimpleIconData` to free the component name. Brand marks render **static** (a spinning logo reads wrong); liveness is a separate `animate-ping` ring around the still glyph.

**The colour/transparency philosophy lives in ONE module (`lib/grove/activity-tier.ts`) so rendering and sorting can't drift.** Three tiers: *active* (working, or — with no agent session — tmux `ACTIVE`) = full opacity; *attention* (waiting / blocked / error) = full opacity + highlighted accent, **never dimmed**; *dormant* (idle / offline / unknown / starting / sessionless-and-not-active) = dimmed, where lower opacity encodes a lower tier. The **tmux fallback** is here: `tierForActivity(null, workspaceStatus)` derives the tier from `WorkspaceStatus`, so a generic/non-Claude agent still reads working/idle from tmux. The same module exports `activityRank` — the sort key that floats running sessions forward — so "what tier is this card" and "does it sort first" share one source of truth.

**Ordering on the wall: `compareByAttention` (pure, unit-tested) = `activityRank` asc (attention=0 < active=1 < dormant=2) → `observed_at` desc → stable.** A blocked/waiting agent burns wall-clock until a human answers, so it outranks working. `@formkit/auto-animate` (~3 kb, honours `prefers-reduced-motion`; chosen over framer-motion purely for footprint) animates SSE-driven reorders via a single `useAutoAnimate` ref on the grid.

**`computeFacets` dedupes nested-project groups by `repo_root` — every facet-level consumer MUST route through it.** A nested project emits one `ProjectGroup` per `cwd`, but they SHARE a `repo_root`; the rail's per-repo session source (`GET /sessions?repo=`) has no per-subpath scoping, so a facet-level section is per-REPO, not per-group. `computeFacets` collapses by `repo_root` (first occurrence's name wins, counts sum), and both facet consumers ride it — the rail AND the composer's create-target picker. **A new facet-level consumer that reads `snapshot.projects` raw will re-introduce duplicate sections (one repo listed N times).**

**One consolidated filter, stored as HIDDEN sets.** `DashboardFilterState = {hiddenProjects, hiddenStates, attentionOnly}` (`lib/grove/dashboard-filter.ts`) — so the **empty default shows everything** AND a state/project that streams in *later* is visible by default; a deselected row is an explicit choice, never a stale snapshot of "what existed when the menu opened". Every row shows a live count from `computeFacets(snapshot)`, so `working: 0` is self-explanatory. `filterSnapshot(snapshot, filter)` is the pure apply (drops emptied groups); `displayState(w)` = `sessions[0]?.activity.state ?? "unknown"` is the single state a workspace filters and labels by. Filter UI is e2e-covered (`filter-attention`/`filter-state-*`/`filter-project-*`/`filter-reset`); the logic is unit-covered. **Don't add a vitest component test that opens the popover** — radix's pointer-capture/portal needs jsdom mocks and is flaky. Test the reducer, not the menu.

**`activity-stream.ts` = stream contract + pure reducer; `dashboard-filter.ts` = wall-presentation policy.** Two answers to two questions that change for different reasons — "how do SSE events fold into a snapshot" (transport-coupled, changes with the daemon's event contract) vs. "which workspaces show, in what order, under what label" (pure policy, changes with UX). They live apart, and the test files split the same way, with shared wire-shaped fixtures in `tests/_helpers/activity-fixtures.ts`.

## Testing pyramid

```
tests/unit/         — Vitest, pure logic (status palette, contrast ratios, ANSI strip, RepoFacet, AgentLiveStatus, GroveClient)
tests/component/    — Vitest + jsdom + RTL, single-component contracts
tests/e2e/          — Playwright, mobile-chrome + desktop-chrome projects
tests/e2e/_fake-daemon.ts — Hermetic Express server used by Playwright
tests/e2e/_live-smoke.ts  — Manual `npx tsx` against a real daemon for screenshot capture
```

- **Vitest config requires** `esbuild: { jsx: "automatic", jsxImportSource: "react" }` — without it the JSX runtime path errors on every component test.
- **`vitest.setup.ts` polyfills what jsdom lacks and a mount path needs**: `matchMedia` (next-themes calls it on mount, and almost everything transitively imports next-themes), `ResizeObserver`, and `Element.prototype.scrollTo`/`scrollIntoView` (the transcript viewport's autoscroll rAF throws without them).
- **`next/font` is a build-time transform Vitest can't run** (`next/font/local` is a directory import that throws under jsdom/ESM). `@/app/fonts` is **aliased to a stub** (`tests/_helpers/fonts-stub.ts`) via a `vitest.config.ts` `alias` entry that must come *before* the generic `@` alias (Vite matches in order). The stub returns inert `{ variable: "" }` font objects; any component that imports a font (terminal panes, the layout) needs this or its test errors at import.
- **jsdom serializes hex colors to `rgb()`.** Tests that assert on color use the `expectColor()` helper (`tests/_helpers/`), which converts hex → rgb before comparing. Don't compare raw style strings. jsdom also cannot resolve `var()` — assert the color *class* (`text-primary` / `text-[var(--ref-info)]`) for var-based tokens.
- **Test seam = the component's testid + ARIA + visible text.** New visual treatments must preserve testids and the first-child structure tests depend on (e.g. `StatusBadge`'s firstChild is the pulse-eligible glyph). If the contract truly changed, update both in the same commit.
- **A fetch stub must DISCRIMINATE.** A blanket 200 for any URL shape converts real server regressions into green tests — a drill-in feature shipped broken for months behind an unconditional `/turns` stub. Known fixture id → realistic payload; anything else → the daemon's real typed 404 envelope. Companion rule: **an error state never shares copy with an empty state** ("Couldn't load" vs "No transcript recorded" vs "No messages") — that ambiguity is what hides the bug from human eyes too.
- **E2E for stateful mutations MUST use per-test `page.route`, NOT the shared fake daemon** — one daemon serves every Playwright worker, so a `kill` there contaminates every other spec. The fake daemon carries only non-destructive routes (`POST /workspaces` echoes a synthetic state, `GET /agents`, `GET /branches`); pause/resume/kill transitions are driven by intercepting `**/api/grove/workspaces/<id>/{peek,pause,resume,kill}` with a per-test mutable closure.
- **Playwright uses port 3101**, not 3100 (3100 is commonly held by a stray root-owned `next-server`). The fake daemon binds 8421. Don't add port-discovery logic — the fixed ports are the contract that makes the webserver/fake-daemon pair deterministic. Running two Playwright projects back-to-back can leave a stuck `_run-fake-daemon` holding 8421, after which the next run's `reuseExistingServer:false` daemon never binds and EVERY data-dependent test times out — that looks like a mass regression and is an env collision. One owner, sequential runs, verify 8421/3101 are free between projects.
- **A `-g`-filtered Playwright run is HARSHER than the full suite**, because the earlier tests that would have warmed a dev route never ran. A `-g` failure that disappears in the full file is a cold-compile artifact, not a regression.
- **`E2E_LIVE_DAEMON=1 npm run test:e2e`** runs Playwright against a real daemon instead of the fake (only useful when iterating on something the fake doesn't model — keep it the exception). The auth setup project polls for up to 60 s in live mode so you can `grove auth approve` the printed code from another terminal.
- **Playwright is hermetic, auth included.** A `setup` project (`tests/e2e/auth.setup.ts`) pairs once through the BFF (`POST /api/auth/pair` → poll `GET /api/auth/pair/{id}`), saves the resulting HttpOnly `grove_session` cookie as storageState (`tests/e2e/.auth/`, gitignored), and both browser projects depend on it. The fake daemon auto-approves (first poll consumes, deterministic `FAKE_DAEMON_TOKEN`) and **bearer-gates every data endpoint**, so the suite pins the full cookie → BFF → bearer chain, not just rendering. The webServer env sets `XDG_CONFIG_HOME` to `test-results/xdg-config` so the BFF's cookie store never touches the real user config.
- **After a post-mutation navigation, assert a destination-only marker BEFORE the URL.** On throttled mobile the App-Router view swap outruns the location update, so a bare `toHaveURL` flakes; wait for e.g. `composer-prompt` to be visible, then `toHaveURL` with a 10 s timeout.

## Production hosting (systemd-user)

For "leave it running on a host" deployments — typically the same machine that hosts the daemon — install the user-scope systemd unit shipped under [`packaging/systemd/`](../packaging/systemd):

```bash
make webapp-build           # one-shot: npm ci + npm run build (required before enabling)
WITH_WEBAPP=1 make systemd  # writes both unit files
WITH_WEBAPP=1 make systemd-enable  # enable + start now
```

Webapp install is **opt-in** (default `WITH_WEBAPP=` is empty). The webapp service `Wants=` (not `Requires=`) the daemon — daemon hiccups don't tear the webapp down; the session rail's footer surfaces the unreachable state instead (`daemon-status`). The unit binds `0.0.0.0:3000` so the dashboard is reachable from a phone on the same Wi-Fi without extra port forwarding.

After webapp source changes: `make webapp-build && systemctl --user restart grove-webapp`. The service does NOT auto-rebuild — production mode reads `.next/` build output and runs cold-fast; dev-mode hot reload would be wrong here.

## Local dev

Run the daemon (`uv run grove daemon serve --port 7421`) and `npm run dev` (binds `0.0.0.0:3000`, LAN-reachable) side by side. The LAN URL is announced in the dev log; open it on a phone on the same Wi-Fi for phone testing.

**When `next dev` errors with `Cannot find module './<chunk>.js'`:** the `.next` cache is stale. Fix is `rm -rf .next && npm run dev` (NOT `--clear-cache`, NOT `npm install`). A `_not-found` collection error during `next build` is the same family — clean cache, rebuild. **Do not** `rm -rf .next` while a `next dev` is running; it corrupts in-flight pack files and leaves the dev server in a permanent error loop. Stop dev → clear → start dev.

**Never run `next dev` inside a checkout that also serves a production `grove-webapp` systemd unit** — `next dev` and `next start` both read/write the same `.next/` directory, so a dev instance launched in place races the running production build (observed symptom: `next/font: Cannot find module '../../../../lib/picocolors'` mid-request). For any live-browser check of a webapp change, verify inside YOUR OWN worktree (fresh `.next`, no shared state). Point `GROVE_DAEMON_URL` at a spare fake-daemon or daemon port and pick a dev port that isn't 3000.

**The bottom-left "N" / "Issues" badge in dev is the Next.js dev indicator.** Production builds don't render it. It is not part of the design.

## Repo-level gotchas (webapp's location in the monorepo)

- **The repo-root `.gitignore` rule for Python `lib/` catches `webapp/lib/`.** Resolved by `!/webapp/lib` and `!/webapp/lib/**` negations in the root `.gitignore`. If a new top-level dir under `webapp/` shares a name with an ignored Python directory (`dist/`, `build/`), apply the same negation.
- **The webapp does NOT depend on the Python venv.** It has its own `node_modules` and `package.json`; CI matrices that build the webapp can skip the Python toolchain.
- **When your branch changes a wire shape, running `codegen` against the *running* daemon (7421) is wrong — it serves the installed checkout's OLD openapi.** `~/.local/bin/grove` resolves to the last-installed checkout, not your worktree, so a new field never appears and `codegen:check` "passes" stale (or diffs forever). Boot a throwaway daemon from the worktree on a spare port and point codegen at it: `uv run grove daemon serve --port 7422 &` then `GROVE_DAEMON_URL=http://127.0.0.1:7422 npm run codegen`. Kill it after. The engine commit + the regenerated `types.gen.ts` land together; on deploy the real daemon must be restarted on the new code. If no daemon can run at all, the schema still needs no network: import the app and dump OpenAPI to a file (`build_app(cfg=…, store=JsonWorkspaceStore()).openapi()`), then point `openapi-typescript` at the JSON file — identical output, so `codegen:check` stays green.
- **`npm run codegen` is never a no-op, even for a purely additive route — budget for a sweep, not a diff.** `types.gen.ts` is only as fresh as the last person who ran codegen, and routes land on the main branch without it, so one regen commonly brings in several routes' worth of schema. The expensive half is second-order: a field that went **required** upstream since the last regen turns every fixture written against the optional shape into a `tsc` error, and those surface a couple of files at a time rather than all at once. **After any regen, run `npx tsc --noEmit` to completion and re-run it after each fix** before assuming you are done, and read `git diff types.gen.ts` for routes you did not add — their presence is real signal about what shipped un-regenerated. **Never resolve fixture breakage by loosening the generated type**; the generated file is the truth and the fixture is what is stale.

## Layout traps

- **Never put `overflow-hidden` on a fixed-height shell that contains actionable chrome — it hangs Playwright's `scrollIntoViewIfNeeded` and every `.click()` times out.** With the target inside a fixed-height `overflow:hidden` ancestor that has no scroll room, the pre-click scroll-to-center never settles and the action retries until timeout. The tell is that `force:true` / `dispatchEvent` work (they skip actionability) while the page is provably stable — constant bbox, no console errors, no render loop. It is **deterministic under `trace: retain-on-failure`** (instrumentation slows the page so the race lands every time) yet only intermittently reproducible on a warm manual server, so trust the suite over a hand probe for this class of bug. Rule: **a viewport-fill shell clips at the LEAF scroll regions, never on the ancestor that holds tabs or buttons.** Keep the fixed height, use `min-h-0` instead of `overflow-hidden`.
- **The viewport-fill pattern, end to end:** flex column on the page (`h-[calc(100dvh-3.25rem)]`) → `flex-1 + min-h-0` on the row → `h-full + min-h-[Xrem]` floor on the leaf. **The `min-h-0` is the load-bearing part everyone forgets** — without it, flex children with `overflow:auto` can't shrink below their content and the scroll viewport silently breaks. Leaf scroll components (`PeekSnapshot`, `CommitList`) do NOT bake in viewport caps: that is policy-at-the-page, not mechanism-at-the-leaf, which is why one consumer can flex-fill while another passes a `className` to constrain. The exception is an **inline** accordion (a digest expanded inside a list), where unbounded height shoves later rows off-screen — those do cap.
- **Width and height leaks share a root (intrinsic sizing) and have opposite fixes.** *Width:* grid/flex children default to `min-width:auto`, so ONE wide child (a 400-char terminal line, an unbroken markdown token) widens its track and hands the whole PAGE a horizontal scrollbar. `min-w-0` on **every** link of the flex/grid chain down to the pane makes the overflow scroll *inside* the pane. The terminal `<pre>` keeps `w-max whitespace-pre` on purpose — wide grids scroll, never wrap; prose gets `break-words` instead. *Height:* percentage flex-basis resolves against CONTENT in an intrinsically-sized chain, so a `flex-1` transcript grows the page instead of scrolling. Fix: the ChatPanel wrapper owns the height policy and the Conversation is `absolute inset-0` inside it, so transcript height can never propagate upward. Also `initial="instant"` on StickToBottom (upstream default is "smooth") — a long transcript must OPEN at its tail; animating the first scroll reads as a glitch and races tab switches. Pinned in `detail.spec.ts` with vacuous-pass guards (the fixture genuinely overflows both axes).
- **Split view = shadcn `Resizable` (`react-resizable-panels`), lg-only, matchMedia-gated — never a hand-rolled pointer-drag resizer.** The canonical primitive is keyboard-accessible and `autoSaveId="grove-detail-split"` persists the ratio for free. A horizontal split on a phone is wrong, so the split is gated behind `useMinWidth(1024)` (a tiny SSR-safe `matchMedia` hook; jsdom reports false → tabs-only in component tests) and the toggle is hidden below lg. `showSplit = isLg && view === "split"` means the state can never desync from the viewport. ONE `useMinWidth(1024)` call at the page level, never two divergent md/lg gates. e2e covers both arms project-gated (`desktop-chrome` opens the split, `mobile-chrome` asserts the toggle is absent) — put `test.skip(testInfo.project.name !== …)` **inside the test body**; the describe-level callback form passes `undefined` for testInfo and throws.
- **`resolvePaneView(sessionResolved, sessionsLoading, isLg, chosenTab, chosenView)` is the ONE seam deciding the pane surface** — `ViewSwitcher`/`AgentWorkspace` just render what it returns. Default tab = `null` while sessions load (skeleton), else `"transcript"` once a session resolves, else `"terminal"`. **Default view = single-pane tabs at EVERY breakpoint; split is never a starting state**, reachable only via the lg-only toggle. An explicit `chosenTab`/`chosenView` wins over both defaults for the page's lifetime. The transcript is what you came to watch; terminal/diff/info are opt-in detail.
- **The `ViewSwitcher` is plain controlled buttons with a hand-rolled `role="tablist"`/`tab`/`aria-selected` contract**, not radix `Tabs` — two quiet text tabs plus the lg-only split toggle, separated by tone and space rather than a `TabsList` pill. Tabs are **icon-only below `sm`** so a phone spends its width on the title.

## Transcript & chat panel

- **The transcript runs on `@assistant-ui/react` headless primitives over Grove's own external-store runtime — primitives ONLY. The `assistant-ui` CLI is NEVER run against this repo, and the `ai` (Vercel AI SDK) package must NEVER enter `package.json`.** Runtime seam: `lib/grove/assistant-runtime.ts`'s `useGroveChatRuntime` wraps the existing pipeline (`useSessionTurns` + `chatItemsFromTurns` + `livePendingQuestions` + `useSendMessage`/`useInterrupt`/`useAnswerQuestion`) into `useExternalStoreRuntime`: `messages` ARE Grove's `ChatItem[]`, `convertMessage` is the pure `chatItemToThreadMessage` (beside `chatItemsFromTurns` in `chat-turns.ts`, unit-tested the same way). `onNew`→`send.mutate` (Grove's optimistic cache write is what shows the sent row — the store reflects `messages`, it never appends), `onCancel`→`interrupt.mutate`.
- **`adapter.isRunning` is deliberately LEFT UNSET.** assistant-ui's `useComposerSend` disables the composer while `thread.isRunning` (and injects a synthetic streaming placeholder), which fights Grove's core model of STEERING a WORKING agent with follow-ups. The working state comes from the `agentState` prop instead (the WORKING-gated interrupt + the panel shimmer), and every mapped assistant message pins `status:"complete"` so `thread.isRunning` stays false and the composer stays sendable.
- **The `data-*` part registry is the integration contract** (`CHAT_DATA_PART`/`CHAT_DATA_NAME` in `chat-turns.ts`). The two text kinds map to native `text` parts; non-text kinds map to `data-tools` (ONE part carrying the whole pre-grouped `calls[]` — Grove pre-groups in `chatItemsFromTurns`, so assistant-ui's own part-grouping is never invoked) / `data-note` / `data-notification` / `data-question` / `data-continuation` / `data-file-edit`, each rendered by a house component via `MessagePrimitive.Parts` `components.data.by_name`. **assistant-ui strips the `data-` prefix**, so the CONTENT type is `data-tools` while the registry key is `tools`.
- **The LIVE pending-question card is NOT a message.** `ThreadPrimitive.Messages` keys children by INDEX, so a live interactive card at the tail would remount — dropping in-flight selections — every time the transcript grows under it. The panel renders it as a stable sibling AFTER the stream, keyed by `group_id`.
- **The chat panel is `next/dynamic`-loaded on `/w/[id]`, so streamdown (~460 kB) and `@assistant-ui/react` ride the panel chunk, not `/`'s first load.** Any future import of `response.tsx` — including the composer's fullscreen Markdown preview — must stay behind a `next/dynamic({ssr:false})` boundary. `/`'s First Load is the number to watch.
- **Transcript rhythm is a per-position top margin in `GroveMessage`** — 56px before a turn head (user prompt / continuation), 24px before an agent reply, 20px before an intra-turn part; the turn boundary stays ≥2× the message gap (assistant-ui's uniform gap won't do it alone). **The intra-turn tier is 20px, not 12px:** substantial parts (a file-edit diff card especially) read cramped at 12px, and at 12px the agent reply's hover copy button — which reveals ~24px below the prose via a `-mb-7.5 min-h-7.5` reserve trick — OVERLAPS the next part. The paired fix tames the pull-back to `-mb-5` so the revealed button stays inside the reply's footprint. **Change either and re-check the copy-button-over-next-part collision.**
- **Assistant prose gets `[&_p]:leading-relaxed [&_li]:leading-relaxed` (~1.625); the USER bubble's line-height is deliberately NOT touched** — `chat-panel.tsx` hardcodes `USER_MESSAGE_CLAMP_HEIGHT = 6 × 1.25rem` off `text-sm`'s default leading, so loosening it would break the SmartCollapse clamp math. Only the sustained-reading surface loosens.
- **User bubbles clamp at `USER_MESSAGE_CLAMP_LINES` (6 lines / 7.5rem) behind a `mask-image` fade + a `self-end` "Show more" toggle**, collapsed by default for every bubble including the newest. The FULL text always stays in the DOM (collapse is `maxHeight` + `overflow-hidden` + mask only) — a char-slice was rejected because it cuts mid-syntax. Overflow is **measured, not guessed**: a `ResizeObserver` compares `scrollHeight > clientHeight` and re-runs on pane resize (a split drag re-wraps). The toggle renders only when overflowing (or once expanded, so it can re-collapse) and must live OUTSIDE the clamped/masked wrapper. Derive the clamp height from the line constant in one place (inline style), never a magic Tailwind class. jsdom has no layout (`scrollHeight` is 0), so the component test pins the no-overflow path and Playwright pins the real clamp. Seams: `user-message-collapse` (+ `data-collapsed`), `user-message-toggle`.
- **The transcript speaks ONE design vocabulary** — every in-transcript renderer shares one icon-per-concept map, one color rule, one type scale. Icons (`lucide`, `aria-hidden`, color inherits): tool = `Wrench`, question = `CircleHelp`, agent/response = `Sparkles`, `you` = `User`, success = `CircleCheck`, error = `TriangleAlert`, expand/collapse = one `ChevronDown` + `rotate-180` everywhere. Color is quiet-by-default: tool/question panels are neutral chrome (`text-muted-foreground` glyphs, `border-border`, `bg-muted/40`); saturated hue ONLY for semantics via existing tokens — `you`=`--primary` / `agent`=`--ref-info` (RoleLabel), tool success=`--ref-add` / error=`--status-error`, question accent=`--ref-info`. Type: body `text-sm` sans; ALL code (tool name/detail, fenced + inline markdown) `font-mono text-[13px]`; labels micro-tier. **Don't reintroduce a per-renderer glyph — extend the shared map.**
- **Transcript speaker labels are the shared `RoleLabel` atom**: lowercase `you` / `agent`, micro-label tier, user = `text-primary` clay / agent = `var(--ref-info)` blue — the same words and hues as the TUI, so the two read as siblings. **Branch teal was rejected for `you` on both surfaces** because branch names render in `--ref-branch` teal immediately beside the turns. Seam: `data-testid="role-label"` + `data-role-label`; assert the color *class*, not a computed color.
- **`Tool` blocks default CLOSED everywhere** — a lone tool call must not dump detail into the scroll. `chat-turns.ts` merges consecutive same-*kind* tool entries into one `tools` row. (Group-by-SUBJECT — same-file edits rolled into one entry with summed stats — is the known future mapper-level lever; deliberately not built.)
- **ONE shared width constant `CHAT_COLUMN`** (`mx-auto w-full max-w-3xl px-3 sm:px-4`, in `chat-panel.tsx`) wraps BOTH transcript content AND composer so the two measures can never drift — edge-to-edge on mobile, readable ~48rem on desktop, user bubbles `max-w-[85%]`.
- **`data-file-edit` is the one kind that must NEVER fold into `data-tools`.** A file mutation rides the wire as `DigestEntryView{role:"file_edit", file_edit:{path,old_text,new_text}}`, maps to its own `ChatItem{kind:"file-edit"}` — **never added to `chatItemsFromTurns`'s tool-run-folding condition**, which is what keeps it out of the "Used N tools" accordion structurally rather than by a rendering choice — and renders via `FileEditCard` (`components/chat/file-edit-view.tsx`) over the vendored `DiffViewer` (`components/assistant-ui/diff-viewer.tsx`). That vendored component takes plain `oldFile`/`newFile` strings and computes its own line diff via the `diff` package, with **zero coupling to assistant-ui's tool-call machinery** (Grove's tool calls are post-hoc and always-complete, not streaming). **It was trimmed at adoption to only the path Grove exercises** — the unified-diff `patch=`/`code=` prop and the markdown passthrough were removed along with two dependencies; a re-sync from upstream must re-apply that trim (documented in the file header). Retoned via `--diff-add-*`/`--diff-del-*` CSS vars set on the card wrapper and mapped onto `--ref-add`/`--ref-remove`. **Renders unconditionally — no `Collapsible`, no default-closed state** — the whole point being that every file edit is visible without a click. `FileEditCard` wears its OWN header (the vendored header is CSS-hidden) carrying the worktree-relative `displayPath` (truncating, full `path` in a Tooltip) and a `+adds −dels` count computed once via the viewer's exported `computeDiff`, so the count cannot drift from the body. **The body is deliberately NOT syntax-highlighted** (that needs a heavyweight highlighter; shiki is bundled *inside* streamdown but not exposed for raw-string use, so using it means a second copy). Readability follows the editor convention instead: line numbers on, content forced back to `text-foreground`, add/remove carried by row-background tint + a colored `+`/`−` gutter — three-coded by position, symbol and color, never hard-to-read colored text. Seams: `file-edit-card`, `file-edit-header`.
- **The todo/plan card is pinned above the composer as a SIBLING, NOT an in-stream message — the "current-state signal" pattern.** A `TodoWrite`/`update_plan` is a full REWRITE of the list, so only the LATEST matters; rendering every historical update inline would stack near-duplicate cards. `itemFromEntry` returns `null` for `role:"todo"` (keeping it out of the item stream AND off the default-note fallback, which it would otherwise hit since a todo entry has non-empty `text`), and a separate pure seam `latestTodoFromTurns(turns)` scans the loaded `/turns` for the newest. `useGroveChatRuntime` exposes it as `todo` — **exactly parallel to `pending`**, the other above-composer sibling. **This is the template for any future "current-state" transcript signal** (a status/plan/progress that supersedes rather than accumulates): derive-latest + pin-as-sibling, never a per-update `ChatItem`.
  - **Collapsed by default, and the reason generalizes to anything pinned above the composer: a sibling of the composer lives in FIXED chrome, not the scroll, so its height is rent charged against the transcript on EVERY turn.** The header IS the trigger (local state + conditional mount + a `-rotate-90`-when-closed chevron, the same idiom as `ai-elements/tool.tsx` — no radix `Collapsible`, no new dep), and the `done/total` count is lifted OUT of the disclosure so it reads in BOTH states. **The invariant: collapse hides the DETAIL, never the SIGNAL.** (The `pending` question card is deliberately NOT collapsible — it is a blocking prompt, and hiding it strands the agent.)
  - **A CLEARED plan is representable**, and an empty-items object is still TRUTHY. `latestTodoFromTurns` returns `null` when the winning list is empty, so the panel's `{todo && …}` degrades it to nothing rather than rendering a dead `Plan 0/0`. **The ordering is load-bearing: the emptiness check runs on the WINNER, never inside the scan loop** — skipping empty entries as you scan lets a stale earlier plan win and resurrects a list the agent has since cleared. Newest-write-wins first, THEN degrade.
  - Status glyphs reuse the shared vocabulary — `CircleCheck`/`--ref-add` (done), a pulsing `CircleDot`/`--status-active` on the `grove-pulse` cadence (in progress), muted `Circle` (pending); an in-progress row prefers the present-tense `active_form`. Seams: `todo-card` (+ `data-progress`, `data-collapsed`), `todo-toggle`, `todo-item` (+ `data-status`). **The card has ZERO e2e coverage** — `_fake-daemon.ts`'s `buildTurns` emits no `role:"todo"` entry, so the card never mounts under Playwright. The contract is pinned by the component test alone; adding that entry to the fixture is the one-line seam if it ever needs end-to-end exercise.
- **A structured agent question rides a `DigestEntryView` of `role:"question"` with its payload on `entry.question`, not `text`.** It is the first digest role whose render data is not in `text` (the prompt may be empty for a bare confirm), so `itemFromEntry` handles `"question"` *before* the `if (!entry.text) return null` guard that drops blanks of every other role. The read-only `QuestionCard` draws a STATIC option list (checkbox/radio glyphs reflect `multiselect`, never `<button>`/`<input>`) plus an answered (`✓` + answer) vs `awaiting answer` footer. **The trap that bites silently:** `ChatItemRow`'s `switch` has no `default`/`never` guard, so a new `ChatItem` kind compiles fine (implicit `undefined` is a valid React node) and renders **nothing**. Adding a `ChatItem` kind means adding a `case` to that switch, not just the mapper.
- **The PENDING question is LIVE on the SSE activity stream (`AgentActivityView.questions`, a LIST — one ask batches up to 4 questions answered atomically in one POST) because the agent flushes NOTHING to the transcript while a question is on screen, so `/turns` structurally cannot see it.** The payload arrives via an ask-time hook instead. `livePendingQuestions` (`lib/grove/live-question.ts`) reads it off the stream snapshot; `PendingQuestionCard` is the interactive twin of the read-only card — a lone single-select tap-submits immediately (mirroring the terminal's own grammar: that one case has no review step), any multiSelect or multi-question group gets an explicit Submit, free-text "Other" is non-multiSelect-only, and `confirm`-kind degrades to read-only. Answers POST `/workspaces/{id}/question-answer`; a 409 means the question resolved in the terminal first — show the notice, degrade to read-only, let the stream confirm. **Two regression-pinned traps: a mutation call must live OUTSIDE a `setState` functional updater** (StrictMode dev runs updaters twice → double POST; pinned by a `<StrictMode>` component test asserting exactly one `onSubmit`), and **steering-refusal wording lives in ONE shared formatter** (`lib/grove/steering-notice.ts`), never inlined a second time.
- **streamdown exposes real props for the fenced-code and table chrome you can't CSS away — kill them there, not by fighting the DOM.** `ai-elements/response.tsx` passes a module-level `STREAMDOWN_CONTROLS = { code: { copy: true, download: false }, table: false }` (stable object identity — `Streamdown` memoizes on props) plus `lineNumbers={false}`. Everything else (surface tone, card-in-card shells, sticky action pills) is restyled via `[&_[data-streamdown=…]]` attribute-selector overrides on the wrapping `className`, which win at (0,2,x) specificity over streamdown's own (0,1,0) utilities without `!important`. Tables need one extra selector: `[&_div:has(>[data-streamdown=table])]` reaches the UNNAMED scroll-div streamdown wraps the `<table>` in — that div becomes the ONE rounded hairline frame. **Never style `[&_pre]`/`[&_table]` directly for fenced code or tables**: streamdown already wraps both in its own nested chrome, so a bare-tag rule nests a THIRD surface inside its two. Inline code (`:not(pre)>code`) is untouched.
- **`ThreadPrimitive.Viewport` IS the scroll container (`role="log"`)**, so the Playwright scroll probe is `[role="log"]` itself, not `[role="log"] > div`.
- **Transport refusals (409/501) render as a quiet `chat-notice`.** BFF trap: **a 204/205/304 must be re-wrapped with a `null` body**, or steering success surfaces as `daemon_unreachable`.

## SSE, streams and untrusted wire data

- **Token/treatment lookups fall back, and one bad card can't white-screen the wall.** An SSE delta is JSON; the TS unions do NOT constrain it, so a daemon shipping a new `WorkspaceStatus`/`AgentActivityState` makes `MAP[value]` `undefined` and the first field read throws — and an uncaught render throw unmounts the **whole** React tree. Two defenses, both required: (1) every color/treatment lookup ends in `?? <neutral>` (`statusColor`→offline, `agentStateColor`→unknown, `tierForActivity`→unknown/dormant) so it never returns `undefined`; (2) each card is wrapped in `components/error-boundary.tsx` — transparent on the happy path (it renders `children` with no wrapper element, so the parent's `useAutoAnimate` ref still sees the real card as its direct child) — so any uncontained throw degrades to one placeholder tile. Pinned by `tests/unit/render-hardening.test.ts`. **Rule for any new enum-keyed `Record` consumed from the wire: give the accessor a fallback, never index-and-deref raw.**
- **An `EventSource` in a background tab can die silently — the stream needs its own focus self-heal.** TanStack queries refetch on window focus for free; SSE has no such reflex, and tab-throttling or network sleep can kill the connection *without firing `onerror`*, so `connected` stays true and the poll fallback never arms — a wall that looks live but is frozen. `useActivityStream` adds a `visibilitychange` listener comparing `lastEventAt` (stamped on every event including the 15 s heartbeat, mirrored into a ref so the listener never re-subscribes) against a 20 s staleness bound, and bumps `reconnectKey`; the fresh connection makes the daemon resend a full `snapshot`. **Any future SSE hook needs the same triad: heartbeat stamp + visibility check + reconnect nonce.**
- **A `session_activity` delta for a workspace NOT in the snapshot is promoted to a full re-fetch, not dropped — that is the out-of-band-create path.** The pure reducer deliberately drops a delta for an unknown workspace (keeping the wall stable, and unit-pinned as such). But the daemon's poll loop emits `session_activity` — not the bus-bridged `workspace_changed` — for a workspace created by a *separate process* (a second TUI, the MCP server, another CLI), because the manager-bus bridge only fires for ops through the daemon's own in-process managers. So the fix lives at the side-effecting edge (`useActivityStream`'s listener), not in the reducer: it tests `snapshotHasWorkspace(snapshotRef.current, …)` and calls the same `client.getActivity()` re-fetch the `workspace_changed` path uses. `snapshotRef` is a ref twin of `snapshot`, mirrored every render, so the listener reads the current value without re-subscribing — same pattern as `lastEventAtRef`. Out-of-band kills self-heal too: the gone row's deltas simply stop, and the next full re-fetch drops it. The TUI's twin of this bug lives in [`src/grove/tui/CLAUDE.md`](../src/grove/tui/CLAUDE.md).
- **A `session_activity` delta older than the row it would patch is dropped — `observed_at` is the freshness key, never the event seq.** The daemon's connect-time snapshot and its poll loop race: a delta read *before* the snapshot was computed can sit in the per-connection queue and arrive *after* it, and seq order doesn't reflect read order (the snapshot's seq is stamped post-compute). `patchWorkspace` compares `observed_at`; malformed timestamps fail open so a bad clock can never freeze a card. The TUI is immune because it re-snapshots on every delta — **any future incremental SSE consumer needs this guard.**
- **SSE passes through the BFF, not around it.** `app/api/grove/[...path]/route.ts` pipes the event streams (predicate `isEventStreamPath` = `GET /events` OR the focused-pane `GET /workspaces/{id}/pane/stream`): it pipes `upstream.body` (never `await res.text()`), sets `export const runtime = "nodejs"` + `dynamic = "force-dynamic"`, forwards `req.signal` (a browser disconnect aborts the upstream fetch — no leak) and the `last-event-id` header (replay), and returns `cache-control: no-cache, no-transform` + `x-accel-buffering: no`. The browser uses a **cookie-auth `EventSource`**; the daemon bearer is injected server-side and never reaches the browser.
- **Every stream hook is EventSource-primary + poll fallback, with a jsdom guard.** `useQuery` runs `enabled: !connected`, so the happy path is one stream and zero polls; `typeof EventSource === "undefined"` falls back to the poll, which is how the component/unit tests exercise these hooks. **One route renders at a time, so per-page `useActivityStream` means at most one EventSource — no shared provider needed.** The fold logic is the pure `applyDashboardEvent` reducer in `lib/grove/activity-stream.ts` (`snapshot` → replace, `session_activity` → patch one workspace + recompute counts, else no-op); that reducer is the unit-test seam, not the hook.
- **The dashboard's live focus is exactly ONE SSE-pushed pane, never N — a page-level `liveId` is the enforcement.** Only the focused card's `useWorkspacePane(id, enabled)` is enabled; it opens a cookie-auth `EventSource` to `GET /workspaces/{id}/pane/stream`, which the daemon **diff-guards** (a `pane_snapshot` frame only when the ANSI changed, keepalive comments otherwise, ~1 Hz, `ansi` may be `null` for an idle/dead pane). **Reset-on-key-change is required:** a new `id` or `enabled → false` closes the stream AND clears the stored pane to `undefined`, so a stale pane from the previously-focused workspace never flashes on the new one. The WORKING+visibility gate stays client-side — the "Live" toggle is status-gated to `working`, and the page auto-drops `liveId` when that workspace stops working or vanishes, using the snapshot it already holds.
- **The open transcript's SSE invalidation rides a NARROWER fingerprint than the rail's, because a transcript can grow without the coarse session `state` changing.** `turnsProgressFingerprint` (`lib/grove/activity-stream.ts`) reads the same `/activity` snapshot the detail page already holds (no second EventSource) and returns `` `${state}:${assistant_replies}:${tool_calls}:${last_event_at}` `` for the open `(workspaceId, sessionId)` pair — an agent can stay "working" through several tool calls, so `state` alone (the rail's fingerprint) misses real turn progress. The page diffs this string in a `useEffect` (skip-first-run via a `useRef`) and invalidates `["turns", id, sessionId]` the instant it changes, so the 30 s poll becomes a pure backstop and a real turn lands as fast as the terminal pane (~1 s). It returns `""` when the session isn't in the snapshot yet — a stable value, so the skip-first-run guard never misfires on that gap.
- **The rail's fingerprint is the coarse twin:** workspace id : status : primary session state : needs_attention. **Invalidating on the raw snapshot or `lastEventAt` would refetch on every heartbeat and pane frame** — fingerprint it so only real state changes trigger a refetch. The row's displayed state is **overlaid** from the live snapshot by session id so the rail and cards never disagree; a row with no live match keeps its recorded summary state. **`workspace_id === null` ⇒ metadata-only** (dimmed, "history only", NOT navigable) — a hard wire-visible gate, because the turns route needs an owning workspace id.
- **`useQueries` is the shape for fan-out fetches** — an array of query objects in stable order, paired with `useMemo` for the id list so the keys don't churn. A loop of `useQuery` violates the rules of hooks (hook count changes with the list). `useProjectSessionsAll` fans `GET /sessions?repo=` across every project, keyed identically to `useProjectSessions` so a rail read and a single-repo read share one cache entry. **The home grid deliberately does NOT fan out** — `useActivityStream`'s snapshot already carries everything a card shows (`base_ahead`/`base_behind`/`dirty_files` per `WorkspaceActivityView`) with sub-second deltas. A per-card peek fan-out there costs N+1 requests per tick and delays a new workspace's appearance by up to 10 s. Trade-off accepted knowingly: losing the fan-out means the detail page cold-fetches its peek, a ≤2 s gap at the 2 s poll cadence.

## Terminal panes

- **The live preview is ANSI→HTML in a real `<pre>` (`components/terminal/terminal-view.tsx` via `fancy-ansi`), NOT a terminal emulator.** The daemon sends `tmux capture-pane -e` — a **fixed character grid** with SGR color escapes and *no cursor motion*. xterm.js is a terminal *emulator* and regresses this three ways: (1) it **reflows at its column count**, so a capture wider than the fitted terminal word-wraps; (2) its **DOM renderer draws box-drawing glyphs disconnected** — crisp connected `─│┼` need the WebGL/Canvas renderer's custom glyphs; (3) `fontFamily` can't take a CSS `var()`, so `var(--font-mono)` silently falls back to xterm's default font. The faithful tool for a *snapshot* is `new FancyAnsi().toHtml(ansi)` into a `<pre className="font-mono whitespace-pre">`: the page's real monospace font joins box-drawing into clean lines, `whitespace-pre` never wraps (the wrapper is `overflow-auto`, so a wide grid scrolls horizontally), and color renders as `<span style="color:var(--ansi-*, #fallback)">` runs. `fancy-ansi` HTML-escapes the text and only injects color spans, so the `<pre>`'s `textContent` is still the plain stripped output — which is both the screen-reader text and the test seam. Pure string→string, no DOM, so it works in SSR/jsdom with no dynamic-import/canvas dance. **xterm.js is the right tool only for a true live PTY** (a deferred websocket attach) — don't reach back for it on the snapshot path.
- **Consumer topology:** `FocusedPane` composes `TerminalView` **directly**, while `PeekSnapshot`'s only consumer is `terminal-pane.tsx`. `PeekSnapshot` never renders inside `FocusedPane` — an easy mis-read, since both merely share the `TerminalView` leaf.
- **Strip ANSI escapes in `peek-snapshot.tsx` via `stripAnsi` (`lib/grove/ansi.ts`)** rather than rendering them as text. **Color is not load-bearing for the dashboard — structure is.** That convention is also why no ANSI/terminal npm dep gets added lightly.
- **Auto-scroll `<pre>` to bottom only when the user is already within 40 px of the bottom** — otherwise you fight a deliberate scroll-up.
- **The detail terminal stays on the polled peek plus an honest "capturing" badge — deliberately NOT a second SSE pane-stream.** The detail page already polls peek at 2 s and the payload carries `agent_snapshot` + `snapshot_taken_at`, so `terminal-capture-badge` is truthful about that cadence without a duplicate transport for the same bytes. Reach for the pane stream only if the detail terminal ever needs sub-second latency.
- **`peek.recent_commits` ≠ `commits()`.** The peek's is a tight 3-row summary (no fork-point filter, capped). The detail page's commit list uses `/workspaces/{id}/commits`, which is fork-point-filtered (`git log base..branch`) and uncapped. Both exist on purpose, for different consumers.

## Lifecycle, sessions and auth

- **Engine lifecycle semantics are NEVER re-implemented client-side — `lib/grove/workspace-actions.ts` is a pure UX mirror, the engine is the real gate.** `availableActions(status, placement)` mirrors the TUI footer gate (active/idle→pause+kill, paused→resume+kill, offline→respawn+kill, orphaned/error→kill; ROOT placement strips pause/resume, which the engine refuses anyway) and `defaultDeleteBranch(provenance, placement)` mirrors `kill(delete_branch=None)`'s resolution (grove→delete, attached→keep, **root→forced false**). These exist ONLY so the UI shows meaningful buttons and a smart kill default; a stale snapshot offering an illegal action just surfaces the engine's typed refusal (`GroveProtocolError`), never corruption. Keep it a lookup table with a fallback to `["kill"]` for an unknown status (untrusted wire enum), never an `if status === …` chain.
- **All lifecycle verbs live in the `ContextBar`'s session popover; there is no `⋯` menu.** Reversible verbs (pause/resume/respawn) sit in an "Actions" section and fire directly — **the open popover re-renders the swapped verb in place as the status flips** (pause→resume), which is better than a menu that closes on select. Destructive `kill` sits in a labelled "Danger zone" (tinted `--status-error`) at the popover foot, behind `KillConfirmDialog` (its own file — it changed owners, so SRP applies; portalled and placement-agnostic, rendered as a SIBLING of the `Popover` so it survives the popover closing when the modal takes focus). WHY the popover: kill destroys the branch/worktree the popover already displays. The confirm carries the delete-branch checkbox (default `defaultDeleteBranch`, disabled for root with a "branch stays" note) plus the "Remote branches are never touched by Grove" line, matching the engine's required-explicit-input stance. **No optimistic update for lifecycle** (unlike chat's `useSendMessage`): the action invalidates and the re-fetch is the source of truth; kill calls `onKilled` → the page `router.push("/")`, since the peek would 404.
- **Popover sections are uniform**: `SECTION_LABEL` + `space-y-2 px-4 py-3`, separated by the shadcn `Separator` hairline — the deliberate exception to tone-over-lines, because a floating Popover already draws its own edge, so an internal hairline is legible where a tone fill is not.
- **Mutations bundle by concern.** `useWorkspaceActions(id)` returns the four verbs sharing ONE `invalidateWorkspace` (workspaces + activity + peek + commits) because they must refresh identically; `useCreateWorkspace` invalidates list + activity. The SSE stream also carries the change, but invalidating keeps a polled detail page fresh whether or not a stream is connected. The BFF needed zero change for any of this — `/api/grove/[...path]` already forwards POST/PATCH/DELETE generically and re-wraps the 204 `null` body.
- Two TypeScript/jsdom traps in this area: **TS 5.5's inferred type predicates narrow a `.filter(a => a !== 'kill')` to *exclude* `'kill'`** — annotate `: LifecycleAction[]` to widen it back. And **the kill-item→`Dialog` focus handoff OOMs under jsdom**, so that one flow is e2e-only and component-tested up to menu-open; the identity component test needs a `QueryClientProvider` for the mutation hooks.
- **The session picker's default primary must be read off the ACTIVITY SNAPSHOT, never off the plain `/sessions` list — the two orderings genuinely disagree.** `GET /workspaces/{id}/sessions` sorts purely by `modified_at` and carries no "is primary" concept; `WorkspaceStateView` deliberately never exposes `agent_session_id` either (views-never-expose — not a gap). The real signal is the engine's `sessions_for()`, which always places `state.agent_session_id` FIRST in `WorkspaceActivityView.sessions` when it resolves live. `primarySessionId` (`lib/grove/live-question.ts`) reads exactly that. **The bug this prevents:** defaulting to `sessions?.[0]` off the plain list looks fine on the happy path but makes a `useRemapSession` pin silently un-pin itself on the next load, because remapping never touches the target session's `modified_at`. The cascade is: explicit local pick → `primarySessionId(snapshot, workspaceId)` → `sessions[0]` as last resort. `useRemapSession` also invalidates `["activity"]` on success, mirroring every lifecycle mutation — **never read the pinned id back from the POST response body.** "Make primary" additionally adopts the id into local state for instant feedback; that is a nicety layered on top, not what makes the pin durable.
- **A dead-pointer workspace can strand the user with no reachable remap — the fix is a SECOND, ungated session source the picker falls back to.** The gated `/sessions` list is the daemon's *attributed* history (adoption-gated); when a workspace tracks a dead-minted pointer whose live successor the gate rejects, that list comes back empty and the cascade resolves nothing → an empty state with no way out. `GET /workspaces/{id}/sessions?candidates=true` (`useWorkspaceSessionCandidates`) is the UNGATED cwd-scoped set that KEEPS exactly the sessions the gate drops. **Two rules make it correct and cheap:** (1) fetch it LAZILY — enable the hook ONLY when the gated/snapshot resolution is null, so a healthy workspace never pays the extra directory scan; the candidate list is *also* the fallback resolver so a freshly-pinned candidate renders across the gated-list invalidation gap. (2) Offer the pick ONLY while `sessionId === null` — once a candidate is pinned the affordance retires; a retained candidate list must not resurrect a "Track a session" control over a now-healthy workspace. **`SessionPicker` is one component, two modes:** multi-session SWITCH (client-side view change + separate "Make primary" remap) vs. TRACK (candidates, one action per row = adopt = remap, no "selected" concept). It returns null only when there is neither a switch nor a candidate to offer — **not** at ≤1 session. **Empty-state CTA seam:** the page passes `ChatPanel` an `emptyStatePicker` node ONLY in the stuck case; its mere presence flips the empty state from generic "send a message" copy to a "pick a session to follow" CTA — no extra flag threaded, and zero candidates keeps the generic copy. Both mounts render fresh elements from one page-level factory (a React node can't mount twice). Rows keep "select" and "make primary" as SIBLING buttons inside a plain `<li>`, never nested.
- **Fake-daemon trap for remap tests:** `buildSessions` fixture ids are literal prefixes of each other, so the remap double must check for an EXACT id match before falling back to prefix search, or an exact-id request misreads as ambiguous.
- **Provenance gets quiet human labels at the render edge, raw codes elsewhere.** The wire's `provenance` is an open string (`grove_launched`, `fs_discovered`, …); the consuming component maps the known codes and passes unknown codes through raw — same fallback philosophy as the enum-keyed color maps. Keep the mapping in the consumer until a second consumer appears.
- **The BFF cookie store is file-as-source-of-truth with single-entry deltas — never a whole-memory dump.** `next start` runs several worker processes, each holding its own in-memory `Map`; rewriting the entire file from one worker's memory means a flush from a stale worker silently deletes a cookie another worker just minted, so the browser's cookie id maps to nothing and the user is forced to re-pair (repeatedly, and especially on mobile). Every mutation (`issue`/`revoke`/expiry-prune) goes through `mutate()`: read fresh from disk, apply a *one-entry* delta, atomic tmp+rename — so siblings can't clobber each other **and** revoked/expired entries are never resurrected (a naive merge-on-flush *would* resurrect them, which is exactly why "just merge" is wrong). `lookup()` re-reads disk on a cache miss to self-heal a sibling's mint. Knowingly accepted residual: two *simultaneous* cross-process `issue()`s inside one read→write window can still lose one; pairing is rare and user-driven.
- **Cookie attributes:** **SameSite=Lax** (Strict drops the cookie on a cross-site top-level navigation, so opening the dashboard from a chat/email/launcher link arrives cookie-less; the LAN, read-mostly, JSON-only BFF makes the CSRF delta negligible) and **Secure honors `x-forwarded-proto`** (behind a TLS-terminating proxy the inbound hop is plain HTTP, so an origin-only `secure` is mislabeled, and mixed http/https origins get separate cookie jars — pin ONE canonical origin in deployment). The proxy decision is the pure, unit-tested `isSecureRequest`, so the route stays a thin edge.

## Performance

- **"The webapp feels slow" is a server-seam claim until measured — time the engine first.** A multi-minute transcript render traced to the daemon re-parsing every session in a workspace's cwd on EVERY `/sessions` + `/turns` request while the activity poll pegged executor threads doing the same; the client's data path (bounded turns fetch, SSE fingerprint-gated invalidation, lazy panel chunk) was already right. Fixed at the engine (`core/agents/transcript_cache.py`); after: worst case 0.49 s cold / ~5 ms warm / ~50 ms per live append. **Invariant:** time `SessionExplorer.for_workspace` + `turns_for` at the engine first — **if warm reads exceed 50 ms the server cache regressed**; only then look at client memoization. The one known CLIENT lever, deliberately not built for want of observed jank: `chatItemsFromTurns` mints new object identities per refetch, so assistant-ui re-converts every message on each SSE-driven refetch — stabilizing item identity across refetches is the seam if transcript-scroll jank ever appears while an agent works.
- **The fix for "the design feels inconsistent" is rarely more design.** It is almost always missing utilities, missing focus rings, hand-rolled chrome that drifted from a primitive that already existed, or a hex token never wired to a Tailwind class. Audit is `curl /CSS | grep -c <utility>` first, screenshot diff second, design talk last.
